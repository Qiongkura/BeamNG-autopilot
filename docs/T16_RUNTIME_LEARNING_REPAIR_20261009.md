# T16：运行可信性与自主学习修复协议

日期：2026-10-09。依据：`PROJECT_STATUS_RECHECK_20261009.md`。这是新修复与后续测量的协议，不修改旧预注册、旧遥测或封存集。

## 1. 本轮实现范围

1. `fsd_drive`：放置与驾驶共用单调时钟截止时间；放置返回统一三元组；异常失败保持制动；启动放置前保持制动。驾驶阶段超限返回 4，不把中断当正常完成。
2. 每次带 `--out` 的运行输出 `*.session.json`，即使放置失败、没有驾驶遥测，也保留配置摘要、请求位姿、实际放置位姿、退出码、测量时长与收尾结果。
3. 后台 `LoopConfig` 增加 `total_steps`、`init`，进入配置哈希、保存文件、计划预览及真实 `rounds` 参数。默认 0／null 仍为历史 epoch 配方。拼错或未知配置字段报错，不能静默丢弃。
4. 新位姿入口复用机器租约与现有进程归属检查；有游戏会话或状态不明时拒绝启动。旧 `.sh` 入口退出并指向 PowerShell 入口。
5. 修正进程收尾结果：仍有新进程、归属未证实或收尾后状态 UNKNOWN 均不能报告 `closed=True`。真实 Tech 发现退出竞态后，增加最多 10 秒的退出确认；已自然消失的子进程不终止，也不伪称证明了归属。终止命令错误保留，但实际是否关闭以最后的可靠进程快照为准。
6. 论文中英文源撤回旧 E5 的单点可走集合因果解释，区分参考点压线和车体包络压线，并同步生成源包。
7. 自动数据路径复用受控 Tech 场景生成器和独立真值导出器：逐帧重算 RGB／标签摘要，核对凭证、地图、帧数、尺寸和类别；无线负例必须有明确证据。准入失败隔离，不把候选自己的预测当标签，不要求新增人工标注。
8. 采集失败仅在已证明游戏收尾后有限重试；启动前资源阻止不消耗尝试。采集已完成且收尾可验证时，中断恢复只重跑离线导出，新导出目录保留旧失败证据。复用准入结果前重新核对文件与凭证。
9. 采集、训练及驾驶记录对应源码摘要（含未提交源文件）。训练期间源码变化视为失败；位姿测量要求驱动与外层入口源码一致、运行前后未变。commit 名称不能代替工作树身份。
10. `--probe-geometry` 可选记录感知边界、候选／选择／控制路径、局部网格、快照及最终实际发送的指令；离线回放复用车体几何实现，区分当前与未来越界。没有越界见证不等于可安全执行。
11. 看板接入实际准入状态、优化步数、初始化、已见／可用样本与拒绝原因；缺少采样记录显示 UNKNOWN。证据归档逐文件摘要与缺项并存，不把缺文件的归档标为完整。
12. 集中实测发现新会话启动未进入采集：第一次 600 秒超时，第二次在同阶段结束自有进程树，0 帧合格、未训练。受控采集入口改为新会话直接加载场景（避免加载前查询当前车辆），增加连接／场景／车辆阶段日志，并把连接建立纳入收尾范围。此修改再次全量回归后使用新 run id 补测；原超时的具体等待 RPC 尚未由旧日志定位，不能将原因假设写成已证实。
13. 第二轮真实学习暴露基线任务指标没有跨轮保存：基线记录改为原子写入完整逐种子任务、负例、平台期、预算与训练元数据，复用时核对评测／源码身份及每个 checkpoint 摘要。旧格式或内容不全拒绝复用，不补造指标；失败任务通过合法审计阶段恢复。确定性入口测试实际走完两轮及失败后重启，但不冒充真实 GPU 中断恢复。
14. 驾驶入口也存在新游戏加载前查询当前车辆的顺序：新启动直接加载场景，明确 attach 的会话沿用现有车辆。两条实际入口分支均有回归；不改变 strict 感知横向约束。
15. 论文 fig21／fig22 改用明确路径与 SHA-256 的输入清单，不扫描新增日志／不按修改时间选取；缺项或摘要漂移拒绝。fig21 使用六次真实 R3 短训练的新图，不冒充旧 321 次历史复原，纵轴保留全部真实损失读数。证据归档补齐附录声明输入、两轮拒绝判定、对应源码与冻结图输入；摘要漂移记失败，不宣称完整训练复现。
16. PDF 入口支持一次重建中英正文与补充材料，使用独立隐藏 Edge 进程与新鲜输出；超时结束自有进程树。论文表格避免跨双栏碎片，四份产物均须渲染核验。投稿源包携带冻结图输入清单；本机没有 TeX 引擎，不能以静态检查代替实际编译。
17. 论文构建器拒绝重复图标识，修正补充材料原图与新增单图页的 ID 重名；按出现顺序统一为唯一的 S1–S42，HTML 与 TeX 引用使用同一映射。补齐英文表格长文件名换行及中文整图图例，负例率标签采用可读精度；安全仲裁示意图按实际规则数排布，为底部说明留出空间。这些显示修复不改变测量输入。

## 2. 位姿测量的两个契约

### A. `production_alignment`

研究“请求出生位姿经过生产放置后的表现”。保留生产 strict 放置流程，允许它根据感知修正实际位姿，但记录位置与航向误差。不能把请求网格当作驾驶阶段的固定真实网格。

### B. `fixed_actual_pose`

研究驾驶阶段的真实起始位姿差异。生产放置仍必须通过，不绕过制动或安全检查。放置后实际位置距请求位置超过 0.10 m，或航向误差超过 1.0°，该条件不合格。无法放置不是“等时长驾驶里无路径”，单独报告。

### 所有条件共有的准入

- Tech、导航目标、sensor 横向模式、strict；相同固定模型、速度上限和测量配置。
- 驱动退出码与 session 记录一致；配置各项及摘要一致；checkpoint 运行前后摘要一致。
- 入口与驱动源码快照完整且一致，运行前后未变；配置、指令、位姿数值范围合格。
- 实际放置成功，实际位姿完整且有限。
- `drive_elapsed_s` 至少为请求秒数减 0.5 秒；遥测首末曝光至少为请求秒数减 1.0 秒。该容差事前固定，短运行不得计完成。
- 至少两帧，必要位姿与指令列齐全，时间与指令序号递增。
- 内外两层收尾均可验证；归属不明的进程不得被终止，也不得把它当作清理完成。
- 不覆盖旧目录，不把文件存在当作成功。每次尝试保留请求、日志、遥测／失败审计和判定。
- 需要几何回放时显式给 `--probe-geometry`；测量资格检查每帧记录是否缺失或捕获失败。实际执行器响应仍需单独验证，指令发送记录不是执行成功证据。

**`qualified=True` 只表示上述测量准入通过，不表示驾驶安全、到达目标、模型改善或完整几何因果证据已成立。** `body_cov_status` 的 UNKNOWN 单独计数，不转为通过。

## 4. 自主学习下一阶段

后台配置示例字段为 `"total_steps": 300`、`"init": "相对项目路径的 checkpoint"`；初始化只加载权重，不等于恢复同一优化器状态。两臂共享初始权重与每 seed 步预算。

无人标注路径使用 `collect="tech"`、`collect_source="controlled"`、`collect_runtime="tech"`，通过 `collect_truth_anchors`／`collect_truth_sites`／`collect_truth_frames`／`collect_truth_anchor_offset` 固定采集配方，`collect_truth_attempts` 固定最多尝试次数。采集资格只覆盖通过核验的包；SHOULDER、ROLE、遮挡等通道保留各自原始资格。下一阶段先验证机械闭环，效果结论仍需冻结的独立开发／确认数据、配对种子与相同预算。

本轮集中机械验证配方为 `docs/T16_AUTONOMOUS_VALIDATION_CONFIG_20261009.json`：2 个种子、每臂 60 步、两轮、共享既有初始权重；最多两次采集，起始锚点跳过前 12 个。既有已核验标签只作为固定输入，不新增人工标签。`pause_while_user_active=false` 用于当前已授权的集中实测，仍记录真实用户活动信号；以后无人值守配置应按运行需要恢复暂停策略。这份配方验证工作流，不用于宣布统计显著收益。

```pwsh
.venv\Scripts\python.exe scripts/m5_seg_autoloop.py run --run-id t16_autonomous_validation_20261009_r2 --config docs/T16_AUTONOMOUS_VALIDATION_CONFIG_20261009.json --dry-run
.venv\Scripts\python.exe scripts/m5_seg_autoloop.py run --run-id t16_autonomous_validation_20261009_r2 --config docs/T16_AUTONOMOUS_VALIDATION_CONFIG_20261009.json --no-dry-run
```

配方或源码变化使用新 run id。成功采集后的再次运行可以复核原凭证并恢复已有学习判定；命令不会将拒绝结果变成通过。旧最终封存集不进入上述输入。

训练阶段补测使用 `docs/T16_EXISTING_DATA_VALIDATION_CONFIG_20261009.json`（`collect=off`，固定 R2 真实生成并核验的 4 帧自动包提议，其他训练预算相同）。R2 原结果不改写；该新目录补测最新代码的跨轮基线保存与学习判定，不重复采集，也不算另一次新数据生成：

```pwsh
.venv\Scripts\python.exe scripts/m5_seg_autoloop.py run --run-id t16_learning_validation_20261009_r3 --config docs/T16_EXISTING_DATA_VALIDATION_CONFIG_20261009.json --no-dry-run
```

仍需依次完成：

1. **小预算真实训练**：用既有合格开发数据执行后台入口，核对实际优化步数、初始权重摘要、参数变化与逐阶段指标。两轮及中断恢复分别留证据；命令接线测试不能代替反向传播实测。
2. **无人值守数据准入**：复用 Tech 采集与 annotation 审计。逐类验证 RGB 对齐、类别覆盖、实例身份和场景来源；不要求用户新增手工标签。不完整线监督只作研究臂，不能冒充独立完整真值或自动晋级依据。
3. **解决横向链**：记录候选、真实感知边界、选择路径、控制路径、扫掠几何、铺装门与最终指令；执行可信车道、缺车道、路外中心、车体越界的正反例。保持不倒车、不压线，无导航线加固定偏移兜底。
4. **新证据评测**：独立冻结开发／确认数据，按地图场景与内容去重，配对种子、同预算、同协议；已消费的最终集不用于继续选择配方。像素、实例、几何和驾驶分别报指标与缺测。
5. **可视化闭环**：当前看板需展示实际采集资格、训练配方、权重与数据谱系、评价范围、拒绝原因、时延分解和恢复状态。不得只凭 loss 下降展示“模型变好”。
6. **论文复现交付**：更新中英正文、补充、投稿源与 PDF，运行源包检查、主张审计与最小证据归档；明确缺失几何证据、实际驾驶未过门及跨地图未确认的局限。

## 5. 验收与工作顺序

- 用户 2026-10-09 指定：**先完成本轮全部代码改动，再统一离线回归，再集中实测**。代码冻结后的真实训练／Tech 测量期间不修改源代码，以免污染源码身份与时延。
- 每个模块包含实际执行分支的确定性回归；按项目约定执行 `scripts/dev_validate.ps1`。
- CPU 回归、真实训练和 Tech 时延测量串行；时延重复测量按既有纪律取较小值入硬门，同时保留重复原值。
- 先验证单基线机械运行的分类与收尾，再决定哪些旧条件需要补跑；不以工具修复追认旧数据有效。
- 后续完整成功仍需真实学习收益、可解释的感知到控制证据及论文可复现产物。本轮基础设施修复不能视作项目或论文研究目标完成。

实测顺序为：自动生成与独立准入 → 后台两轮真实反向传播及恢复 → 带几何的 Tech 基线与离线控制链回放 → 论文 PDF 和证据归档。任何失败保留原始产物，按失败原因处理；训练与驾驶不共享游戏控制权。
