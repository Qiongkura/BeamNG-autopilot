## 0. 前置约束（来自 AGENTS.md，不可违反）

任何在本方案中被采纳的机制，都必须满足：

1. **横向参考只能来自感知**（语义分割 / 漆线投影 / 可行驶边界），不得来自导航线或地图线 + 固定偏移。
2. **感知不可用时的合法降级只有三种**：刹停、保持当前航向直行、落到路面安全点。
3. **strict 绝不倒车、绝不压线。**
4. **没有可靠边界时 fail-closed 停车**，不得用猜测的边界继续开。
5. 缺测写 `UNKNOWN`，**不得当作 PASS**。

**本方案中有三个机制会触碰这条红线，必须按注明的边界使用**（见 §10 的"有条件采用"）：

- 时序列机制（粒子滤波 / EKF / IMM / 中值滤波）的**预测值**；
- 龙彩霞的**转向角先验**；
- 陆军 / 黄炜的**左右对称先验**。

## Phase 0：口径与评估方法学（前置，不改行为）

> 不做完 Phase 0，后面所有数字都不可比。这一 Phase 全部是"测量契约"，不涉及驾驶行为。

### 0.1 统一停车统计口径

- **做什么**：明确 `settle_s`、采样规则、停车阈值；每跑次并列输出 `raw_frames / settled_frames / speed_lt_0_3_frames / final_stop_frames / emergency_frames / stall_seconds / longest_continuous_stall_seconds`，并按 `reason / effective_rule` 分类累计秒数。
- **依据**：本轮审阅发现的 P0 缺陷（同一跑次可算出 54/57/59 三个"停车帧"数）。
- **改哪里**：`beamng_autopilot/eval.py`、`scripts/m5_fsd_benchmark.py`、`scripts/m5_coverage_index.py`、`scripts/m5_run_metrics.py`。
- **验收**：报告里任一停车数字都能由一条命令 + 一个 JSON 复算；缺列输出 `UNKNOWN` 而非 0。
- **代价**：低，纯统计。

### 0.2 标线评估改为容差带 + 三分法

- **做什么**：
  1. 横向误差**只统计超出容差带的部分**：`λ = max(|GT − X| − W/2, 0)`，其中 `W` 是标线物理宽度在世界坐标下的当量；
  2. 结果分三类：**正确**（≥N/2 的估计落在容差带内）/ **漏检**（>N/2 落在外）/ **误检**（本无标线却检出）；
  3. 同时报告**偏查准**的指标（对"把某处判为可行驶"的用途，查准率优先于查全率）。
- **依据**：Borkar et al. 2012（§III.B.2 容差带度量 + §IV 三分法）；吴一全 2019（查准率优先论述）。
- **改哪里**：`scripts/m5_eval_seg.py`、`scripts/m5_lane_metrics.py`。
- **验收**：标线指标能区分"亚像素差异"与"真漏检/真误检"；报告的 line IoU 与容差带指标并列。
- **代价**：中，需要世界坐标下的标线宽度基准。
- **注意**：Borkar 的 6 英寸容差是它的 IPM 分辨率下的值，**必须用你自己的世界坐标重新标定**，不能直接套用。

### 0.3 建立离线回放评估（替代不可比的实车跑次）

- **做什么**：把已有连续片段做成离线样本，用回放方式做可重复评估；每次改动先在回放上跑，再上实车。
- **依据**：易世春 2014（离线样本 + 硬件在环测试方案）。
- **改哪里**：`scripts/m5_fsd_replay.py`、`scripts/m5_shadow_replay.py`（已有基础，扩展为正式评估入口）。
- **验收**：同一改动在回放上可重复得到同一结果；实车只用于确认。
- **代价**：中。

### 0.4 测试集按退化因素组织，而非按配置

- **做什么**：把测试跑次按**退化因素**分组：光照（昼/昏/夜/逆光）、标线状态（清晰/磨损/缺失）、道路（直道/弯道/发夹弯/路口）、遮挡。每组的记录条数与覆盖单独统计。
- **依据**：Son et al. 2014（10 组光照条件：自然光变化 + 人工光变化 + 隧道 + 车道灯）；McCall & Trivedi 2006（65 km × 四个时段）。
- **改哪里**：`scripts/m5_scenario_set.py`、跑次清单与报告模板。
- **验收**：报告能回答"哪一类退化下失败最多"，而不是只有总里程。
- **代价**：中（需要重跑或重新归类已有跑次）。

### 0.5 横向指标改为三件套

- **做什么**：采用 **横向位置误差均值 + 横向位置误差标准差 + 横向速率误差标准差**。前两个衡量精度，第三个衡量预测能力。
- **依据**：McCall & Trivedi 2006 §V.C（明确选这三个，并说明 TLC 因位置/横向速度的小误差产生大误差、且真值难造而被放弃）。
- **改哪里**：`scripts/m5_lane_metrics.py`、报告模板。
- **验收**：第三个指标存在且非空；能区分"位置准但速率抖"与"位置偏但速率稳"。
- **代价**：低（依赖 1.1 提供速率）。

### 0.6 假设审计表（每轮报告必附）

- **做什么**：固定四行，逐轮填写当前依赖与风险：

| 假设 | 依赖位置 | 失效场景 | 本项目暴露情况 |
|---|---|---|---|
| 路面纹理一致 | CNN 路面通道 | 改道/加车道/出口处位置估计出错 | 城镇路口 |
| **车道宽度局部恒定** | `LANE_WIDTH_DEFAULT_M`、`pair_width`、`lane_half_m` | **城市驾驶、合流/匝道处** | 城镇段 |
| 标线外观有规则 | 白/黄线掩码 | 深色线在浅色路面、反光道钉 | BeamNG 标线 |
| **路面是平面或固定高程模型** | 地面反投影 | **弯道上的高程变化导致曲率估计错误** | 山路 |

- **依据**：吴一全 2019 §2 开场（四假设清单）；McCall & Trivedi 2006 §III.E（四假设的**失效条件版本**）。
- **改哪里**：报告模板（`docs/REPORT_FORMAT.md` 的八项必附中扩展一项）。
- **验收**：每轮报告有这个表，且"暴露情况"一列有实测证据。
- **代价**：零。

## Phase 1：状态与判据（纯逻辑，不需重训，不改感知）

### 1.1 引入横向状态估计 `(e, ė, θ, θ̇)`

- **做什么**：在参考发布与使用之间加一个滤波状态。**第一步只写遥测、不改控制**，用已有跑次 JSON 离线回放对比"逐帧原始量"与"滤波状态"。
- **状态向量**（取彭红的裁剪版，去掉与自车无关的相机参数）：`(e, ė, θ, θ̇)`，其中 `e` = 相对本车道中心的横向偏移、`θ` = 相对车道方向的航向偏差。
- **依据**：彭红 2015（EKF 状态含 `θ, θ̇, e, ė, c₁, c₀, φ, W`，并明确"新增 θ̇ 与 ė 的估计使稳定性、抗干扰性与检出率提高"）；McCall & Trivedi 2006（横向速率指标）；罗强 2014（FOD 需要侧向速度）。
- **改哪里**：`beamng_autopilot/lane/tracking.py`（承载滤波）→ `beamng_autopilot/lane/reference.py`（发布）。
- **验收**：遥测出现 `e / e_dot / theta / theta_dot`；离线回放中速率序列的噪声显著小于逐帧差分的噪声。
- **代价**：低。**不改控制，风险接近零。**

### 1.2 参考存在性概率化 + 双阈值滞回

- **做什么**：把"参考可信/不可信"从硬门控改为**两个假设的概率竞争**：
  1. 两个滤波器，**预测模型相同、测量模型不同**：`i=1`（参考为真，正常测量噪声）、`i=0`（参考为假/不存在，**更大的测量噪声**——理由：误检的残差分布更散）；
  2. 残差似然：`Λ_i = N{ν_i; 0, S_i}`；
  3. 贝叶斯更新：`μ_i(k) = Λ_i·μ̄_i / Σ_j Λ_j·μ̄_j`；
  4. 交互步：`μ̄_i(k) = Σ_j π_ji·μ_j(k−1)`（Markov 转移矩阵编码"切换的可能性"，替代临时的计数器）；
  5. **决策用滞回**：`D=1` 需 `μ₁ > μ_high`，`D=0` 需 `μ₁ < μ_low`，`μ_high > μ_low`。
- **依据**：Kang et al. 2012 §III（IMM + 概率决策 + 滞回），并被 程国柱 / 龙彩霞 的"连续权重而非二值门控"独立印证（收敛 3）。
- **改哪里**：`beamng_autopilot/lane/reference.py`（门控段）、新模块 `beamng_autopilot/lane/hypothesis.py`；测试 `tests/test_lane_reference.py`。
- **验收**：
  - 同一路段的参考侧别翻转次数显著下降；
  - `lane_src` / `lane_from` 的逐帧分布不再出现"三种读法交替"；
  - **滞回生效可观测**：`μ₁` 与 `D` 的遥测同时存在，且翻转点只在阈值穿越时发生。
- **代价**：中。**这是本方案里对"参考翻转"最根本的一改。**
- **红线**：`i=0` 假设"参考不存在"**不等于**"可以用预测续命"。`D=0` 时仍然 fail-closed，只是不再把"参考不存在"误判为"路径不存在"。

### 1.3 宽度从硬阈值改为概率先验

- **做什么**：`pair_width` / 侧向偏移的硬阈值改为带 `(μ, σ)` 的似然（宽度应接近车道宽度先验），并**把宽度作为被跟踪状态**纳入 1.1 的状态向量。
- **依据**：刘富强 2010（MAP 中 `p(x) ∝ exp(−(o₂−o₁−μ)²/σ²)`；粒子滤波状态含车道宽度 `w`）；程国柱 2026（边界互斥 τ=0.2 m）；徐美华 2016（宽度进候选计分）；McCall & Trivedi 2006（**注意其失效场景：城市/合流处**）。
- **改哪里**：`beamng_autopilot/lane/pairing.py`（打分）、`lane/reference.py`。
- **验收**：遥测中每个候选带"宽度似然"；**已知两种错配对（整条路 7.6 m、分隔线+左侧线 2.0 m）的似然显著低于正确配对**——这是可离线验证的。
- **代价**：低。

### 1.4 失效判别三条 + 跟踪/重检测状态机

- **做什么**：
  1. 加两条**失效判据**：① 本帧参数相对上一帧**突变**；② **平行度/倾角置信度**低于阈值（你现有的是"检测为空"的等价物，缺这两条）；
  2. 加**跟踪模式 ↔ 重检测模式**状态机与失效计数：连续 T 帧（原文 T=5）无有效观测 → 清空参考与滤波窗口，回到"全图重检测"。
- **依据**：杨喜宁 2010（失效判别三条判据）；陈涛 2016（跟踪↔重检测切换 + T=5 失效计数）。
- **改哪里**：`lane/reference.py`、`lane/tracking.py`、`lane/geometry_check.py`（平行度计算已有基础）。
- **验收**：注入式单测——构造"参数突变帧""低置信度帧""连续 5 帧无观测"，验证状态机按预期切换与复位。
- **代价**：低，纯逻辑。

### 1.5 偏离判据：按原理组合，不选单一判据

- **做什么**：按下列组合替换单一 `lane_dev` 硬阈值：

| 组件 | 做法 | 依据 |
|---|---|---|
| **位置项（CCP）** | 保留，但**仅在直道/低速成立** | 罗强指出 CCP 前提是"航向近似平行于车道边界" |
| **预测项（FOD）** | 加 `L_p0 = L_p + L_v·T`（侧向速度 × 预瞄时间），判据 `L_p0 > 边界` | 罗强 2014（FOD 判据） |
| **越线时间项（TLC）** | `y(s) = y₀ + α·s` 或恒定转角模型，与边界求交后除以车速 | 罗强 §2.4.3（两种运动模型） |
| **TLC 的航向修正** | 用 1.1 的 `θ̇` 补"航向角变化"——这正是罗强点出的 TLC 缺陷 | 彭红 2015 + 罗强 2014 的交叉 |
| **距离度量** | 车辆建为**四角点矩形刚体**，用角点到边界的距离，而非单一中心点距离 | 董因平 2004 |
| **判定方式** | 硬阈值 → **模糊隶属度**（单极性 Sigmoid），实现连续降级而非二值跳变 | 董因平 2004 |
| **按速度分档** | 低速用位置项、高速用时间项（阈值切换） | 孙铭宽 2026（40 km/h 切换 TLC/CCP） |
| **横摆率项** | 距离偏置差变化率（N 帧窗口）独立成一路判据 | 张三林 2015 |

- **改哪里**：`beamng_autopilot/safety_monitor.py`（判据）、`beamng_autopilot/planning/lateral_ref.py`、`beamng_autopilot/vehicle_body.py`（四角点距离已有 footprint 基础）。
- **验收**：
  - 直道与弯道各有确定性正反例；
  - **"safe / degraded / minimal_risk"之间的转移是连续的**（隶属度可观测），不再在阈值附近抖动；
  - 弯道段的横向异常不再被误判为"阈值调得不对"。
- **代价**：中高，但这是把 5 篇的判据合成一条链。

### 1.6 可变虚拟边界（自适应边界 + 模糊规则）

- **做什么**：把"警告边界"从固定几何事实改为**随状态调整的量**：
  - 输入：`y`（横向位置，值域参考 [0, 1.6] m，高斯隶属）、**`y'²`（横向速度的平方**，值域参考 [0, 0.6] m²/s²，高斯隶属）、驾驶风格/模式；
  - 输出：边界调整量 `Δv`（范围参考 [0, 0.5] m，梯形隶属）；
  - 规则：`IF (y is near) AND (y'² is large) THEN (Δv is large)`，Mamdani 推理 + 反模糊化。
- **依据**：罗强 2014 §3.3（VVLB）。**注意：该章是设计而非验证**——原文承认"由于研究时间和实验条件有限，本文无法对所建立的预警模型进行测试和检验"。所以机制可借，效果无证据。
- **改哪里**：`safety_monitor.py` 的阈值来源。
- **验收**：边界调整量可观测；**小幅漂移几乎不调整、大幅漂移显著调整**（即 `y'²` 的二次响应成立）。
- **代价**：中。
- **注意**：值域是罗强按它的车道宽度标定的，**必须按你的车道宽度重新标定**。

### 1.7 参考的时序滤波（中值，带强制复位）

- **做什么**：对**已被证据接受的**参考做长度 N=5 的**滑动窗口中值**滤波。
- **必须同时实现的两条约束**：
  1. **滤波只平滑"已被感知证据接受"的参考，不得把滤波结果当作新的感知证据**（遥测需区分"本帧来自观测"与"来自滤波"）；
  2. **证据断档必须立刻复位窗口**，不允许用中值把旧参考续命。
- **依据**：孙铭宽 2026 §5.3.1（N=5 中值，抗脉冲噪声；仿真显示能隔离单帧 0.8 m 的脉冲）；McCall & Trivedi（预测与观测的区分）。
- **改哪里**：`lane/tracking.py`。
- **验收**：脉冲式单帧跳变不再传播；**断档帧后窗口长度为 0**（可观测）。
- **代价**：低。
- **红线**：这是本方案中**最容易被误用**的一项——见 §10.1。

### 1.8 干扰线排除层

- **做什么**：把散落在多篇里的"排除"机制合成一个显式层：
  1. **极角/方向约束**：限定候选线段的允许角度区间（左/右不同）；
  2. **只取内侧**：对多车道场景，优先取本车道内侧边界，主动排除旁侧车道线与护栏；
  3. **内外边界判定**：配对时取内边界而非任意边界；
  4. **特征约束**：用车道线的几何特征（宽度、平行度、连续性）排除干扰线段。
- **依据**：杨喜宁 2010（极角约束区域）；何鹏 2015（左线 θ∈(−75°,−30°)，右线 θ∈(30°,75°)）；李亚娣 2016（只取本车道内侧，排除旁侧与护栏）；彭红 2015（选内边界 + 特征约束排除干扰线）；Son et al. 2014（候选筛选）。
- **改哪里**：`lane/pairing.py`（候选生成与筛选）。
- **验收**：构造"护栏在旁""对向车道线可见""平行长干扰线"三类确定性用例，验证候选被正确排除。
- **代价**：低。
- **对应你的已知失败**：配对到对向车道、把护栏当边界。

## Phase 2：边界来源（无标线时）

> 你的实际事故（出铺装、撞树、大量 `no_drivable_path` 停车）**全部发生在标线不可用的时刻**。所以本 Phase 的适用面比所有车道线论文更贴你的问题。

### 2.1 路面边界升格为"共同类边界" + 动态权重

- **做什么**：把 `paved_fallback` 从布尔开关改为**连续加权裁决**：
  ```
  w(t) = ρ_curb · ρ_lane · ... · exp(−β·∇D(t))
  ```
  - 边界越可信（`ρ_curb` 高）越该用；
  - **标线越清晰越不该用边界先验**（`ρ_lane` 反向）；
  - **侧向距离梯度 `∇D` 大处（分合流、路口、宽幅多车道）主动衰减先验**。
- **依据**：程国柱 2026 §2.4（动态拓扑权重）。
- **改哪里**：`lane/reference.py`（现在 895–911 行附近是"整段切换"）、`vision/line_evidence.py`（`ρ_lane` 的现成来源）。
- **验收**：路口段与分合流段的权重自动衰减可观测；标线清晰段的权重接近零（即不干预）。
- **代价**：中。

### 2.2 LiDAR 道路边界：曲率/半径梯度 + B 样条

- **做什么**：
  1. 用**单束激光的曲率/半径梯度**提取边界特征点（**不要用高度差阈值**）；
  2. 用 **B 样条**拟合边界；
  3. 平面过滤做粗分割（允许不精确），边界检测做精提取。
- **依据**：王俊 2016 §5（明确"基于高度差阈值的方法在起伏地面上失效"，改用曲率梯度，并用三次 B 样条拟合；场景为乡村不平路面）；Zhang et al. 2018（分段路缘检测 + 高度/水平阈值自标定）。
- **改哪里**：LiDAR 处理链（`beamng_autopilot/perception.py` 相关）+ `lane/pavement.py`。
- **验收**：在坡道/不平路段上，边界点提取的稳定性优于现有高度差判据（可离线对比）。
- **代价**：中高。

### 2.3 阈值从传感器几何推导（逐线自标定）

- **做什么**：把 LiDAR 的"是否在路面"判据从固定阈值改为几何推导：
  ```
  δ_xy,l = H_s · cot(θ_f,l) · θ_a         水平期望间距
  δ_z,l  = δ_xy,l · sin(θ_f,l)            垂直期望间距
  ```
- **依据**：Zhang et al. 2018 §III.B（`H_s` 传感器高度、`θ_f,l` 第 l 线垂直角、`θ_a` 角分辨率）。
- **改哪里**：LiDAR 地面点筛选。
- **验收**：判据随激光线号自动变化；不再有手工距离阈值。
- **代价**：低。
- **同一洞察的另一个应用**（供参考）：孙铭宽 2026 用标准车道宽反推像素尺度 `Kx = W_real / W_pixel`，并称其"能实时适应俯仰角变化引起的投影缩放"。

### 2.4 粗到精两阶段（允许粗阶段不精确）

- **做什么**：明确"粗分割 + 后续专用检测"的两段式；**粗阶段允许不精确**，不把它的质量当作下游的硬前提。
- **依据**：Zhang et al. 2018 §II.B 原话——路面与 sidewalk 的精确提取"**都不必要**"（阈值仅取平均路缘高程 0.2 m）。
- **改哪里**：`lane/reference.py::_drivable_fraction` 的 60% 门槛语义（**不是降低门槛**，而是把它从"硬前提"改为"证据强度的一部分"）。
- **验收**：模型漏检导致的掩码退化，不再直接等价于 fail-closed 停车；但**真实的非铺装仍然 fail-closed**。
- **代价**：中。
- **注意**：这与 1.2 的概率化是同一件事的两面，建议合并实施。

### 2.5 路口/无边界时的模式切换

- **做什么**：把决策输出用于**切换控制模式**，而非只切一个标志：
  - 边界可信 → 边界跟随模式；
  - 边界不可信（路口）→ **保持航向通过**（对应 AGENTS.md 允许的"保持当前航向直行"）。
- **依据**：Kang et al. 2012 §III.B 原话——决策规则使控制策略在"缘石跟随模式"与"路口穿越模式"之间切换；**路口时依靠航位推算保持期望方向**。
- **改哪里**：`beamng_autopilot/fsd_drive.py`（模式层）、`safety_monitor.py`。
- **验收**：路口段的停车秒数下降，且**不引入越界**；"我在路口"的判断有独立证据（不能只靠边界丢失这一条负面证据）。
- **代价**：中高。
- **⚠️ 这是本方案中需要你**人工决策**的一项**：你现在的规则是"可疑就停"，Kang 是"路口就保持航向通过"。后者的前提是**"我在路口"必须可信**——这一条我没有在你的实现里找到独立证据源，**建议先补这个证据，再改行为**。

### 2.6 固定距离参数不用于路口（滑束）

- **做什么**：任何用"固定前向距离"处理路口的逻辑，改为随场景滑动的模型。
- **依据**：Zhang et al. 2018 §III.A 原话——前作用固定距离，"**很难确定一个对各种路口都鲁棒的固定距离**"，故改为滑束。
- **改哪里**：路口相关的局部路线/ROI 逻辑。
- **验收**：不同尺寸路口下不再出现"刚好在参数边界上失败"的模式。
- **代价**：中。

### 2.7 坡道投影核对（零算力，纯核查）

- **做什么**：核对地面反投影用的是"过车体高度的**水平面**"还是"带车体俯仰的平面"。取山路坡道帧，比较两种假设下的落点差。
- **依据**：陈小海 2025 §1.1（带高度 z 的 BEV↔自车换算 `x = x'·(1 − z/h)`，明确 z 会改变横向坐标）；吴一全 2019（引文献[68]：训练网络预测 IPM 投影矩阵，**去除路面平坦假设**）；McCall & Trivedi §III.E（"弯道上的高程变化会导致曲率估计错误"）。
- **改哪里**：`beamng_autopilot/vision/projection.py`。
- **验收**：给出坡道段两种假设的横向落点差。**若差 > 0.1 m，之前所有坡道段的横向指标都需重新解读。**
- **代价**：零改动，只需核查与离线对比。
- **优先级**：**建议排在 Phase 1 之前或并行**——它影响你对已有数字的信任度。

- 改哪里：骨干。

- 改哪里：`SegUNet` 骨干。
- 验收：分割耗时显著下降，精度损失在容许范围。
- 代价：中（重训）。

### 3.9 光照鲁棒：百分位阈值 + 分类管线
- 依据：Son et al. 2014（**对角模型 → 序关系保持 → YCbCr 的 Y/Cb + 累积直方图百分位阈值**；白线前 3%、黄线最低 1%）；杨喜宁 2010（按整体灰度均值分类，暗用灰度拉伸、亮用均衡化，正常用 Sobel、强光用 Canny）；陈涛 2016（**不做固定灰度化**，RGB 分解为单通道分别处理，避免"削弱车道线像素优势"）。
- 改哪里：`vision/lanes.py::_color_masks()`（现在是绝对阈值 `WHITE_GRAY_MIN=150` 等）。
- 验收：跨光照的分割稳定性改善。
- 代价：低（经典 CV 兜底路径）。
- **注意**：你有 CNN 主干，经典 CV 只是兜底，**这条本身收益有限；真正可复用的是"凡绝对阈值都应问能否改为当前帧的百分位"这个原则**。

### 3.10 先验融合（两个来源，均在感知层）
- **路缘几何先验**：程国柱 2026（`w(t)`，标线退化时启用，标线清晰时抑制；**论文自承在上下坡 F1 52.4、急弯 61.1 明显退化 → 平行先验必须按曲率门控**）。

- 改哪里：`vision/heads/semantic.py`、`vision/line_evidence.py`。

## Phase 4：数据与标注（可并行，不受其他 Phase 阻塞）

### 4.1 time slicing：把标注成本降一个数量级
- **做什么**：
  1. 从连续片段按**固定行**抽帧堆叠成 `F×N` 时序切片图（**行 = 帧号**）；
  2. 用户在不同行的 2–3 张切片图上标**少量控制点**；
  3. **三次样条插值**（C² 连续）补出控制点之间的帧；
  4. 取某一行（= 某帧）的点映射回该帧图像，**再做一次样条**补出行与行之间；
  5. 对所有帧重复。
- **依据**：Borkar et al. 2012 §III.B（time slicing 全流程；原文称不做自动化则"几小时的视频生成真值可能要花数周"）。
- **改哪里**：新脚本（如 `scripts/m5_timeslice_annotate.py`），与 `scripts/m5_annotate_manual.py` 并存。
- **验收**：
  - 人工工作量按"控制点数"而非"像素数"计；
  - 生成的标签**在时间上连续**（这是副产品，也是你需要的）。
- **代价**：中。
- **⚠️ 前置条件（必须先查）**：**TS 要求时间连续的帧**（依赖车道线在相邻帧平滑移动）。
  - 若你那 142 帧是**散布的关键帧** → TS 用不了，需先改为"采集连续片段 + 时序切片标注"；
  - 若是**连续片段** → 可直接用。
  - **这是本方案中第一个应该去查的事。**

### 4.2 采集连续片段（若 4.1 前置条件不满足）
- 依据：Borkar et al. 2012（其框架包含"系统性存储视频"）；朱威 2021（多帧序列是时序方法的前提）。
- 改哪里：`scripts/m5_collect_seg.py`、`scripts/m5_collect_seg_ring.py`（`--step` 已支持序列取帧）。
- 验收：得到**车辆在行驶中**的连续帧序列（不是停车状态的近似重复帧）。
- 代价**：低。

### 4.3 跨视角标线留出验证
- 依据：你报告里"标线只标一次即可跨视角迁移"目前**未被验证**。

## 14.1 时间模糊连虚线 —— **已实现，改为"验证与补遥测"**（2026-09-22 核查后更正）

> **更正说明**：本节初稿把它列为"最高性价比的待实现项"，并怀疑"累积证据没喂给连通域提取"。
> **代码核查否定了这个怀疑**，而且发现该机制**已经实现了两次**。以下为更正后的内容。

### 已存在的实现（两套）

**（1）世界坐标多帧累积**：`beamng_autopilot/vision/line_evidence.py::LineEvidenceAccumulator`
- **文件开头就引用了 王俊 ch3**（"Adapts the spatio-temporal matching-fusion idea from 王俊《无人驾驶车辆环境感知系统关键技术研究》ch3"）；
- 已做：逐帧标线掩码反投影到地面平面 → **带 ego 位姿补偿**的逐格证据累积 → 把累积证据**重投影回当前视角并与当前掩码取并集**；
- `HIT_MIN=1.25` 的门限保证"单帧假阳永远不会被传播"；
- 双置信度（`current_confidence` / `history_confidence`）+ 过期规则（`MAX_AGE_S=6.0`）已实现；
- `support_mask()` 支持"只读不投票"，供远场分区规则使用（E2）。

**（2）同帧内共线碎片分组**：`vision/lanes.py::recover_dashed_boundaries`
- 动机（代码注释原文）："the town `line` class is **mostly short blocks (median 17 components per frame, median height 7 px), so a dashed lane line leaves no usable boundary behind**. Group the discarded collinear fragments back into one long boundary so the own lane can have two detected edges again."
- **有实测 A/B**：paired own-lane **13.0% → 28.2%**，`lane_sel=sensor` **27.7% → 59.7%**；
- 成本已优化：`_mask_fragment_polylines` 从 **53.7 ms → 3.2 ms**（整段 ~70 ms → ~3.6 ms，做法：相机位姿每帧构建一次而非每采样像素一次；标签图扫一次而非每组件一次）；
- 现在 **默认 ON**（`BEAMNG_DASHED_RECOVERY=0` 关闭）。

### 核查确认的接线（正确）

```
seg.predict_with_probs()  →  _predict_timed
    └ _postprocess:  strip_soil_from_road → _morph_close_line
                     → _temporal_line_gate(默认关) → constrain_line_to_road → filter_line_shape
```

- `enable_evidence` 默认 `True`（`vision/heads/semantic.py:51`）；

**结论：证据融合的结果确实进入了连通域提取。初稿的怀疑不成立。**

### 核查发现的三个真问题（实测数据支撑）

**（P1）约 1/3 的标线证据是"记忆"而非当帧观测 —— 但没有任何横向消费者使用这个事实**

`line_conf_current` = 被支撑格中"最近一次观测就是本帧"的比例。跨 23 个跑次的实测：

| 量 | 值 |
|---|---|
| 跨跑次中位数 | **0.661** |
| 各跑次中位数范围 | 0.434 – 0.849 |
| 全部 23 个跑次 | **均 < 0.9** |
| 最低单帧 | **0.093**（`models2_nodqn`，**即撞树那次跑次**） |
| 其它低值 | `linesfix1` 0.185、`p13_gate_on` 0.000、`models1` 0.196 |

即：**典型帧里约 34% 的标线证据是"记住的"而不是"看到的"**；撞车跑次的最差帧达到 91% 靠记忆。

而 `line_conf_current` 的**唯一消费点**是 `fsd_drive.py:3809` → `long_planner.update(line_conf=...)`：
- 那是 **D4 纵向规划器**，只影响**速度**的置信度缩放；
- 而 **D4 默认关闭**（`BEAMNG_LONG_PLAN=1` 才开）。

**因此：AGENTS.md 的红线"预测不得授权横向位置"，在证据层面没有任何机制在执行。** 这条需要补。

## 14.2 可操控滤波器（steerable filters）——完整实现

- **为什么它是真正的光照无关**：它响应的是**二阶导（结构）**，不是绝对亮度。这比 ESWA 的百分位阈值更彻底——后者只是让阈值跟着光照走，前者换掉了特征本身。
- **公式**（二维高斯二阶导）：
  ```
  Gxx = ∂²/∂x² e^{−(x²+y²)/σ²}
  Gxy = ∂²/∂x∂y e^{−(x²+y²)/σ²}
  Gyy = ∂²/∂y² e^{−(x²+y²)/σ²}
  任意角度的响应:  G2θ = Gxx·cos²θ + Gyy·sin²θ + Gxy·cosθ·sinθ
  极值角:          θ_min/max = arctan( (Gxx − Gyy ∓ A) / (2·Gxy) )
  ```
  **注意**：`A` 的表达式在 PDF 文本层里丢了根号（印出为 `G²xx − 2GxxGyy + G²yy + 4Gxy`），**实现前必须对照原文核对**。
- **判别规则**：
  - **圆形道钉**：各方向响应都高 → **最小值高 且 最小/最大响应接近**；
  - **线标线**：某方向响应高、最小响应低 → 对"**车道方向响应 − 最小响应**"取阈值即可检测特定角度的线。
- **两个实现要点**：
  1. **核尺寸 ≈ 3 倍标线宽度**；
  2. **在 IPM/BEV 图上滤波 → 全区域可用同一个核尺寸**（透视消除后标线宽度均匀）。**你已有 BEV，同一论证成立——这省掉多尺度搜索。**
- **可分离**：拆成 X、Y 分量 → 两次一维卷积代替一次二维卷积。
- **对阴影路段有效**（论文给了树影路段的例子）。
- **依据**：McCall & Trivedi 2006 §IV.B（这份是全部语料里**唯一给出实现路径**的）。
- **归入**：Phase 3 / 经典 CV 兜底路径（替代 `vision/lanes.py` 的固定阈值）。
- **验收**：同一路段跨光照（含阴影）的标线召回稳定；单帧耗时低于现有多尺度方案。
- **代价**：中。

## 14.8 KBIRS：第四种预警模型（罗强清单里没有的）

余天洪把预警模型分为**四种**，比罗强的五种少一类但多一类：

| 模型 | 余天洪的表述 |
|---|---|
| CCP | 令 `y₀` = 车辆中心与车道中心距离，假设车辆大致与车道平行；由车宽 `b` 求前轮相对左右边界的距离，**任一侧 < 0 即判偏离** |
| FOD | 虚拟边界加驾驶习惯偏离量；触发 `L'_p > V`；`L'_p = L_p + T·L_v`（`L_v` = 侧向速度，`T = (V−x)/L_v`） |
| TLC | 两种模型：① 航向不变 `y(l) = y₀ + β·l`；② **转角不变 `y(l) = y₀ + β·l + c₀·l²/2`**，`c₀` 由当前方向盘转角算得；左右车轮轨迹 = 中心 ± b/2 |
| **KBIRS** | Knowledge-Based Interpretation of Road Scenes——**通过场景感知的剧烈变化判定偏离**："如车辆产生大幅度偏移，则场景感知会发生剧烈的改变，当这种情况发生时，就应当发出警告"。**论文自承"目前仅仅作为一种理论观点……还不够完善"** |

- **KBIRS 对你的价值**：它是一个**不依赖几何量、不依赖标定、不依赖边界**的偏离判据——纯"画面剧变"检测。适合作为**独立的交叉校验层**（当几何链路失效或自相矛盾时，它能给出一个正交的判断）。
- **TLC 公式的收益**：第②种模型的**二次形式在余天洪这里写得比罗强清楚**（罗强那份的公式在文本层散掉了）。`c₀` 由方向盘转角算得——**你有方向盘转角，可直接用**。
- **§7.3 的选型**：余天洪最终采用**横向位置 + 方向参数**模型（与罗强 §2.4.5 **独立选择了同一个**）。
- **整个论文的光照主题**：第 2 章正常光照、第 3 章非正常光照、第 4 章不同光照下重建、**第 6 章基于 BP 神经网络的道路图像光照模式分类器**——这是一整本讲"光照鲁棒"的博士论文，与你标线学不出来的问题同源。

## 15.0 ⚠️ 一条改变执行顺序的结论（最高优先）

**Bar-Hillel et al. 2012 §4.4 明确指出**：

> 多数跟踪方法的一个弱点是**naive 的逆透视变换，它假设相机标定稳定且地面是零高度平面**。**车辆振动与地面坡度的变化会向时间序列注入噪声与突变**，这给带强平滑假设的跟踪方法（如 Kalman 滤波）造成困难。

**这是第四次独立指出"平坦地面假设"的问题**（此前：陈小海、吴一全引文献[68]、McCall & Trivedi），但**它指出的是新的一层后果**：坡道突变会**破坏时序跟踪本身**。

**对本方案的修正**：
- 原 §2.7（坡道投影核对）被列为"零算力，可最早做"，但**没有说明它是 Phase 1 的前置条件**；
- **现在必须把它前移为 Phase 1 的硬前置**：**不先修正 IPM 的平地假设，就不要引入 EKF / IMM / 中值滤波**——否则在坡道上，强平滑假设与坡度突变冲突，跟踪可能**比不跟踪更差**。
- **修订后的顺序**：`2.7 坡道投影核对` → `1.1 横向状态估计` → `1.7 中值滤波` → `1.2 IMM`。

## 15.1 B-Snake：把两条边界降维成"一条中线 + 一个标量"

Wang, Teoh & Shen, *Lane detection and tracking using B-Snake*, Image and Vision Computing 22 (2004) 269–280（被引 782）。

**核心推导**（假设地面两侧边界平行，右侧 = 左侧沿 x 轴平移 `D`）：

```
d = l²·D·(r − hz) / ( H·(l² + hz²) )  =  k·(r − hz)
k = l²·D / ( H·(l² + hz²) )
```
（`l` 焦距、`H` 相机高度、`hz` 图像中消失线位置、`r` 图像垂直坐标）

于是左右边界完全由中线与单个标量决定：
```
c_l = c_m − ½·d ,   c_r = c_m + ½·d
```

**为什么这条对你的价值很大**：

1. **它是"宽度先验"的纯几何形式**。我此前从刘富强取到的是概率形式（MAP 里的 `μ/σ`），B-Snake 给的是几何形式（`k` 由消失线与相机几何唯一确定）；
2. **它天然给出"单侧缺失时补另一侧"的方法**：观测到一侧 + 已知 `k` → 直接得到另一侧。**这不是猜测**——`k` 由消失线位置和相机几何决定，且可用观测到的那一侧在线标定。这落在 AGENTS.md 允许的几何契约范围内（不是"地图线 + 固定偏移"）；
3. **`d = k·(r − hz)` 同时告诉你"宽度在图像中随行号线性变化"**——这正是你 `pair_width` 判据应该用的形式，而不是一个常数区间。

**dual external forces（双外力）**：采样位置的计算结合"地面平行线"知识，所以**形变外力同时依赖两侧而非单侧** → 作者称其对阴影、噪声、偶发缺失与误标线鲁棒；且两个形变问题合并成一个 → 处理时间下降。

**B-Spline 相对多项式的第 4 条优势（对你的跟踪问题最关键）**：

> 本模型**特别适合车道跟踪**，因为当前帧的模型参数通常与上一帧相似，即**控制点的移动较小**。相反，对其他模型如二阶多项式车道模型，当道路形状有小变化时，**可能导致模型参数的大变化**。

**这解释了为什么参数化模型（多项式）跟踪不稳**——参数对形状变化敏感。对你的意义：如果用参数化参考，**优先 B 样条（3 个控制点足够）而非多项式**。

**仍需注意的坑**（Bar-Hillel §4.4）：跟踪样条时，每个控制点被运动模型移动，**有些会跑到车后或图像平面之外，需要重新排列控制点**——用世界坐标样条表示参考时会遇到同样的问题。

## 15.2 Bar-Hillel 2012：时序集成的三个目标（多出一个）

Bar-Hillel, Lerner, Levi & Raz, *Recent progress in road and lane detection: a survey*, Machine Vision and Applications 2012（被引 775）。

**§4.4 时序集成的三个目标**（此前我只从 McCall / 刘富强 / 吴一全拿到前两个）：
1. 提高正确检测的精度（预测检测 + 时间平滑）；
2. **减少所需计算量** —— 通过提供良好的模型参数初始化、**约束被搜索的参数空间**、**限制提取特征的图像区域**；
3. **纠正错误检测** —— 把当前检测与之前的比较，**在差异大时拒绝较不可能的那一个**。

**第 3 条是你的方案里缺的一环**：你的时序机制（证据累积、中值滤波、IMM）目前给出的都是"加权/平滑"，而**"当前检测与历史差异大时，主动拒绝较不可能的那个"是一个显式的、双向的判决**——它同时会拒绝"新来的错误检测"和"旧的错误历史"。

**其他可迁移的实现细节**：
- 自车运动估计三档质量：视觉匹配相邻帧 < **车辆里程计（速度 + 横摆角速度）** < **GPS + IMU 组合（最精确）**；
- **[9] 的"只在新露出部分搜索"**：等间距的（左-右）**成对**车道边界点，帧内沿车道用粒子滤波跟踪；下一帧用**车辆里程计**跟踪这些点，**粒子滤波只用于在新露出的车道部分找点对** —— 这是纯粹的算力节省思路，对你的 tick 预算直接相关；
- [53]：**横向与时间相干性联合**引导概率模型来分组两条边界，时间推理用**动态贝叶斯网络（DBN）**给上一帧生成的假设打分；
- [30]：**时序滤波剔除"稳定道路路径"中的非稳定段**；
- §4.5：相机相对地面的位姿估计在**所有阶段**都有用（例如预处理阶段可剔除地平线以上部分）。

## 15.3 Narote 2017：偏离的两类危险情形 + 若干判据

Narote, Bhujbal, Narote & Dhane, *A Review of Recent Advances in Lane Detection and Departure Warning System*, Pattern Recognition 2017（被引 262）。

**§10 把危险的车道偏离归结为两种情形**：
1. 车辆**过于靠近**车道边界；
2. 车辆的**偏离速度过快**（接近边界太快）。

**这正是"位置项 + 速率项"的二分**——与收敛 1 一致，且给出了它的问题定义来源。

**其他判据（可作为 §1.5 判据池的补充）**：
- **驾驶意图修正**：决策模块可**根据方向指示灯的有无，判断变道是有意还是无意**（与孙铭宽的转向灯修正一致，两篇独立）；
- **对称比值判据** [29,63]：定义左右边界的角度 `θ_l, θ_r` 与距离 `ρ_l, ρ_r`；光轴与车道中心重合时 `θ_l/θ_r ≈ 1` 且 `ρ_l/ρ_r ≈ 1`；偏离时两个比值偏离 1。靠左边界时 `θ_l, ρ_l` 同时减小而 `θ_r, ρ_r` 同时增大。用**回归分析（回归系数 + 残差平方和 SSE）**融合判断，以最小化假边缘检测并确定偏离的起止点；
- **EDF（边缘分布函数）对称轴 + 局部极大值**法 [28]：车辆偏离中心时对称轴位置改变；**但高度依赖标线可见性，在弯道 + 虚线时可能出错**；
- **guard zone（警戒区）** [22]：沿图像 x 轴、车辆中心周围设警戒区；**尺寸选择关键——足够大才能快速响应，太大又会频繁误报**。这是阈值两难的标准表述，与罗强对 CCP 的批评同源。

## 15.4 Wijesoma 2004：LiDAR + EKF 做道路边界的源头

Wijesoma, Kodagoda & Balasuriya, *Road-Boundary Detection and Tracking Using Ladar Sensing*, IEEE T-RA 20(3), 2004（被引 241）。**该 PDF 无文本层**（9 页仅 354 字符水印），本项通过渲染首页为图片读取。

- **动机与你的处境完全一致**：虽然视觉是道路车道检测最常用的模态，但**在光照不良、恶劣天气与复杂驾驶环境下，仅靠视觉提取道路特征极其困难，甚至不可能**；
- **场景前提**：在城市/半城市环境，**两侧路缘定义了道路边界**（对应你的 `paved edge` / kerb）；
- **方法**：基于 **扩展卡尔曼滤波（EKF）**，用 2D ladar 的**连续 range/bearing 读数**做路缘的快速检测与跟踪，提取**直线特征**；
- 宣称相比文献里的毫米波雷达方法**更简单、计算更高效**；作者称这是"文献中首次"将 ladar 用于通过路缘检测确定道路边界；
- **局限**：2D ladar（单扫描面）+ 直线特征模型 → 在不规则几何道路上受模型假设限制。

**它是 Kang 2012（多卡尔曼/IMM）的祖先**——两者都是"路缘 + 卡尔曼"这条线。对你而言它的价值是**谱系确认与动机背书**，方法本身已被 Kang 超越。

## 15.5 ONCE-3DLanes：一条不必学的特性

Yan, Nie, Cai et al., *ONCE-3DLanes: Building Monocular 3D Lane Detection*, CVPR 2022（被引 79）。

- 贡献：最大的真实世界 3D 车道基准 + 新评价指标 + **SALAD**（**extrinsic-free and anchor-free**，端到端单图预测 3D 车道）；
- **自我声明的局限**：数据集构建依赖 LiDAR 提供 3D 信息 → **遮挡会造成短中断，用插值修补**；**远处仍存在缺失点问题，因为 LiDAR 分辨率低**；未来工作聚焦地面点云补全。

**对你的判断**：它的 `extrinsic-free` 是**它没有精确外参时的妥协**，不是优势。**你有精确外参（BeamNG 已知位姿）**，所以这条不必学。它的"LiDAR 分辨率导致远处缺失"反而是一个**对你同样成立**的警示（你的 LiDAR 也有距离分辨率极限）。

## 15.6 Transformer 综述：只有"如何压到可用"这一块与你相关

Chu, Li, Xie & Zhao, *A survey of transformer architectures for autonomous driving*（38 页）。自我定位是补上"架构演进 + **部署挑战**"的系统级综述。

**可用的只有轻量化手段清单**（若将来某个模块必须用 Transformer）：
- **知识蒸馏是核心手段**：DistilBERT **模型尺寸 −40%，保留 >97% 性能**；TinyBERT **小 7.5 倍、快 9.4 倍，保留 96.8% 性能**；
- 稀疏/线性注意力（Performer 的 kernel 级替代 softmax）；
- **Shuffle Transformer**：窗口自注意力 + 空间 shuffle 实现跨窗口通信，**对密集预测任务达到线性复杂度**。

**优先级判断不变**：**你的瓶颈是 ring I/O（300–700 ms），不是注意力复杂度**。这份清单是"如果不得不用"时的逃生手册，不是现在该做的事。§10.2 关于不采用 GNN-Transformer 的结论**不变**。
