## 2. 与上一轮（闭环轮 §9）的关系 + **一处更正**

**更正**：`docs/T16_CLOSED_LOOP_PREREG_20261005.md` §9 表头写"**lane_paired**"
的那一列，实际取的是 `assessed.lane_sensor_rate`（**感知车道来源可用率**），
不是 `lane_paired_rate`（配对率）——逐条比对 7 份记分卡，7/7 与 sensor_rate 精确
相符（例：`town_1791206973` 表列 52%，sensor_rate 0.524，而 paired_rate 是 0.995）。
**§9 的结论方向不变**（v8 可用率更低），但"配对率中位 85.5%→29.5%"这个说法
应更正为"**sensor 来源率**中位 0.775→0.292"。

**两个口径都重算**（同一批 8 份遥测；`town_1791201426` 无记分卡，按同一
`assess_run(goal, settle_s=8.0)` 从遥测重算）：

| 轮次 | paired 中位（范围） | sensor 中位（范围） |
|---|---|---|
| v7（闭环轮 4 次） | **0.890**（0.809–0.986） | **0.851**（0.231–0.975） |
| v8（闭环轮 4 次） | **0.528**（0.130–0.995） | **0.292**（0.097–0.524） |
| v8（本轮验收 4 次，`60e2a5e`） | **0.852**（0.479–0.970） | **0.520**（0.314–0.740） |

读法：① v8 的**两个**可用率都低于 v7（方向不变）；② 但**轮间方差极大**——
同一 v8 配置，sensor 中位 0.292 → 0.520，paired 中位 0.528 → 0.852；
③ **压线/stall 的失败在 12 次 v7+v8 运行里 12/12 出现**（bodyC 4–45，
stall_frac 0.93–1.0）——**这才是稳定的结论**：当前驾驶栈在 town 上
"不爬行"和"车体不压中心线"两条硬门都过不了，与配置无关。

## 3. 判定与后续（按纪律）

1. **限定场景 Tech 驾驶验收：未过门**（0/4）。方案 §5"签收"的第三件因此**不成立**；
   链条停在驾驶层。**不调阈值、不改注册表、不重挑场景**。
2. 失败面已定位到**驾驶层的横向参考与可用率**（不是本次交付的感知线候选：
   该轮用的是注册表固定 `seg_model_hand/best_task.pt`，与 `base6x` 臂无关）。
   具体：感知车道中心有 23–56% 采样落在铺装外 + 停车策略导致 93–100% 帧在爬。
3. **不把这次读数当作"v8 更差"的证据**：本轮只有 v8（生产默认），没有 v7 对照；
   §2 的 v7/v8 对比来自上一轮（且已更正表头）。
4. **安全项**：碰撞 0/出铺装 0 是 4/4 测到的（不是单次 damage=0），但
   **不足以**宣称安全——车体骑中心线本身就是安全相关失败项。
5. 下一步（需计划层定夺，本代理不擅自改默认）：驾驶层的**横向参考质量**
   （感知车道中心 vs 铺装）与**停车/爬行策略**是明确的两个下手点；
   以及"车体压线"是否应作为独立于参考线的控制目标。
