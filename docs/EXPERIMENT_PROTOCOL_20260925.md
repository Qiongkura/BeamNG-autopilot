## 1. 为什么需要协议哈希

同一个指标在不同口径下是两个数。实测教训：`line_precision 0.30` 在
"引擎弱真值（漏标约四成漆线）"与"agent 逐帧核对真值"下分别是 0.30 与 0.65——
差别来自**真值完整性**，不是模型。所以：

* 定义、有效区域、分组、聚合方式、匹配容差、阈值单位、标签版本要求**一起进哈希**；
* 判定文件保存协议快照 + 哈希；旧协议路径消失时**不得**悄悄改用最新阈值；
* 改了口径就是新协议：旧阈值不能未校准直接复用，且**不得为让当前候选过门而调低阈值**。

## 2. 指标字典（定义/单位/分母/未知怎么记）

| 指标 | 层 | 单位 | 分母 | 未知规则 |
| --- | --- | --- | --- | --- |
| `road_iou` | 像素 | ratio | 有效区（label ≠ 255）上的 road TP+FP+FN | 无预测或无有效区 → **UNKNOWN**（不写 0） |
| `line_iou` | 像素 | ratio | 有效区上的 line TP+FP+FN | 无预测标线像素 → UNKNOWN |
| `line_precision` | 像素 | ratio | **有效区内**的预测标线像素 | 无预测 → UNKNOWN |
| `line_recall` | 像素 | ratio | **有效区内**的真值标线像素 | 无真值 → UNKNOWN；必须报**场景覆盖** |
| `offroad_false_ratio` | 像素 | ratio | **有效区内**的预测标线像素（不是全部预测） | 无有效区预测 → UNKNOWN |
| `pred_unknown_line_px` | 像素 | count | —（计数） | 落在未知区的预测：不算成功、不算假线，但**必须上报** |
| `candidate_identity_rate` | 候选 | ratio | 有可用参考的候选（投影匹配，容差冻结） | 无参考的候选记 UNKNOWN，不算漏 |
| `candidate_reference_coverage` | 候选 | ratio | 全部候选 | 无候选 → UNKNOWN；**覆盖率本身要过门** |
| `left_right_role_agreement` | 候选 | ratio | 两侧都有 side 标签的匹配候选 | 缺 side → UNKNOWN |
| `inference_ms_p95` | 性能 | ms | 逐帧总耗时的分位 | 没有一次干净重复 → UNKNOWN（污染值留档不平均） |
| `tick_deadline_miss_ratio` | 控制 | ratio | 该轮全部 tick | 无 Tech 闭环 → UNKNOWN |

补充纪律：

* `inference_ms_p95` 是**离线分割链**（预处理 + 前向 + 后处理）指标，**不能**替代完整
  驾驶 tick deadline（方案 §10.4）；
* `candidate_identity_rate` 当前实现是投影候选匹配率，**不等于**左右车道身份正确——
  必须与 `left_right_role_agreement`、`candidate_reference_coverage` 分开报；
* 每个硬门输入都必须有**实际测量**：缺测记 UNKNOWN 并阻止晋级。

## 3. 覆盖要求（首批人工评价集，方案 §6.3）

| 场景 | 必须包含 | 起步帧数 | 独立组数 |
| --- | --- | --- | --- |
| 清晰漆线 | 左/右边缘、中央线、白/黄线、实/虚线 | 20 | ≥2 |
| 弯道与路口 | 斜线、断线、交汇、不同远近尺度 | 20 | ≥2 |
| 退化与遮挡 | 阴影、磨损、车辆遮挡、亮度变化 | 20 | ≥2 |
| 易混淆纹理 | 路缘石、排水槽、护栏反光、墙面、轮胎印 | 20 | ≥2 |
| 真无线铺装路 | 能确认整片评价区域无线，保留边界信息 | 20 | ≥2 |
| 铺装/土肩与纯土路 | 两种道路类型分别标记，不能混成 road 一类 | 20 | ≥2 |

* 至少 **6 个完整路段组**；关键场景尽量覆盖两个独立组，达不到要**显式记录缺口**；
* 评价主视角 `front_main`；要声明其他相机可用，必须先为该相机建立有效评价覆盖；
* 这些数字是**起步工作量**，不是统计充分性保证；连续相邻帧不算独立样本。

## 4. 标签来源资格（由 rank 派生，**不由命令行字符串决定**）

| rank | 能训练 | 能测量 | **能晋级** | 典型来源 |
| --- | --- | --- | --- | --- |
| `verified` | ✅ | ✅ | ✅ | `human_revision`、经独立验证的模拟器真值 |
| `agent` | ✅ | ✅ | ❌ | agent 逐帧核对式标注（本轮 640 帧） |
| `pseudo` | ✅ | ✅ | ❌ | `engine_annotation_partial`（弱监督） |
| `unreliable` | ❌ | ❌ | ❌ | `engine_annotation`（默认） |
| `absent` | ❌ | ❌ | ❌ | 未知来源 |

**不可旁路**：漏传 `--research-arm`、在命令行写 `human_revision`、混用来源，
都不能让非 verified 数据获得晋级资格；所有入口（`rounds` / `evaluate` / 恢复 / `replay`）
必须走**同一个纯函数**判定资格（方案 §6.1、验收 A1/A8）。

## 5. 空间隔离与最终集访问（W2，进哈希）

**空间缓冲 = 50 m，已冻结**（`SPATIAL_BUFFER_M`）。依据：front 相机在 536×403 下的
可见范围约 40–60 m 路面，取保守值 50 m；**改相机或分辨率必须重标定并升协议版本**。

判据（`experiments/spatial.py`，审计与 `rounds` 共用）：

* 训练帧与开发/评价帧的**平面距离 < 缓冲**即冲突（`violations`），并报
  `n_pairs_checked`、`min_distance_m`、`n_missing_position`（无位姿的帧单独计数，
  **不能**当成"没有冲突"）；
* **同曝光多视角**：同一 `map/source_id` + 同一曝光的不同相机帧必须**同组**，
  跨组即泄漏（`exposure_split`）；
* **同地点重采**：不同 `source_id` 但位置相邻的采集同样受缓冲约束，不因字节不同而放行；
* 缺地图身份的帧进隔离队列，**不从目录名猜地图**（方案 §7.1）。

**最终确认绑定**（`experiments/final_set.py` + `scripts/m5_final_set.py confirm`）：
唯一被允许读最终集的路径是确认程序——先 `access()`（一次即消费，被拒不评估），
再按 `map/source_id` 分场景评估，写出绑定**协议哈希 + 候选 + 权重 sha16 + 最终集
摘要 + 结果 + 未测口径**的确认记录。判定侧 `confirmation_check()` 把两种"没有确认"
分开：**没有记录**只说明 R2 未确认（不推翻研究结论）；**记录对不上**（换协议/换权重/
换最终集）是输入不一致 → `rejected`，并且确认的权重必须就是本轮某个 seed 的
checkpoint（不允许登记"跨 seed 平均成绩"）。

**最终集封存**（`experiments/final_set.py`）：搜索器无读取权限；封存记录绑定
数据集摘要 + 协议哈希 + 候选；`access()` 在**协议不匹配 / 摘要变化 / 未封存 / 已消费 /
用途不符**时一律拒绝，并把每次尝试（含拒绝原因）追加进只增不改的账本
（`final_set_ledger.jsonl`）。**一次确认消耗一次访问**：失败后不得对着同一最终集调参再
宣称独立验证，旧集降为已消费诊断集，新一轮另冻结未使用场景（方案 §7）。

## 5.5 聚合方式：均值不能替 seed/场景过门（v3 新增）

同一批数字在"跨 seed 取均值"与"每个 seed 各自过门"下是两个结论，所以聚合方式
本身进协议哈希（`AGGREGATION`）。规则：

* **硬门三路并查**：总体均值 + **每个 seed** + **每个场景**（`map/source_id` 组）。
  4 个 seed 的 `line_recall` 都 0.9、第 5 个 0.3，均值 0.78 过 0.70，
  但那个 checkpoint 不该部署——逐 seed 检查会把它挡下（A7）；
* **分场景只把已标定的口径当硬门**（像素三项 + 该场景耗时）。候选/身份类指标
  单场景候选数可能只有几个，"每场景至少多少候选才能单独判身份"这条门槛
  **尚未标定**，所以只上报（`per_scene_candidates`）不进硬门；
* **缺测分通道**：坏场景/坏 seed（测了不达标）→ `rejected`；
  没测到 → `needs_evidence`。两者不能混成一个列表（§10.3 判定顺序）；
* **可测候选覆盖率门槛未冻结**（`coverage_gate_frozen: false`）：即使测到了也
  进缺测通道阻止晋级，直到在独立数据上标定出新阈值并写进协议；
* 报告同时保留：均值、宏平均、**最差场景**、**每个 seed**（§10.2）。
* 判定文件落盘 `hard_by_seed` / `per_scene` / `missing_metrics` 原始测量，
  `replay` 读回同一份——"在线判 needs_evidence、重放判 rejected"是不允许的。

## 6. 比较与结论规则

* 保留每个成对差值；不确定度用**明确记录的方法**：**成对差值的双侧 95% t 区间**
  （`df = n-1`，假设差值 iid 近似正态；t 分位用表 `T95_TABLE`，df>30 用正态近似 1.96，
  **不依赖 scipy**），判定文件里写 `ci_method`/`df`，并同时报告
  `ci95_halfwidth_approx_2sd`（旧口径）与原始差值分布；
* **口径变更的影响要如实记**：`2*sd/sqrt(n)` 在小样本下低估区间（n=3 时 t=4.303，
  是它的 2–3.7 倍）。实测例：同一批差值 `[0.10, 0.02, 0.20]` 在旧口径下是
  `candidate_better`，t 区间下是 `inconclusive`——**历史判定是按 v1 口径做的，
  不能与 v2 混比**；
* `seeds_needed_for_effect` 是**保守近似**（乘子取 2，平方 16；严格设计用 7.84），
  报出的 seed 数偏多，方向安全；
* 场景不确定度与 seed 不确定度**分开报**；跨路段重采样时相邻帧不算独立样本；
* 最小有意义收益、非劣余量、方向在实验前冻结；
* 判定顺序：输入不一致/标签污染/生产路径不一致 → `invalid`/`rejected`；
  证据缺失或定义未冻结 → `needs_evidence`；完整测量但硬门失败 → `rejected`；
  任务主指标通过且无明显退化 → `shadow_candidate`；
* **像素 IoU 的 candidate_better 只是研究结论**，不能直接变成模型晋级（方案 §10.3）；
* 在线判定与 `replay` 调用**同一个纯函数**，输入含完整协议、来源资格、测量覆盖、硬门、
  统计方法与 production mismatch；
* **判定文件自带协议快照 + 哈希**（`protocol` 键，阈值取本轮实际解析出来的那份），
  `snapshot_hash()` 能查出快照被手改；`replay` 会区分"按旧协议留档"（提示，
  不与当前口径混比）与"快照与记录哈希不符"（rc=1）；
* 缺测/硬门/逐 seed/分场景的**原始测量**都落盘，`replay` 读回同一份——
  同输入不同决策是不允许的（在线判 `needs_evidence`、重放判 `rejected` 就是 bug）。

## 7. 性能协议

回归门、CPU 重活、训练**不得与计时并发**；固定硬件/输入/预热/同步；
每个 checkpoint **至少 3 次独占测量**，取重复 p95 的较小值进离线门，
保存全部 repeats + min/median/max + 忙闲检测 + 预处理/前向/后处理分解；
完整驾驶另统计全部 tick 的 p50/p95/p99、超时次数/比例/连续超时长度与源年龄。
目标 tick 周期在运行前按实际控制配置冻结。
