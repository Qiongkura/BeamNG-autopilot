# 横向字段契约（P0-2）

来源：`docs/HANDOFF_20260921_round5_REVIEW.md` P0-2。目的：**只看一帧遥测 + 本文件，
就能判断"车相对某条线在哪一侧"**，不再出现报告里 `+0.91 m` 与 `−0.368 m` 那样
看起来互相矛盾、实际是不同帧/不同参考的数字。

机器可读版本在 `beamng_autopilot/telemetry_contract.py::LATERAL_FIELD_SPECS`，
本文件必须与它逐字段一致（`tests/test_lateral_contract.py` 会检查）。

## 统一格式

```text
字段 = reference + frame + sign + unit + coverage
```

- **reference**：被测量的参照物（车 / 路线 / 标线 / 车道中心）
- **frame**：坐标架（车体、路线、或"无量纲幅值"）
- **sign**：正负方向。`+ = 左侧` 是本项目的统一约定，凡是有符号的横向量都遵守
- **unit**：米
- **zero / none**：`0` 与"没测量"的区别写清楚；**缺列一律 `None`/UNKNOWN，不写 0**

## 字段表

| 字段 | reference | frame | sign | zero 的含义 | none 的含义 |
| --- | --- | --- | --- | --- | --- |
| `line_lat` | 语义标线掩码反投影到世界的**所有**标线（25 m 内取**均值**） | 车体 | **+ = 标线在车左侧**（即车在标线右侧） | 标线正穿过车中心 | 本帧没有标线被投影出来——**不是"居中"** |
| `ego_lat_route_m` | 导航路线折线（道路中线，**仅作度量**） | 路线 | + = 车在路线前进方向的**左侧** | 车压在路线中线上 | 没有导航路线 |
| `lat_route_m` | 导航路线（仅作度量） | 路线 | + = 左侧 | 该点落在路线中线上 | 无路线／点无法投影 |
| `lat_car_m` | 车自身中心线 | 车体 | + = 车头方向的左侧 | 该点在车中心旁边 | 该点距车 >25 m |
| `lane_side_off_m` | 导航路线（只作"路中心"度量，用作 SIDE 门控，**从不做横向设定值**） | 路线 | **+ = 感知车道中心在路线左侧** | 车道中心压在路中线上（strict 下被拒，限值 −0.2 m） | 车道中心与路线无可测重叠 |
| `lane_dev_m` | 已接受的横向参考（感知车道） | **无量纲幅值** | **无符号**：规划路径到参考的中位**绝对**距离 | 路径与参考重合 | **没有横向参考**——旧实现这里返回 `0.0`，会被读成"完美对齐" |
| `lat_left` | 本帧发布的**左**边界 | 车体（**车辆中心点**） | **+ = 车心越过左边界、偏向对向车道** | 车心正好在边界上 | 未发布该边界 → **UNKNOWN，绝不等于"在路面内"** |
| `lat_right` | 本帧发布的**右**边界 | 车体（**车辆中心点**） | **− = 车心越过右边界、偏向路面外** | 车心正好在边界上 | 同 `lat_left` |
| `body_lat_left` / `body_lat_right` | 同上，取**四角中最差** | 车体（四角） | 同 `lat_left` / `lat_right` | 车角正好在边界上 | 同左 |
| `road_off` | 感知到的车道边界 | 车体（四角） | ≥0：越界宽度（幅值） | **两种含义**：车身在边界内 **或** 本帧没测到边界——**单看此字段无法区分**；先读 `lat_left/lat_right` | 不会为 None；用 `lat_left/lat_right` 区分"在界内"与"没测" |
| `edge_over` | 地图 DecalRoad 边缘折线（**只作度量**，永不作为横向控制输入） | 车体 | ≥0：越出道路自身边缘的米数 | 车在两缘之间 | 无路线／无地图边缘 |

> **2026-09-22 更正（T01）**：`lat_left/lat_right` 的生产者用**车辆中心点**投影到边界
> （`fsd_drive.py` 的 `_boundary_lateral(pos, ...)`），四角最差是 `body_lat_left/right`。
> 早期版本把两者都写成"四角"，会让读者把一个 0 读成"车身没越界"，而中心点 0
> 只说明车心在边界上。
>
> **停车口径（T01）**：`stop_digest.by_reason[*].s` / `active_s` 是该原因**存在**的
> 秒数（车可能仍在行驶），**不是**停车秒数；按原因分的停车秒数读
> `by_reason[*].stop_s` / `stop_longest_s`。同一跑次实测：`no_drivable_path`
> 存在 25.89 s，其中真停车 22.92 s（最长连续停车 9.54 s）。

## 覆盖条件（报告必须分开统计）

- `lat_left` / `lat_right` / `body_lat_*`：**只有双侧配对边界发布时才有值**。
  单侧镜像、分隔线回退、融合走廊都不发布 → 这些帧的压线**是 UNKNOWN**。
- `line_lat`：只要有标线被投影就有值；多条标线时是均值，**不代表某一条具体线**。
- `lane_dev_m`：需要同时有参考和路径。
- `edge_over`：需要导航路线与两侧地图边缘。

## 一帧实例（2026-09-21 现场探针，车正压在中线上）

```text
ego_lat_route_m = 0.00    # 车压在路线（道路中线）上
lat_route_m     = +0.91   # 检出的一条长实线在路线左侧 0.91 m ≈ 车宽一半(0.9)
                          #   => 车的左轮正压在这条线上
lane_side_off_m = -2.90   # 感知车道中心在路线右侧 2.9 m（本车道）
lane_from       = None    # 本帧参考来自单侧镜像（paired=0），非分隔线回退
lane_dev_m      = None    # 无参考可测（本帧为 perception-unavailable）
lat_left/right  = None    # 未发布双侧边界 => 压线为 UNKNOWN，不能写 0
```

读法：`lat_route_m = +0.91` 说明**线在车左**；若它是分隔线，则车正在线上的判断成立。
注意 `line_lat` 与 `lat_route_m` 是两个不同的量（前者是车体系、对多条标线取均值；
后者是路线系、单条标线），**不要跨字段比较大小**。

## 与历史报告数字的关系

- 报告中的"实线 +0.91 m"＝本表 `lat_route_m`（**路线系**，单条线）。
- 探针早期日志中的"0.368 m（车体系 −0.368 即线上）"＝同一类量的另一次采集（**不同帧**、且那时是**车体系** `lat_car_m`）。
  两者不矛盾，属于不同帧 + 不同坐标架；本契约要求报告引用时**必须写明字段名与坐标架**。
