## 3b. 集合口径（**实测发现，必须预注册**）：用**去重后的 9 个场景**

`reviewed_full/` 下有 9 对重复目录（`pkg_X` 与 `pkg_pkg_X` 内容同源）。同一臂、
同一 seed、同一口径，只换集合：

| dev 集合 | 精度（6 seed） | 召回（6 seed） | 召回均值 | 召回门 |
|---|---|---|---|---|
| 18 目录（含重复） | 0.5495–0.6692 | 0.6106–0.7663 | **0.6925** | ✗（3/6 跌破） |
| **去重 9 场景** | 0.5470–0.6725 | 0.6323–0.8053 | **0.7360** | ✓（2/6 跌破） |

→ 重复目录**双计**了难场景（城镇/土路），足以把召回均值从过门压到不过门。
**R2 判定必须写清集合**；本文件预注册 **去重 9 场景**（`pkg_*` 那 9 个目录）作为
R2 的 dev 集合，重复目录只作诊断。

## 3d. 两分支合看：**dev 上失败的门只是"换了哪一边"**（本轮最重要的结论）

| 门 | B/C（v7） | A（v8） |
|---|---|---|
| 覆盖率 | 0.9523 ✓ | 0.9560 ✓ |
| 身份率 | 0.4335 ✗ | 0.6650 ✓ |
| 精度 | 0.6098 ✓ | 0.8942 ✓ |
| 召回 | 0.7360 ✓（2/6 跌破） | **0.5593 ✗（6/6）** |
| 角色 | 0.8656 ✓ | 0.8830 ✓ |

两边都是 **4/5**，失败的门分别是：
- v7：身份率（候选落在**非漆**线状结构上 → 与"人工标签=线"不一致）；
- v8：召回（外观门把线定义成**漆** → dev 标签里 29% 的非漆线像素被删）。

→ 这不是"哪个模型更好"，而是 **dev 人工标签与自动真值认证口径（只认漆）对"线"
的定义分歧**；每种口径各自暴露分歧的一边。**在同一套 dev 标签上五门不可能同时
全过**，除非：
① 接受其中一个门作为"定义性约束"（v7：身份率；v8：召回），并在判定文件里写明；
② 或重标 dev（违反零标注约束）；
③ 或把两套口径**并列报告**（每套在**自己定义内**判五门 + 交叉报分歧率）。

**给计划层的补充建议（新增选项 E）**：R2 用"**声明定义 + 定义内五门**"的口径——
v8 定义下在 R3 认证类上五门全过（已测），dev 上按 v8 定义报四门 + 召回按
"漆像素召回"另立一门（真值取标签 ∩ 像漆）；v7 定义下 dev 四门 + 身份率按约束报。
这样两条定义都不需要"假装"另一边的标签是对的，分歧率（dev 29%）作为已知量随行。

## 4. 两个分支共同的纪律（现在就冻结）

1. **最终集封存**：最终集在 R2 通过前不得被任何实验消费；确认只消费一次
   （协议原文：同一候选决策批次只消费一次，不把失败反馈继续用于调参）。
2. **判定文件按协议版本分开存**，不互相覆盖（v7 的历史判定保持 v7 标注）。
3. **不放宽任何门**；缺测记 UNKNOWN，不用单次结果证明安全。
4. R2 判定必须附：五门逐 seed + 均值、逐场景明细、协议版本、checkpoint sha、
   集合清单（目录 + 帧数 + 来源）。
5. R2 通过后才允许进入最终确认与 Tech 驾驶；R2 未过时**不得**用最终集试参数。

## 5. 裁决后的执行顺序（两分支通用）

1. 按裁决确认口径（A：切 `BEAMNG_PROTOCOL=v8`；B/C：保持 v7）；
2. 跑 §2/§3 的 R2 判定（6 seed、两套集合、逐场景明细）；
3. 写 R2 判定文件 + 方案追加节（含代价与未验证项）；
4. R2 过门 → 排期最终集独立确认（一次性）与 Tech 驾驶验证；
5. 规划侧闭环行为验证（A 分支必做，B/C 分支作为可选补测）单独一轮。
