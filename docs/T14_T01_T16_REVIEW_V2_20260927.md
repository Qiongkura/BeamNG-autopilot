## 5. 残余缺口清单（按严重度）

1. **refusal 在评价链里不可见（T09/T11，中）**：探针的结构化 refusal（无 `summary`，例如
   整 run 缺相机）经 `identity_metrics` 后 `eval_run_errors` 仍为空、`counts` 被写成全 0，
   而判定文件注释与看板把"空 `eval_run_errors`"当作"每个 run 都测到了"。复现：命令 15。
   建议：refusal 也进 `run_errors`（带 reason），或把 `counts` 在无任何实测时写 `{}`
   并让 `_is_count_blob` 拒收全 0。
2. **看板 negative_line 形状不匹配（T16，中）**：生产端 `{baseline,candidate}` vs 消费端
   扁平读取；真实 E1 页面把实测数据渲染成"无数据"（复现：命令 23）。测试夹具形状与生产
   不一致，属"测试通过但抓不到真实缺陷"。
3. **`decide()` 多问题并存时 reasons 不列缺测类（T08，低）**：blob 里
   `missing_metrics/hard_gate_violations` 都在，但 `decision.reasons` 只留优先级最高的
   一类（复现：命令 18）。
4. **`evaluate` 与计数契约脱节（T12，中）**：evaluate 不计算任何计数、无仓库内 pairings
   生成器；它新写的判定立刻被 `legacy_replay_note` 判为"早于 v5、不可重判"（复现：命令 18）。
5. **协议快照自检对旧 schema 误报篡改（T13，低-中）**：54 个合法 v3 记录被打印为
   "判定文件被改过？"并使 replay 返回 rc=1（复现：命令 21、25）。应把"字段集不同"
   与"同一字段集内容不符"分开报告。
6. **`scene_counts` 与 `counts` 的口径差未在文件里注明（T06/T12，低）**：E2 v3 里
   `counts`=最后一个 seed（C=327），`scene_counts`=3 seed 汇总（C=1040）；逐 seed 整数
   计数不落盘，逐 seed 门只能靠比率重读。若这是有意设计（"一个场景在整轮评价里累计
   够 30 条参考"），建议在判定文件里写明单位，避免读者把两个数当同一分母。
7. **recall=0 无专项测试（T09，低）**：行为正确（执行确认），但没有测试会在它被改成
   None 时报警。
8. **看板不显示 `eval_run_errors`（T11/T16，低）**：判定文件已写，页面没有这一格。
