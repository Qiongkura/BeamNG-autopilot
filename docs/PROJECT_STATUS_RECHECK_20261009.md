## 3. 本轮重新确认的优先问题

### P0：放置阶段的超时与异常处理

`beamng_autopilot/fsd_drive.py`：

- `_prewarm_and_place()` 在第 2178 行调用 `_wall_hit()`；该名称是另一个方法 `run()` 第 2247 行的局部变量，没有传入放置方法。
- 第 2181 行超时分支返回整数 `3`，而第 2373–2375 行调用方解包三项返回值。
- 第 2238–2240 行捕获异常后，方法返回第三项为 `0`，可能将放置异常作为非终止结果传回。

建议显式传入截止时间或检查函数，统一三元组返回契约，strict 放置异常返回失败并完成制动与收尾。使用假连接和注入时钟实际执行正常、超时、异常分支，再进行 Tech 验证。

**证据链 B**：原假设：内部超时已在放置阶段生效 → 是否激活：入口与放置方法均有检查，但作用域未接通 → 可复现输入：上述方法与调用方 → 实测结果：本轮静态复核确认名称不可达、返回契约不一致、异常落入非终止返回 → 结论：该修复尚未完成 → 未知与下一步：本轮未动态触发；先用确定性例子验证，再补有效驾驶实验。

### P1：后台入口缺少新训练配方字段

`beamng_autopilot/experiments/controller.py` 的 `LoopConfig` 没有 `total_steps`、`init` 字段；`load()` 会过滤未知配置键。`scripts/m5_seg_autoloop.py` 的 `rounds_args_from()` 也未向参数对象传递这两个值，而手工 `rounds` 与 `train_cmd()` 已支持它们。

这不意味着后台完全不能训练；它意味着把这两个参数写进后台配置，当前不会形成预期的训练预算或初始化命令。

建议补齐配置、配置哈希和参数转换；未知键应显式报错。验收必须追到实际训练命令、优化步数、初始权重哈希、样本利用记录与 checkpoint，不能只验证配置文件保存成功。

**证据链 C**：原假设：后台入口与手工训练具有同一预算及初始化契约 → 是否激活：训练器已实现，后台配置与转换层缺字段 → 可复现输入：`LoopConfig.load()` → `rounds_args_from()` → `train_cmd()` → 实测结果：本轮重新读取确认中间两层未传递参数 → 结论：无人值守学习链尚未接齐 → 未知与下一步：本轮未发起训练；修复后先核对命令，再做小预算真实训练。

### P0：位姿运行器缺少进程归属与输出资格检查

`scripts/m5_pose_sweep.sh` 的 `cleanup_games()` 对 `game_pids()` 返回的每个 PID 强制终止，没有启动前差集或进程归属校验。注释与实现不一致，可能终止用户已有的游戏会话。该入口也未遵循项目 PowerShell 7 约定。

运行器以输出文件存在判成功，未验证配置摘要、测量时长、放置状态与退出码。点名山路日志 `logs/experiments/_e5_mountain.log` 最后更新时间仍为 10 月 7 日 17:12，结尾反复出现解释器路径不存在；这是启动入口失败的记录，不能计作山路驾驶结果。

建议迁移为可复用 PowerShell 入口，采用项目已有的进程归属与收尾组件；只终止本轮所有的进程。输出准入检查应读取 manifest、实际起始位姿、阶段时长、退出原因与配置摘要。

**证据链 D**：原假设：无人值守运行器只清自己的实例，九份输出等于九次有效实验 → 是否激活：清理和文件计数代码确实执行于运行链 → 可复现输入：`m5_pose_sweep.sh`、E5 结果表、点名山路日志 → 实测结果：源码缺归属检查；报告时长不齐；日志为入口失败 → 结论：上述两个成功条件不成立 → 未知与下一步：本轮未执行运行器或终止进程；先补合同与资格检查，再补无效项。

## 4. 建议的下一阶段顺序

1. **先恢复实验可信性。** 修超时、返回契约、异常失败处理与进程归属；无效输出保留但不得算通过。每个实验明确记录请求位姿、实际放置位姿和有效测量时长。
2. **接通后台训练配置。** 复用现有控制器与 `rounds`，把预算、初始化、采样及恢复状态传到真实训练器，记录完整谱系。
3. **修感知到横向控制的链。** 将“没有可信车道所以没有路径”与“路径存在但铺装、障碍或车体扫掠拒绝”分别定位。用感知标线、实测边界和车体范围验证正反例；保持 strict 不倒车、不压线，不新增导航线加固定偏移。
4. **扩大无需人工标注的合格数据。** 优先 Tech annotation；先自动检查类覆盖、RGB/annotation 对齐、相机身份和场景资格，再入训练池。真值不完整的场景隔离或仅作研究臂；相邻帧和重复内容不得泄漏到评测集。
5. **形成可观察的自主循环。** 采集 → 资格审计 → 困难样本选择 → 定预算训练 → 同协议成对评测 → 晋级或拒绝 → 记录原因与恢复状态。看板显示每阶段真实进度、数据变化、权重变化和拒绝原因；loss 下降不能单独触发晋级。
6. **以驾驶效果验收。** 感知改善后再进行具有导航目标、唯一控制者的 Tech 闭环。独立最终集已消费，不反复用它选配方；需要新的独立确认时另外冻结合格数据。

上述顺序优先打通可验证的学习和控制链。当前尚无充分依据为完整修复承诺固定小时数，尤其真实游戏放置与横向感知仍需受控复测。

**证据链 E**：原假设：增加训练轮次就能解决当前停滞 → 是否激活：已有训练和评测，但正式驾驶采用固定模型，且失败还涉及放置与横向参考 → 可复现输入：正式验收报告、后台调用链和 E5 运行器 → 实测结果：训练参数接线与实验资格问题均存在，驾驶失败尚未被单一模型指标解释 → 结论：应先打通与核验上述链路，再扩大训练预算 → 未知与下一步：具体收益需靠修复后的成对评测和有效闭环证明。
