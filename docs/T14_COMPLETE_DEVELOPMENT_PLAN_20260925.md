## 1. 要交付什么

交付一个能在本机后台工作的感知学习系统：从 BeamNG.tech 采集新的场景，审计身份与标签，选择值得学习的样本，训练 SegUNet 候选模型，在固定评价体系中比较并淘汰候选，保存可重放证据，在看板展示学习过程。标签、指标、资源或驾驶约束不满足时，系统应明确暂停或拒绝候选。

最终应能回答五个问题：这轮学了哪些新数据；神经网络权重是否真实改变；在哪些场景变好或变差；为什么候选被保留或淘汰；经过哪些证据才允许进入 Tech 影子验证和驾驶测试。

验收分为三个结果，分别签收：

| 结果 | 必须具备的证据 | 不能据此声称的能力 |
| --- | --- | --- |
| R1 后台研究循环可用 | 采集、审计、训练、评估、判定、恢复、自停和可视化实际联通 | 模型已经适合驾驶 |
| R2 离线感知候选合格 | 独立有效标签、分场景任务指标、完整硬门、冻结最终集确认 | 已满足实时驾驶与安全约束 |
| R3 Tech 驾驶候选合格 | 感知进入最终控制、控制权唯一、完整 tick deadline、驾驶约束实测 | 无限制场景泛化或长期安全保证 |

R1 可以在研究标签上运行；R2 的晋级评价必须使用经过验证的独立标签。没有正收益时，R1 仍可能验收通过，R2/R3 保持未达成，禁止为交付“一个好模型”放松门槛。

## 3. 授权、运行范围与硬约束

已有记录明确允许无人值守启动 Tech 采集，且取消每日 120 分钟 GPU 上限。工作配置保持 `daily_gpu_minutes <= 0` 表示不设每日上限，同时保留机器级用量记录。不得因为新方案重复要求相同授权或偷偷恢复旧的每日上限。

单次任务的最长时长、资源不足暂停、连续无收益停止，属于可配置的运行保护；在配置中明确显示。未配置真实用户活动信号时，看板必须显示“未接入”，不能声称已经实现随用随停。

生产权重切换仍走人工确认；先把模型、评价报告、回滚方案做完整，再提交这一步。研究与影子候选不能自动获得车辆控制权。无人值守采集使用独占的任务会话，不能附着并接管用户正在使用的游戏。

以下约束贯穿所有工作包：

1. Tech 为开发与新数据来源；Steam 只保持兼容，不新增优化任务。
2. 横向参考必须来自感知。禁止导航/地图线加固定偏移，禁止丢感知后拿导航线兜底。
3. 右边界优先使用漆线，其次为真实感知的铺装边界、护墙、围栏。无法确认时停车。
4. 有铺装时土肩不能算道路；纯土路的判断需要铺装占比及其有效覆盖证据，不能由单个全局布尔值或地图名字代替。
5. strict FSD 不倒车、不主动压线；现有车身压线收敛机制按原约束验证。
6. Tech 驾驶演示必须带 `--goal X Y`，并验证 sensor/strict 配置真正生效。
7. GUI/autopilot 控制继续使用 `ControlBridge`，实时驾驶遥测使用现有 `live.json`；学习看板保持只读，复用实验事件。

## 4. 架构与数据流

Tech 场景队列 → RGB/annotation/位姿/相机身份 → 不可变原始采集版本 → 标签提议与复核队列 → 逐类别有效性审计 → 训练/开发/最终集清单 → 单因子实验提议 → 成对 seed 训练 → 像素/候选/几何/性能评价 → 判定与重放 → 研究候选或影子候选 → Tech 验证 → 人工审阅部署。

各阶段同时向现有事件系统写入事实，看板按同一 experiment/candidate/dataset ID 关联。训练器负责反向传播和检查点；控制器负责任务状态与资源协调；评价器负责测量；判定器只消费测量与冻结协议。

| 能力 | 优先复用 | 本阶段主要补充 |
| --- | --- | --- |
| 后台状态与资源 | `beamng_autopilot/experiments/controller.py`、`collection.py`、`events.py`、`checkpoint.py` | 跨 run 互斥、停止条件接线、可恢复的分阶段调度 |
| 标签与数据版本 | `experiments/labels.py`、`manifest.py`；`scripts/m5_seg_dataset_audit.py` | 逐帧复核凭证、空间分组、来源不可被命令行随意提升 |
| 标签编辑与提议 | `m5_line_truth_agent.py`、`m5_annotate_manual.py`、`m5_annotate_package.py` | 复核完整性、弱标签负例屏蔽、多场景任务包 |

## 6. 工作包 W1：让标签来源与复核覆盖可验证

预计：1–2 个开发日；人工复核时间单独估算。缺少人工复核时研究臂可继续，晋级评价暂停。

### 6.1 标签质量不再由一个字符串决定

保留 `engine_annotation_partial`、`agent_revision`、`human_revision`、`engine_verified` 来源。增加独立的复核状态与适用范围，至少包括：生成器版本、原帧/原标签哈希、复核人或 agent 身份、复核时间、逐类别完整性、有效区域、修改量、未解决问题。

人工只确认实际看过并保存的帧/区域；不能将一个目录整体改名为 human_revision。用户同意使用 agent 数据，只能记录为“允许研究使用”，不能改变数据的生成来源。经独立验证的模拟器真值也可以用于晋级，但必须保存其对齐、可见性、遮挡和标签完整性验证证据。

`--paint-source` 可声明来源或选择研究模式，但不得越过逐帧凭证抬高质量。删除/漏传 `--research-arm` 不能让使用 agent 或弱标签作为评价参考的研究运行获得晋级资格。所有入口，包括直接 `rounds`、`evaluate` 和恢复路径，都必须遵循相同规则。

训练来源与评价资格分别记录：训练可以使用通过准入的弱监督数据，研究评价仍禁止晋级。同一个冻结 checkpoint 后续可以在新的独立 verified 确认协议下重新申请评价；必须通过可信开发评价、任务硬门和独立最终集，保留原训练来源与旧研究判定，不能靠改来源字符串或取消 flag 升格。这样后台可继续利用自动采集和弱标注，人工工作集中在有价值的训练修订及独立评价集。

### 6.2 部分标签的训练语义

“可以训练”不等于“所有未标像素都是背景”。对弱引擎标签与 agent 提议，保留确认过的标线正例；未覆盖、低置信或未复核区域不得制造标线负例。

复用现有通道屏蔽与 ignore 机制，检查 CE、Tversky、clDice 等实际启用的每一项损失和所有指标。需要区域级有效掩码时再扩展数据契约。有效路面监督与缺失标线监督必须能共存：不能因为 road 标签覆盖了漏标漆线，就把该处作为“确定不是漆线”参与训练。

必须有确定性测试：同一帧某区域改为 UNKNOWN 后，该区域不贡献对应监督；弱标签未标区域不提供错误负例；所有 ignore 帧不产生 NaN；已确认的无线帧可以合法贡献负例；没有复核的零标线帧不能被误认成无线。

### 6.3 建立第一批人工评价集

先建设一个可负担、可逐帧核查的工程验收集。以下数量是起步工作量，不是统计充分性保证：

| 场景 | 首批建议有效帧 | 必须包含 |
| --- | --- | --- |
| 清晰漆线 | 20 | 左/右边缘、中央线、白/黄线、实/虚线 |
| 弯道与路口 | 20 | 斜线、断线、交汇、不同远近尺度 |
| 退化与遮挡 | 20 | 阴影、磨损、车辆遮挡、亮度变化 |
| 易混淆纹理 | 20 | 路缘石、排水槽、护栏反光、墙面、轮胎印 |
| 真无线铺装路 | 20 | 能确认整片评价区域无线，保留边界信息 |
| 铺装/土肩及纯土路 | 20 | 两种道路类型分别标记，不能混成 road 一类就结束 |

选择至少 6 个完整路段组，避免把连续相邻帧当独立样本；每个关键场景尽量覆盖两个独立组，达不到就显式记录缺口。先用 20 帧混合包计时和统一标注规则，再估算余量，禁止承诺“十分钟审核全部 640 帧”。

初始评价主视角为 front_main；要声明其他相机可用，必须为相应相机增加有效评价覆盖。32 帧旧包与640帧扩标池是候选来源，不能直接作为通过证明。高价值训练错误帧和代表性评价帧分别选样，防止评价集只含“最容易找到漆线”的帧。

人工编辑输出到新数据版本目录。确认编辑器优先加载已有提议标签，不能因指定 prefill 模型而悄悄覆盖已修订标签；保留输入/输出哈希和审阅差异。

验收：能查询任意帧是谁、何时、对哪些类别和区域做了复核；640 生成帧、实际训练帧、有效评价帧、人工确认帧四个计数分别可查；未经核验的来源不能进入晋级门。

## 7. 工作包 W2：不可变数据版本与自动选样

预计：0.5–1 个开发日，可与标签复核交错进行。

1. 每帧记录地图及来源、session/source_id、时间/曝光、相机角色、标定、位姿、分辨率、RGB/annotation/label 哈希与逐类质量。缺失身份进入隔离队列，不从目录名猜地图。
2. 数据集版本由内容、标签、来源、质量标记、划分清单共同确定；标注修订必须产生新版本。旧实验继续指向旧哈希。
3. 按空间路段和采集组隔离训练/开发/最终集。相邻位置的重复采集即使 source_id 不同，也不能绕过隔离；同曝光多视角必须同组。空间缓冲依据相机可见范围制定并冻结，不能仅检查字节重复。
4. 现有已分析的 T13/T14 数据作为训练或开发诊断数据。新的最终集单独封存，搜索器无读取权限；冻结候选后才允许一次确认。
5. 选样评分结合场景缺口、未知程度、模型分歧和已验证的任务错误。无真值区域只能进入复核队列，不能自动当 hard negative。
6. 限制同一地点连续帧和同一相机的占比；保留无线负例、左右侧、铺装/土肩等覆盖。每次只增加预设小批场景，经审计后才训练。
7. 对已有 640 帧先审计、去重、按质量分层，再做增量训练对照；“有 8 视角”不等于“8 路同步融合已经实现”。

验收：复制帧、同曝光不同相机、同地点重采和缺地图来源都有拒绝/隔离反例；新增数据确实改变训练输入；报告每 epoch 使用的唯一样本数、重复采样次数和实际优化步数。

最终集必须有访问与消费记录，绑定协议、候选、调用方和结果；只允许最终确认程序读取。失败后不得对着同一最终集调参再宣称独立验证；旧集降为已消费诊断集，新一轮另冻结未使用场景。

## 8. 工作包 W3：连续后台调度、资源互斥与恢复

预计：1–2 个开发日。保留现有 `run`/`rounds`，优先把缺口补进同一套调用链。

### 8.1 一轮必须按以下顺序执行

1. 只读加载明确存在且通过 schema 校验的配置，验证路径和数据身份，发现上次未结束状态；此时不结算、不清理、不改写恢复状态。
2. 取得机器/GPU 级学习资源租约和 run 内写锁，再原子结算、恢复或清理；游戏采集另取得控制权租约。统一锁顺序，避免不同入口死锁。
3. 检查用户暂停、空闲窗口、资源余量、单轮墙钟、候选数、连续无收益次数及可选每日上限。
4. 有采集需求时运行 Tech 采集，审计后形成新版本；无可用新数据时记录原因，避免重复采相同起点。
5. 产生一个可解释的因子提议；无提议/标签不足时进入 waiting/needs_review，并释放重型资源。
6. 审计两臂输入，训练独立基线与候选，逐阶段保存检查点和事件。
7. 做质量评价；独占执行受控时延测量；根据证据判定并写盘。
8. 重放判定，更新研究候选登记、资源账本和失败样本队列；决定下一轮、暂停或正常结束。

停止条件必须在采集前、训练前、每个 seed/epoch 的可恢复边界和下一轮前检查。日志打印 stop=true 不能代替实际停止。持续运行以明确的候选/时长边界结束，不能无条件 while 循环。

### 8.2 资源保护与游戏所有权

| 场景 | 规定行为 | 验收方式 |
| --- | --- | --- |
| 两个不同 run 同时启动 | 同一 GPU 上只允许一个重型实验持有租约，另一个排队或暂停 | 不同 run-id 的双进程竞争测试 |
| 用户已运行 Tech/Steam | 不附着、不传送、不重置车辆；采集暂停 | 预先存在的会话/PID 保持不变 |
| 用户在使用 GPU 游戏/重型软件 | 依据实际信号暂停或降为等待；不能用写死的 user_active=false 冒充检测 | 记录原始检测值和状态变更 |
| 执行 pytest/offline 回归 | 与训练、计时顺序运行；计时取得独占资格 | 时延记录中无重型回归并发 |
| OOM | 保存失败；允许一次受控重试。改变 batch 等配方必须产生新 ID，并重新建立公平对照 | 不无限重启、不混写原候选 |
| 停止/中断/超时 | 合作式停止，保存可恢复状态，回收本任务子进程 | 无孤儿 trainer/collector；用户进程保持运行 |
| 关闭采集器启动的游戏 | 优先正常关闭，必要时仅结束拥有明确归属的进程 | 用 PID、创建时间、父子关系或任务句柄验证，不仅凭名称 |
| 断电/崩溃后恢复 | 识别过期租约，校验检查点与输入哈希，结算未记账时间 | 已完成 seed 不重复训练，事件和判定不重复 |

采集可继续使用当前授权；常驻入口由项目自有调度器或 Windows 任务计划程序唤起同一入口。任务计划程序只负责启动，互斥和恢复由库负责。新增启动/安装脚本放 `scripts/`，不能依赖 `.workbuddy-ai/` 中的临时脚本。

配置须明确列出：当前每日上限=不限制、单次最长时长、连续无收益上限、用户活动信号来源、窗口、显存/磁盘余量、采集范围、训练数据、开发集、种子、阈值版本。配置未知字段和不存在的配置文件必须报错，避免拼错后悄悄使用默认值。

机器账本在资源租约内原子更新，并按日期分摊。记录“已确认占用墙钟”和“无法确认时段”；崩溃到次日重启之间的整段时间不能直接认定为 GPU 使用。日上限为 0 时继续记账但不因日累计暂停；用户未来启用日上限后，采集前和每 seed 边界均须生效。显存/温度传感器缺失时显示 UNKNOWN，只执行有实际信号支持的策略。

验收分三步：离线假训练器完成故障矩阵；真实 2 轮研究实验完成一次自动淘汰与一次恢复；受监督观察通过后做 8 小时持续运行验收。8 小时是运行稳定性目标，不要求每一分钟都训练，也不保证获得正收益。

## 9. 工作包 W4：可解释的神经网络实验

预计：1 个开发日加训练时间；前置为可信训练语义与固定评价口径。

### 9.1 训练契约

先保持 SegUNet 单帧结构，默认 width=1.0；现有 width=2.0 仅保留对照能力。固定生产后处理，研究时改变一个因子。用同一初始权重/初始化规则和成对 seed、相同划分、增强、优化器与评价路径。

数据配比实验保持每轮采样预算和总优化步数一致，并记录各组被抽到的比例；若实验目的是“训练更久”，步数就是被改变的因子，明确报告 120→240 等变化，不能同时称它为等步数实验。固定截取少量帧和轮换采样全量帧回答不同问题，必须写清。

每次候选记录训练/评价标签版本、架构参数、初值/最终权重哈希、每 seed checkpoint、optimizer/AMP/RNG 状态、epoch/step、实际输入清单与训练曲线。检查点选择口径在实验前固定；当前 last 可继续作为起点，后续调整必须出新协议，不能看完结果临时改 best/last。

### 9.2 实验顺序

| 实验 | 改变的唯一因子 | 主要问题 | 停止/晋级依据 |
| --- | --- | --- | --- |
| E0 重建可信基线 | 不改配方 | 独立标签下错误究竟是什么 | 分场景、逐 seed 的完整基线，不宣布优化收益 |
| E1 复验 Tversky 2.0 | line Tversky 权重 | +0.079 的方向能否在独立评价集复现 | 任务硬门不劣；IoU 改善不能覆盖身份/假线失败 |
| E2 扩展有效训练场景 | 数据组或采样配比之一 | 新路段能否减少场景差距 | 等步数、记录唯一样本覆盖和最差场景变化 |
| E3 有证据的困难负例 | 困难样本采样比例 | 路缘石/阴影/反光假线能否减少 | precision/offroad 改善同时检查 recall，防止全不画线 |
| E4 多视角混合训练 | 加入通过审核的相机样本 | 共用同一单帧模型能否学习更多尺度/视角 | 每视角评价与 front_main 非劣；不得称为融合 |
| E5 时序或多视角融合 PoC | 一种输入/结构变化 | 前述改进后残余错误是否有时序/几何依据 | 进入后续独立方案，先离线回放，再考虑驾驶 |

E0–E3 优先。不要同时改数据、损失、宽度和训练预算。研究搜索允许 3 seed 预筛，确认实验建议预先登记 5 个 seed；实际晋级仍受冻结协议最小数与所有硬门约束。“估算需要 2 seed”不自动降低确认实验的 seed 数。

### 9.3 自动迭代应如何选择下一步

错误有可信标签且集中在某类场景 → 提议该组数据/采样因子；标签不完整 → 输出复核任务；当前配方仍明显未收敛 → 提议预算因子；资源不足 → 暂停；连续无收益达到配置上限 → 汇报并结束。

自动提议器首期限定在已经实现的键和预先登记的取值范围内，不自动修改训练源码、不任意调整安全阈值。没有可执行提议时停下，不能退化成换 run-id 重复同一训练。

## 10. 工作包 W5：指标、统计和晋级门

预计：1–2 个开发日。这一包与 W1 同为优先任务。

### 10.1 四层指标与 UNKNOWN

| 层 | 指标 | 有效证据要求 |
| --- | --- | --- |
| 像素 | road/line IoU、precision、recall；左右/近远区域结果 | 同版本标签，逐类别/区域 known mask；分子分母可查 |
| 候选 | 漆线候选匹配率、左右身份、路外候选、漏检/重复候选 | 实际生产候选提取结果与有身份标记的独立参考；匹配容差冻结 |
| 几何 | 本车道边界、车身与线关系、米制偏差、可执行走廊 | 独立几何参考、标定和可见性有效；缺失则 UNKNOWN |
| 控制/性能 | 新源消费、最终命令、tick deadline、停车原因、越界与碰撞 | Tech 遥测与独立检测，同步到同一 tick/模型版本 |

本次已核实 `candidate_identity_rate` 来自 identity probe 的投影候选匹配率：候选与参考横向距离落在容差内算匹配，左右角色一致率另有字段。它不是纯像素精度，但也不足以证明左右车道身份正确。当前 autoloop 读取原始 match_rate，对参考缺失候选的处理与已有 `match_rate_with_reference` 不同。

拆分报告“可测候选覆盖率、可测区域匹配率、左右角色一致率、正确本车道边界配对率”。分母缺参考的候选记 UNKNOWN；覆盖率本身必须过门，不能只在少数容易区域计算高匹配率。重定义后的指标进入新协议，不能直接换分母并沿用 0.60 宣称提升。几何任务回放也不能把“预测车道中心靠近车体 0”直接视为正确，必须有独立车道参考。

候选与参考使用可复现的一对一分配，或明确把多余的重复匹配候选计为错误并设门。增加反例：复制同一条候选不能提高身份正确率或参考召回；同侧多条漆线、交叉线、参考缺失、角色错配、错位空对照均能区分。

所有候选、路外和几何统计都必须传播 valid/known 区域。未知区里的候选独立计数；不能算成功，不能直接算假线，也不能悄悄从报告消失。没有候选时确认率为 UNKNOWN，并结合召回/有效无线真值判定，不能给 100%。

### 10.2 保留现有阈值，先核实定义

当前 `docs/t14_thresholds_v2.json`：

| 指标 | v2 门槛 | 本阶段要求 |
| --- | --- | --- |
| candidate_identity_rate | ≥0.60 | 当前为投影候选匹配率；参考覆盖或角色定义变化须发布新协议 |
| line_recall | ≥0.70 | 只在有效标线参考上统计，报告场景覆盖 |
| line_precision | ≥0.40 | 不能靠忽略全部困难区域达标 |
| offroad_false_ratio | ≤0.10 | 路面/铺装参考及分母口径必须明确 |
| inference_ms_p95 | ≤45 ms | 离线分割链指标，不能替代完整驾驶 tick |
| min_seeds | ≥3 | 研究确认建议使用预先登记的 5 seed；小样本不宣称通用收益 |

新协议需要把指标定义、有效区域、分组、聚合方式、匹配容差、阈值单位、标签版本要求一起纳入哈希。改变候选匹配、参考覆盖或左右角色口径后，旧阈值不能未经校准直接复用；在独立校准数据上定新值，冻结后再搜索。不得为当前候选过门而调低阈值。

mean IoU、宏平均、最差场景、各 seed 都要保留。硬门不能靠跨 seed 均值隐藏一个坏模型；真正待部署的具体 checkpoint 必须独立满足门槛。关键场景不允许被总体均值抵消，覆盖不足时给 needs_evidence。

铺装误入、压线、碰撞等必须有单独指标。道路 IoU 高不能证明没有把土肩当道路。新硬门若尚未完成基线标定，标记未冻结并阻止相应晋级。

### 10.3 比较与结论规则

保留每个成对差值。当前 `2*sd/sqrt(n)` 是近似不确定度，不能无说明命名为严格小样本 95% 置信区间。新协议应采用明确记录的方法（例如基于成对差值的 t 区间，写清自由度和假设），并同时报告原始分布。

场景不确定度与训练 seed 不确定度分别报告；按路段组进行场景重采样时，不把相邻帧当独立样本。最小有意义收益、非劣余量和正负方向在实验前冻结。多次试配方后的开发集优胜，需要新的确认阶段，不能反复调到固定最终集通过。

推荐判定顺序：输入不一致/标签污染/生产路径不一致 → invalid/rejected；证据缺失或定义尚未冻结 → needs_evidence；完整测量但硬门失败 → rejected；任务指标通过且无明显退化 → shadow_candidate。像素 candidate_better 只是研究结论，不能直接变成模型晋级。

训练基线和候选都必须产生逐 seed 的任务主指标并按 seed 配对；当前只给 IoU 的接线必须补齐。在线判定与 replay 调用同一个纯函数，输入包含完整冻结协议、来源资格、测量覆盖、硬门、统计方法与 production mismatch。判定文件保存完整协议快照及哈希；旧协议路径消失时不得悄悄改用最新阈值。

增加三类关键判定例：主任务改善且硬门全过；IoU 改善但主任务退化；所有数字通过但晋级评价参考仍属研究来源。只有第一类且其余覆盖条件满足才能成为 shadow_candidate。最终候选登记还需绑定实际 checkpoint，不能仅登记一个横跨多个 seed 的平均成绩。

### 10.4 性能协议

遵循项目测量纪律：回归门、CPU 重活和训练不得与计时并发。固定硬件、输入、预热和同步方式；每个 checkpoint 至少 3 次独占测量。按当前协议取重复 p95 的较小值进入离线门，保存全部 repeats、min/median/max、忙闲检测和预处理/前向/后处理分解。

较小值代表安静条件下的受控结果，完整驾驶另统计所有 tick 的 p50/p95/p99、deadline 超时次数/比例/连续超时长度及源年龄。目标 tick 周期必须在运行前按实际控制配置冻结，不能从 14 ms 分割耗时推断驾驶已经实时。

## 11. 工作包 W6：把学习过程完整展示出来

预计：0.5–1 个开发日。复用现有只读看板与监控，不另造一套实验数据库或控制协议。

| 视图 | 必须展示 | 验收动作 |
| --- | --- | --- |
| 全流程时间线 | 采集→审计→标注→训练→评价→判定→下一轮；对应 ID、时间、暂停原因 | 从一个候选反查它来自哪次采集和哪份标签 |
| 数据质量 | 生成/审阅/人工确认/实际入训/有效评价各计数；地图、场景、相机覆盖 | 640 帧不能被显示为 640 帧人工真值 |
| 神经网络训练 | train/val loss 分量、任务指标、学习率、epoch/step、梯度/AMP 异常、逐 seed | 可指向实际 checkpoint；缺点不补成 0 |
| 固定探针 | RGB、参考标签、预测、FP/FN、UNKNOWN；baseline/candidate 同一帧 | 标注范围和未知区可见，可定位左右边缘假线 |
| 因子对比 | 两臂数据差异、实际步数、成对差、区间方法、分场景结果 | 知道收益来自哪个因子，看到最差场景 |
| 失败归因 | 假线类型、漏线、左右错误、路外误检和具体帧/候选 | 从 rejected 原因点到原始证据 |
| 资源与恢复 | GPU/显存/磁盘、单轮墙钟、机器账本、活动信号、租约、恢复点 | 资源阻塞真实显示，关闭看板不影响训练 |
| 驾驶证据 | 模型版本、源刷新/消费、最终控制、边界可信度、deadline、事件计数 | 无 Tech run 时全部标为未测 |

沿用 `events.jsonl` 的 schema；新增字段兼容历史。事件包含单调序号、发生/记录时间、输入与模型哈希、阶段和缺失原因。处理半写行、重复事件和重启，不能靠页面猜测完成状态。

性能目标：常规状态在写盘后 10 秒内可见；图像只为固定探针和最差样本生成，限制每候选数量。按已登记 run 清单或增量索引读取，避免每次刷新递归扫描全部历史 logs。

看板不发布“总体成功率”掩盖不完整任务；分别展示 R1/R2/R3、研究指标、硬门状态和真值等级。

## 12. 工作包 W7：Tech 影子、短程控制与部署

预计：1–2 个开发日加运行窗口；前置为 R2 达成。若 R2 未通过，交付未通过原因与待补证据，不能跳过。

1. 离线回放：同一输入，验证新模型权重真正加载，候选提取和生产后处理一致。记录模型哈希、源帧/曝光/采集时间和预测时间。
2. Tech 影子：候选参与感知与规划观察，车辆控制权由指定的唯一控制器持有；禁止两个进程争抢油门/转向。
3. 强制刷新用例：人为使旧源过期或触发刷新，证明新结果的 source_id/frame_id/model_hash 被最终消费者读取；仅打印“reload success”不算通过。
4. 几何正反例：有空隙但车身扫掠不可通过、可见漆线优先于边界、无线但真实右边缘有效、所有边界未知时停车、已有车身压线只收敛缓行。
5. 道路类型：铺装+土肩不能驶入土肩；纯土路有效识别；铺装比例覆盖不足或两类混淆时停车并记录原因。
6. 短程闭环：预先登记路线、goal、天气/光照、车辆、速度上限、重复次数、停止条件。先低速受控路线，再逐步增加难度，不用“跑得远”代替约束验收。
7. 记录全部失败、接管和非终点停车时间；碰撞/压线/出铺装检测缺列时不能写 0 次。任何候选违规退出该轮资格并保留失败证据。
8. 通过后形成具体 checkpoint 的模型卡、已验证范围、完整配置、切换命令和回滚命令，人工确认再部署。切换在停止控车且资源明确的边界执行；不在行驶中随意热换。

标线模型训练输入和驾驶推理使用 RGB/真实传感器；annotation/独立真值只用于监督与评价，不能泄漏进驾驶参考。导航只回答去哪，横向参考仍按感知硬规则执行。
