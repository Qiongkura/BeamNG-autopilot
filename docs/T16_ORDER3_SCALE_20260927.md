# T16 §4.4 扩量：多路段受控场景批次与逐站点资格（2026-09-27）

方案 §4.4："先验收一个可重复的小批次，再以数百到低千帧的有效样本池做首轮规模
试验；优先增加路段、材质、曲率和光照组合，再增加近邻帧。"本文是该首轮规模试验
的记录与结论。前置：`docs/T16_ORDER2_SCENES_20260927.md`（五类场景入口）、
`docs/T16_P0_INIT_SMOKE_20260927.md`（初始化对照冒烟）。

## 1. 这一轮做了什么

| 改动 | 内容 |
|---|---|
| 挡位修复（用户实测反馈） | spawn/teleport 后**显式挂前进挡** `control(..., gear=1)`；每帧读回并记录 `gear/gear_m/reverse/throttle/brake/parkingbrake`（此前挡位不在任何证据里）。实测：场景里玩家车 spawn 后停在 R（NPC 是 N），teleport 与驻车指令都不改挡位；`gear=1` 一发即离开 R |
| 相机位姿 | 位置改用**传感器读回**（我按车体系重建的位置与读回差 ~0.36 m，10 m 处 ≈4 px）；方向仍用车辆状态（`get_direction()` 不含俯仰/侧倾） |
| 异步旧帧 | poll 前后各读一次位姿，漂移 >0.02 m / 0.05° 就重试（有界 4 次），漂移量落盘 |
| 静态投影标定 | 逐帧拟合 (yaw, pitch) 对齐渲染线像素，**落盘**（`line_projection_calibration.json` + 每场景记录），并报**交叉验证**（用别的帧的标定套到本帧，检验不是对本帧过拟合）。单看角度不可唯一辨识（沿路长直线对 yaw 退化），验收看残差 |
| 证据源按站点选择 | annotation 线类覆盖够（≥30 px）就用 annotation，不够改用**外观掩码**（白/暖白/黄，仍经深度遮挡校验）；用的是哪种记进报告 |
| 逐站点资格门（§4.3） | 证据**覆盖** = 画面内线真值点中 6 px 内有证据像素的比例；覆盖 <0.6 的站点**隔离**并写明原因，不拿假残差当结论 |
| 扩量 | 从 road network 自动挑 **12 条互不相邻的路段**（`pick_anchors`，长路优先、最小间距 150 m），每段布 5 站、五类轮转 → **60 站 / 120 帧** |

## 2. 规模批次的结论

```
站点 60（12 路段 × 5 类轮转）| 证据源：annotation 36 / appearance 24
批次验收（生成器自报）：合格 23 / 隔离 37（共 60 站）
合格站点：校准前 mean 3.77 px → 校准后 mean 2.46 px（median 1.93、p95 6.07）
          ≤2 px 的站点 12/23 | 交叉验证 mean 2.74 px
隔离站点：校准后 mean 7.03 px（不参与打分，逐条给覆盖值与原因）
known_no_line 全部 12 站：线类像素 0–1、LINE 通道 not_applicable（对照稳定）
```

> 口径说明：这次运行用的是"覆盖不足 -> 隔离"的判定；其中 12 个
> `known_no_line` 站点按**修正后**的语义应记 `not_applicable`（线通道没有主体，
> 既不算合格也不算隔离），修正已入库、下一次运行生效；本表按运行时记录如实
> 列出（故隔离数偏大）。

**关键发现（扩量才暴露的）**：引擎 annotation 的**线类覆盖随路段变化**——
同一批生成方式下，有的路段线类像素上万，有的只有 25 个甚至 0（贴花明明可见，
外观证据能命中）。在覆盖不足的站点上，"到最近线像素的距离"会算出 10–14 px 的
**假残差**（最近的那个像素根本不是这条线）：在三个最差站点上试过"角度修正 /
角度+焦距 / 角度+主点"三种相机模型，残差都停在 10–12 px，说明不是相机模型
问题，而是**证据没覆盖这条线**。按方案 §4.3 的处理是隔离并换场景，不是扩量。

## 3. 验收判定

- **合格站点**（证据覆盖 ≥0.6）：校准后投影一致性 **median 1.93 px、mean 2.46 px**
  （12/23 站点 ≤2 px）。五站点小批次（同一路段）为 1.29–2.02 px，达标。
  规模的均值略高于 2 px 的原因：少数合格站点的 p95 到 6 px（帧间漂移 + 远处点
  的证据像素稀疏），下一步按 §4 第 1 条压漂移。
- **隔离站点**（24 个）：报告里逐条给出覆盖值与原因，不参与打分（§4.3）。
- **交叉验证 2.74 px** 差于逐帧 2.46 px：帧间位姿漂移仍在（异步旧帧检测
  已记录漂移量），这是下一步要压的项——把"同一站点两帧位姿一致"做成硬前提，
  或改成单帧/站点并把标定在同一路段的多站间交叉验证。

## 4. 未做 / 下一步

1. 压帧间漂移（采帧前要求位姿稳定 + 站点两帧同姿态），把交叉验证拉到 ≤2 px；
2. 合格站点上把 `verify_batch`/`write_truth_credentials` 接进采集链，加
   "覆盖达标 + 几何一致才允许写 `engine_verified`"门槛（§4.3）；
3. 扩到数百帧：继续加路段（当前 12 条，italy 还有大量可行驶 DecalRoad），
   并加入光照/时段变化（§4.4）；
4. 训练/开发/最终集按**场景族（路段）**划分——`pick_anchors` 已经给了
   "同路段 = 同族"的天然分组，划分时按 anchor 分，不按站点分。
