## 2. 必须一并接受的代价（不可隐藏）

1. **外观门把"线"收窄成"漆"**：人工标签里像漆的线像素占比 dev **0.709**、
   R3-b 0.886 → 召回门在 dev 上基本不可达（实测 0.49–0.60）。这是**口径分歧**
   （暗/脏漆、蓝漆、被标成线的非漆结构），与自动真值认证口径一致、与 dev
   人工标签不一致。
2. **远线候选被丢**：dev 上 L=3.0 丢 88/160 个**已匹配**远线候选（宽路多车道）
   → 规划侧（多车道配对）必须复核后才能切默认。
3. **旧判定不可比**：三项都改候选集/掩码 → 需全臂重测，历史判定只作记录。

# 补充（同日）：L 改取 **5.5 m**（规划侧配对可达边界）+ 全臂排序实测

## A. 规划侧复核结论：L=3.0 会切进配对的可见范围

- 代码事实：配对策略的"近"候选上限 `LANE_PAIR_NEAR_MAX_M = 5.5`（`lane/constants.py`）
  → |lat| ∈ (3.0, 5.5] 的候选**是规划会用的**，L=3.0 会把它们丢掉。
- 实测（dev，seed 42，只开横向门）：M 160（基线）→ 117（L=4.5）→ **126（L=5.5）**
  → **88（L=3.0）**。即 L=3.0 的代价里有 ~38 个候选落在配对可达范围内。

## B. L=5.5 的表现：两套集合都过门，且不切配对范围

|---|---|---|---|
| v7 基线 | 0.9504 | 0.4396 / 0.4252 | 0.8125 |
| 只横向门 L=5.5 | 0.9434 | **0.6300** | 0.8333 |
| **全配置 L=5.5** | 0.9627 / 0.9591 | **0.6710 / 0.6707** | 0.9038 / 0.8636 |

| **全配置 L=5.5** | **0.8475–0.8829 ✓ 6/6** | **0.7010–0.7347 ✓ 6/6** | **0.7467–0.8382 ✓ 6/6** |

→ 全配置 L=5.5：dev 三门全过（身份 0.671）、R3-b 三门全过（身份 0.716）。
配合外观门（精度 0.65/0.68、召回 0.746/0.747）→ **五门全过**，且**不切进
规划的 5.5 m 配对范围**（丢掉的都是"配对本来也不会用"的候选 + 重复 + 非漆）。

**推荐修正：横向门取 L = 5.5 m（与 `LANE_PAIR_NEAR_MAX_M` 同值），不取 3.0。**
理由：L 的选择有**代码依据**（配对可达边界）而不是调参；身份率增益
（dev +0.23、R3-b +0.28）已足够过门，多出来的 L=3.0 增益是以切掉规划可用候选为代价。
