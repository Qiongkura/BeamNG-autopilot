# 项目遍历复核与下一阶段开发顺序（2026-10-11）

## 1. 当前判断

项目已经具备分层驾驶、Tech 自动采集、独立数据准入、真实神经网络训练、候选拒绝、可视化和论文证据归档的研究流程。接下来最需要完成的是：**驾驶数据进入最终控制时仍保持一致、有效；自动生成的数据能带来可重复的学习收益。**

当前已有证据支持“流程运行过”和“部分测量、回放可复现”；尚不能支持“strict 自动驾驶已可靠”或“模型能够持续自主变好”。下一阶段应按以下顺序推进：

1. 修复驾驶循环中已离线复现的场景替换问题。
2. 修复最终指令发送时的时效检查，补完整控制延迟及冷启动测量。
3. 建立针对可用率和停车原因的生产输入回放，先解释问题再改阈值。
4. 改进无人标注数据的覆盖、真值资格和训练配方，开展配对学习实验。
5. 在这些代码及回归完成、源码冻结后，再运行安静的 Tech 实验。
6. 根据新证据收敛论文主张，并完善可公开复现的材料。

本次为代码与既有证据复核：没有启动游戏、训练或新的驾驶实验，没有修改库、入口、模型及历史运行产物。以下开发项尚未实施。

## 4. 本次发现与结论链

### A. P0：只读诊断改变了用于安全检查的场景

**原假设**：规划器与安全检查使用同一份感知场景，诊断代码只读取它。

**是否真正激活**：在 [驾驶循环](I:/projects/beamng-autopilot/beamng_autopilot/fsd_drive.py:2935) 中，诊断 `try` 插在场景存在性判断和原本的回退逻辑之间。第 2969 行的 `else` 实际属于 `try`，因此诊断成功会进入场景重建分支。

**可复现输入**：复用 [生产循环离线测试](I:/projects/beamng-autopilot/tests/test_fsd_drive_pipeline.py) 的一帧 fixture：明确提供规划器 Scene；分别让 `polyline_point_distances` 正常运行、抛出 `ValueError`；观察驾驶模块的 Scene 构造调用。

**实测结果**：

| 输入 | 已提供规划器 Scene | 驾驶模块另建 Scene 次数 |
|---|---:|---:|
| 诊断成功 | 是 | **1** |
| 诊断抛异常 | 是 | **0** |

AST 也确认回退分支属于 `try` 的成功分支。fixture 的监控器为固定输出替身，两种情况均产生 throttle=0.4；因此该探针证明场景选择被诊断改变，**没有证明真实监控器的控制输出差异或具体事故原因**。fixture 没有 out.bev，回退产生简化 Scene；生产有 out.bev 时走另一重建路径，不能把简化场景结论直接套到所有实测帧。

**支持/推翻的结论**：推翻“诊断不改变场景选择”。这是确定的逻辑缺陷，应先修。现有离线驾驶测试替身不敏感于 Scene 身份，解释了为何常规通过计数没有覆盖此问题。

**未知与下一步**：尚未证明它对 E5 停车、压线或其他驾驶现象的贡献。先把回退明确放回 `scene is None` 分支，再用真实 SafetyMonitor 的确定性场景检验 verdict 和最终指令。

### B. P0：快照时效没有随后续耗时推进

**原假设**：最终控制使用的感知年龄反映从输入产生到指令发送的时间。

**是否真正激活**：[驾驶年龄辅助函数](I:/projects/beamng-autopilot/beamng_autopilot/fsd_drive.py:944) 读取发布时保存的 head/BEV/lane 年龄，不随下游计算推进。[安全年龄汇总](I:/projects/beamng-autopilot/beamng_autopilot/safety_monitor.py:697) 也读取这些静态值。已有 [PerceptionSnapshot.age_s](I:/projects/beamng-autopilot/beamng_autopilot/perception_snapshot.py:89)，但该调用链未使用显式当前时钟来推进年龄。

**可复现输入**：创建有效快照，captured_at=100，semantic/range/BEV 年龄均为 0；分别在逻辑时钟 100、105 查看完整快照年龄和这两个辅助函数结果。纯函数探针不发控制指令。

**实测结果**：

| 当前时钟 | 完整快照已过时间 | 驾驶辅助函数年龄 | 安全汇总 max_s |
|---|---:|---:|---:|
| 100 | 0 s | 0 s | 0 s |
| 105 | **5 s** | **0 s** | **0 s** |

既有 E5 `04_O` 的 E2E 单帧最大耗时为 5781.9 ms，控制间隔最大 6.359 s。按 `cmd_t - source_poll_started_t` 复算的 range 代理年龄最大 **6.159 s**，而遥测发布阶段 range_s 最大只有 **0.273 s**。T18 首次无效运行也出现 6.860 s 对 0.303 s 的阶段差异。合格 B 臂的指令时代理年龄中位数约 0.360/0.380 s，早先记录值约 0.226/0.227 s。

**支持/推翻的结论**：这些函数及遥测字段不能独自代表指令发送时的时效。`tick_wall_ms` 的终点在 stack.tick 后，早于 E2E、后续安全/控制与发送，不能当完整控制截止时延。

**未知与下一步**：真实 sensor capture timestamp 仍 UNKNOWN；poll_start_proxy 不是精确采集时刻。尚未用生产监控器证明延迟注入时最终是否误发油门，也不能把冷启动确定为曝光失败的唯一原因。下一步统一时钟基准和年龄参考时刻，推进到最终发送边界，覆盖所有仲裁、恢复与子步分支。

### C. P1：驾驶可用率低，需要确定性归因

**原假设**：固定实际位姿能分离起点条件对驾驶的影响。

**是否真正激活**：预注册后执行 O→B→B→O；实际放置误差约 0.02 m，三次达到等曝光资格，第四次曝光不够原样保留。

**可复现输入**：[E5 A/B 预注册](I:/projects/beamng-autopilot/docs/T16_E5_AB_PREREG_20261011.md) 及四个点名运行；同地图、模型、strict/sensor、25 s 请求。

**实测结果**：合格 O 净行进 3.484 m；B 两次分别 3.944、1.573 m。B 同臂差异大；三次合格运行记录区间中，估计静止/低速时间合计约 **68.625/74.127 s（92.6%）**，主要记录原因是 no drivable path 与 obstacle very close。

**支持/推翻的结论**：此轮不足以建立起点条件的因果差异；仅提高实验放置精度仍未消除闭环变异与可用率阻塞。停车原因是系统记录的触发条件，不等于已验证的根因，也不能据停车多直接认定“误停”。

**未知与下一步**：最新四个 E5 运行没有启用几何探针，缺少逐帧生产场景/候选/最终控制的完整回放输入。先修 A/B 中的代码问题，再记录同一源身份的生产输入，离线解释候选为何无效、何时存在可执行路径；之后才重做配对驾驶。

### D. P1：真实训练已发生，学习收益未发生

**原假设**：自动数据增量和真实优化会使模型更好。

**是否真正激活**：R2 生成 10 帧、独立准入 4 帧；R3 复用这些数据，基线与两轮候选各两个种子、每作业 60 步，共 360 步。卷积参数更新有 checkpoint 差异证据。

**可复现输入**：[R3 运行目录](I:/projects/beamng-autopilot/logs/experiments/t16_learning_validation_20261009_r3)，尤其两份 decision JSON、采样记录与权重比较报告；本次重新核对判定字段。

**实测结果**：基线标线 IoU 均值 **0.48025**，候选 r0 **0.36950**、r1 **0.36675**。两轮均 rejected，各有 18 项硬门违反、3 项指标缺失；all_at_plateau=false。基线可用/见过样本 60/60，候选 62/62；不是新增大量独立样本。未更换驾驶模型。

**支持/推翻的结论**：支持真实神经网络优化和自动拒绝已生效；不支持自动增量产生改善。两个种子、60 步且缺失部分分母，不能推出“自动数据普遍无效”或“网络学不动”。

**未知与下一步**：数据配比、标签语义、增量覆盖与训练预算的各自作用尚未分离。下一轮先完成通道资格、负例、域配比和开发评测的完整分母，再比较相同初始化/优化步预算下的候选。只延长后台运行时间不能替代这些工作。

### E. P2：回放加速与论文数字通过有明确适用范围

**原假设**：CPU 回放输出一致且数字核对通过，足以推导安全和完整复现。

**是否真正激活**：T18 固定 423,670 点输入，48 次 reference/current 调用；本次实际运行 129 项论文数字核对。

**可复现输入**：[T18 CPU 比较证据](I:/projects/beamng-autopilot/logs/experiments/t18_geometry_replay_20261009/cpu_comparison.json) 与 [数字审计入口](I:/projects/beamng-autopilot/scripts/m5_paper_number_audit.py)。

**实测结果**：同源 CPU 输出相同，最佳轮 p95 为 172.647→132.420 ms，约减少 23.3%；129 项已存数字一致。CPU 证据是既有结果，本轮没有重测其时延。

**支持/推翻的结论**：支持该固定输入、fresh-tracker 单帧处理的输出一致与耗时差异，支持数字来源核对；不足以证明多帧追踪、闭环驾驶安全、全链加速或公开完整复现。

**未知与下一步**：多帧回放、独立路面/漆线真值、执行 ACK、完整公开原始输入仍缺。论文当前更有证据支撑的贡献是可追踪的数据资格、测量有效性、可用率与安全约束之间的关系；“可靠自主驾驶”“持续自主学习收益”须等新的证据成立。

#### 2. 统一年龄参考时刻，增加最终发送检查

- 验收：记录源身份、参考时刻与最终 command 的连接；UNKNOWN 保持 UNKNOWN。没有真实 capture timestamp 时明确使用代理或下界，不伪造真实采集年龄。

- 先修可复现误分类及证据消费错误，再调整参数；放宽 strict 或安全门不算改善。
- 验收：每类反例的拒绝/放行都能连接到最终指令；控制权来源唯一；新增能力不依赖 annotation 驱动或地图横向偏移。

## 8. 下一轮最小成功标准
