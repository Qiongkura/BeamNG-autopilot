## 3. 排除项的证据

**相机横向零偏置**（`CameraModel.camera_pose`）：

```
heading=π/2 时 fwd=(0,1,0), left=(-1,0,0)
offset=[right=0, fwd=1.5, up=1.4] → C = pos + 1.5·fwd + 1.4·up
C.x - pos.x = 0.0    C.y - pos.y = 1.5    C.z - pos.z = 1.4
```

**斜率法给出的"−0.333 m 横向偏置"是错的**：它假设两条线都在 z=100 且间距 3.60 m，
反推 H=1.2908 m；但相机实际离地 1.537 m。该假设不成立，故斜率法结论作废——
这正是本轮**推翻**先前"相机偏置"判断的依据。

**无地图标线混入**（按 HSV 饱和度分组）：

| 分组 | 像素数 | 左峰 | 右峰 |
| --- | ---: | ---: | ---: |
| sat ≥ 200 | 1268 | +299.116 | +303.520 |
| 150 ≤ sat < 200 | 1176 | +299.074 | +303.470 |
| sat < 150 | 45 | +299.026 | +303.401 |

三组峰位一致 → 画面里只有两条漆线，右线本身就渲染在 303.5。

**生成侧完全对称**（`probe.built.json`）：

```
left  x={299.1} y=(704,734) z={100.0} width=0.15 lat=+0.9
right x={302.7} y=(704,734) z={100.0} width=0.15 lat=-2.7
```

## 4. 剩余唯一可能：不对称的渲染输入

生成侧、相机侧、位姿侧、地图侧全部排除后，右线与左线**唯一的差异**是：

1. `SCENES["proving_lane"]["lines"]` 的 `kind` 不同（`white` vs `yellow`），
   但 CLI 已把两者覆盖为同一材质 `line_yellow_double`；
2. `_add_road` 的 `render_priority = 30 + k`，两条线分别是 **30** 和 **31**。

因此下一步（需开游戏的对照实验，各约 4 分钟）应直接测这两项，而不是继续离线推：

| 对照 | 做法 | 判读 |
| --- | --- | --- |
| **C1 交换 kind** | 把 `proving_lane` 改成 `[("yellow",+1,"left"),("white",-1,"right")]` | 若偏移跟着 `kind` 走 → 材质/贴图问题；若跟着位置走 → 优先级/几何问题 |
| **C2 同优先级** | 两条线都用 `render_priority=30` | 若偏移消失 → 优先级导致右线被另一张贴花盖住/推开 |
