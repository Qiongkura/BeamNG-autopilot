### 统计契约

只有非空、二维、全部像素标签已知（0/1/2）、且没有标线类 2 的帧才是合格负例。
255 表示未知；含未知像素的帧一律不进入完整负例分母，即使已知区域没有标线。
此统计不证明标签可信，也不替代 verified 身份和训练/评价集泄漏审计。

`negative_line` 字段：

| 字段 | 定义 |
|---|---|
| `frames` | 已记录逐帧统计的数量 |
| `eligible_frames` | 完整已知、无标线帧数量 |
| `clean_frames` | 合格负例中预测标线像素为零的帧数量 |
| `false_positive_frames` | 合格负例中至少预测一个标线像素的帧数量 |
| `false_positive_px` / `eligible_px` | 合格负例的预测标线像素总数 / 总像素数 |
| `positive_frames` | 完整已知、有标线帧数量 |
| `unknown_frames` | 含至少一个 255 的帧数量（优先于有标线分类） |
| `empty_frames` | 空数组数量 |
| `false_positive_frame_rate` | 假线帧数 / 合格负例帧数 |
| `false_positive_pixel_fraction` | 假线像素总数 / 合格负例像素总数，非逐帧比率平均 |

`status=measured` 表示有合格负例；此时零误报就是数字 0。
无合格负例时为 `no_eligible_frames`，比率为 null。
旧产物缺计数或新旧数据混合导致计数帧数不符时为 `missing_counters`，比率为 null，
并提供 `missing_reason`。不从总体 `gt_line_px=0` 倒推逐帧成功数。

旧 precision/recall/IoU 的零分母仍为 null，不改成 1 或 0。
新指标仅提供诊断，不接晋升硬门；一个噪声像素也算假线帧，因此应同时看像素占比。
历史报告需要重新评估才会有新计数；本轮只读历史数据和权重，另存新的 58 帧诊断报告。
没有重算整个 136 帧集，也未覆写旧产物。后台 `_pixel_eval` 复用本评估函数，
但本轮没有扩展轮次判定文件的硬门字段或看板；新统计完整保存在评估矩阵 JSON。
