# E1（困难负例）数据就绪审计（2026-09-26）

结论先说：**仓库里没有任何目录同时满足 E1 的四个条件**（评价集之外、有身份/位姿、
人工确认无线、≥30 帧/场景），所以 E1 目前**跑不了合格版本**；本轮不拿弱数据凑实验，
而是把缺口逐条钉死、把"弱负例冒充已确认负例"这条路径用代码封住，并给出解除规格。

依据：`logs/experiments/e1_readiness_20260926.json`（逐目录机器可读清单）、
方案 v2 §S6/E1 与 §3.5/T10。

## 1. E1 的四个条件（方案原文拆解）

1. 负例来自**评价集之外**（"新训练负例不得取自当前固定开发/校准/最终评价帧
   或其空间邻近段"）；
2. 有**身份/位姿**（否则空间独立性 UNKNOWN，审计直接拒收）；
3. **人工确认无线**（T10：engine/agent/unknown 来源的"标签全零"不构成确认无线）；
4. 规模够（每场景 ≥30 帧，用于"替换固定比例"的配额）。

## 3. 本轮做了什么（不凑实验，但把路修好）

1. **代码封堵**：`negative_scenes.negative_training_eligibility(dirs, research=...)`
   把"全零标线"目录分成三类：`verified` = 合格负例；非 verified + 研究运行 =
   **弱负例**（允许但逐条记录）；非 verified + 可晋级运行 = **拒训**。
   接进 `_rounds_audit`：`rounds_dataset.json` 新增 `negative_training`
   （confirmed/weak/rejected + note），终端逐条打印弱负例。
   实测意义：以后任何"用引擎全零标签当已确认负例"的做法都会在审计里显形，
   不会悄悄变成一条 E1 结论。
2. **解除规格**（给数据/标注方，最小工作量）：
   * 采集：在**与 dev 不同地点**跑一次土路/碎石路段（Tech 采集已授权）；
   * 标注：对每场景 **≥30 帧**做"确认无线"复核（可复用现有复核包流程，
     `m5_review_pack.py` 生成队列、`annotate_review_pack.ps1 -Full` 启动）；
   * 交付要求：目录带 `meta.json`（map/source_id/位姿）+ 标线档位 `human_revision`，
     且与 dev 的空间距离 > 50 m（脚本会自动核对，见 §2 的空间列）。
   满足后 E1 可按冻结设计直接跑（`docs/T14_S6_EXPERIMENT_DESIGN_20260926.md` §4）。
3. **替代路径（若不想新增标注）**：书面授权研究臂 E1 —— 用 agent/engine 标签负例，
   判定记 `research_only`、不可晋级，且结果只能作为"弱负例"证据。本轮**没有**默认
   走这条路：这类负例的"全零"是缺失而非确认，跑出来的"无改善"无法归因
   （可能只是标签噪声），不符合方案"减少假线不得以全不画线获胜"的判定纪律。
