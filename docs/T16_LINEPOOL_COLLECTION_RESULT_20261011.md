# 第二线帧池族采集结果（2026-10-11）：正控制未获得，负例入库存

预注册：[T16_LINEPOOL_COLLECTION_PREREG_20261011.md](T16_LINEPOOL_COLLECTION_PREREG_20261011.md)
（先于采集提交，commit `a5cab37`）。

## 1. 实际执行

* `m5_controlled_scenes.py --map italy --anchors 1 --sites 8 --frames 3
  --step-m 2.0 --anchor-offset 24 --line-convention tiers`：
  8 站 → 采集侧合格 2 / 隔离 3 / N-A 3；产线 25 帧；游戏收尾
  `closed=True`、进程归零。
* `m5_auto_truth_export.py`（冻结门）：**准入 3 池、9 帧，全部无线负例**
  （`known_no_line_a0s1/a0s7`、`structure_negative_a0s5`，均 engine_verified）；
  含线站点（如 `known_line_a0s6`，annotation 线像素 628）**全部隔离**。
  输出：`logs/experiments/t16_linepool_20261011/auto_truth/`。

## 2. 隔离原因（逐条，原样）

含线站点未通过三道独立冻结门的至少一道：

1. **投影标定残差超限**（1.32 px > 1.0，或 2.70/8.51/32.75 px > 2.0）——
   生成侧线几何与标注投影未验证一致；
2. **标注覆盖 < 0.8**（如 straddled 0.022/0.332，near_left/right 0.52–0.67）——
   引擎标注在该站点不携带这些线；
3. **外观一致率 < 0.9**（如 0.171、0.419）——标注把 RGB 里不像漆线的像素
   标成了线（标注流程忽略遮挡物）。

## 3. 预注册判据

「至少一个准入池 line_px > 0」**未满足**：本轮如实记为**未获得线帧正控制**。
3 个准入无线池按预注册入库为负例供给。

## 4. 结构性结论（比单轮失败更重要）

回查 R2 导出报告：**R2 的 auto-truth 轮同样从未准入含线池**（仅 2 池：
1 个声明无线、1 个未证明含线）。即：受控生成 → 独立导出这条链在
**两轮、两个锚点偏移（12/24）**上都未能产出一个通过冻结门的线真值池；
失败理由是结构性的（标定/覆盖/外观三道各自独立拒），不是站点运气。

这与 E4 的结论同类且更强：**新线真值池的供给被「生成线 → 标注验证」链阻断**。
放宽这些门是被禁止的（"A failed attempt never lowers these thresholds"）——
解开它需要代码侧工作：标定/外观验证链与生成器的对齐修正，属于独立批次，
不属于采集轮。

## 5. 对配比实验的影响

* 跨池族配比实验（第二线帧族）在真值链修复前**不可执行**；组成实验继续以
  人工标注池（e2_it3 等）为线帧供给，负例供给从本轮起有 3 个 verified 池可选；
* 剂量扫描的结论（高占比更优更稳）不受影响——它用的是已准入池。

## 6. 根因诊断（本轮新增，指向下一代码批次）

`line_projection_calibration.json` 的残差结构呈现稳定的模式——**逐帧拟合残差
远小于跨帧泛化残差**：

| 站点 | before_px | after_px（逐帧拟合） | cross_validated_px（跨帧泛化） |
|---|---:|---:|---:|
| known_line_a0s0 | 2.907 | **1.449** | 3.040 |
| material_mix_a0s4 | 7.246 | **1.315** | 10.245 |
| slope_curve_a0s3 | 6.900 | 2.702 | 12.186 |
| known_line_a0s6 | 12.131 | 8.511 | 9.925 |
| occluded_line_a0s2 | 47.013 | 32.754 | 32.754 |

逐帧拟合把残差吸收到 1.3–1.4 px（部分站点已达 1.0–2.0 px 门内），但换一帧
就差 3–10 倍——**记录的相机位姿在帧间不稳**，逐帧拟合吸收的是帧间漂移。
已知的位姿来源问题（代码内 2026-09-27 记录）：`get_direction()` 不含俯仰/
侧倾（与渲染光轴差 2–6°）、位置读回与车体系重建差 ~0.36 m；当前实现用
「车辆状态基架 + 位置读回」折中，但帧间车辆姿态沉降/时序差仍在。

**修复方向（下一批次，非降门）**：投影消费**渲染时刻的实际相机状态**——
采集帧里已记录 `cam.get_direction()/get_position()` 读回（只作记录未用于
投影），把投影基准切到渲染时刻读回并对齐基架约定；预期 cross_validated
收敛到逐帧残差量级，含线站点即可通过现有冻结门（门不动）。

本诊断只读：未改任何采集/导出代码，未放宽任何门。

## 7. 根因确认（离线判别实验，2026-10-11 第二轮诊断）

**假设一（相机基架来源）被否定**：用「固定站点方向基架」替换「车辆状态基架」
重跑同帧标定，残差几乎不变（s6 帧三 15.28 → 13.19 px）——漂移不在基架来源。

**确认的结构**：残差是真值链**弧长的单调函数**。用拟合后位姿逐真值点量残差
（站点 known_line_a0s6，弯道 32.8°、坡 −4.95%）：

| 帧 | 拟合 (yaw, pitch) | 链弧三分位残差（近 → 远） |
|---|---|---|
| 0 | (−1.5°, −0.1°) | 1.50 → 5.20 → 6.47 px |
| 1 | (−1.5°, −2.6°) | 3.39 → 11.09 → 12.54 px |
| 2 | (−1.5°, −4.4°) | 9.11 → 20.08 → 22.09 px |

帧间「漂移」是同一现象的视窗效应：相机每帧沿链前移 2 m，可见弧段更远，
残差更大。**真值链的远端与渲染贴花沿弧渐进分离**——生成器在弯道/坡道上，
DecalRoad 渲染插值与真值链节点源逐渐偏离；平坦站点（material_mix 逐帧
0.77–2.26 px）正常通过。

**结论**：阻断点在生成器的链-贴花几何一致性（弯道/坡道站点），不是相机
位姿、不是导出门。修复属于生成器几何批次（链采样与贴花插值同源，或生成时
以已标定投影验证链-贴花对齐并只放行对齐站点）；门不动。

## 8. 第三轮诊断：径向尺度否定 + 深度缓冲量化极限（2026-10-11）

* **径向尺度假设否定**：偏移向量对图像半径的逐帧最小二乘 k 不一致
  （s6：−0.075/−0.276/−0.513 随帧增长），且径向拟合只降残差 22%
  （17.4→13.6 px）——不是 FOV/尺度误差。
* **深度缓冲判别实验不可行**：共享内存深度是 **uint8 米制量化**
  （探针 2026-09-27 实测记录），值呈 9.93/17.57/20.12/22.66 平台；
  远弧的表观 −7/−12 m 差是饱和伪影。uint8 米制分辨不出亚米级的
  链-贴花分离——离线诊断在现有数据上达到极限。

## 9. 下一步（仪表化批次，非降门）
