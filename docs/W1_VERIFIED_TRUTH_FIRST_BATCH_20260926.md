## 2. 三条结论（其中一条**推翻**了之前的判断）

1. **recall 是瓶颈，precision 不是**：人工真值下 precision 0.80–0.91、recall 0.36–0.42。
   而同一批模型在 **agent 真值**下是 precision 0.15–0.31、recall 0.66–0.72（E0 报告）。
   方向完全相反 → **agent 标注漏标了大量真漆线**，把"模型画对了但标签没有"记成了假阳。
   这与方案里"line_precision 0.30 在引擎弱真值 vs agent 逐帧核对下是 0.30 与 0.65"
   是同一个现象，现在是第三次、用人工真值独立确认。
2. **"模型在非铺装处画线"这个结论被推翻**：E0 在 agent 真值下报的路外假线比
   0.56–0.71（plain 场景），在人工真值下只有 **0.003–0.012**。也就是说，那些
   "路外假线"绝大部分是**真漆线**，只是 agent 标签里没有。E3（有证据的困难负例）
   因此**不该**再被当成第一优先；该做的是提高 recall 的监督（更完整的漆线真值、
   面向漏检的损失权重）。
3. **场景差异是真的，而且很大**：`233648`（路口）生产模型 0.000 / 研究候选 0.168，
   `135717`（plain）两者都约 0.30 —— 这两个场景是真正的漏检区；而 `135450`/`135342`
   已经到 0.68–0.79。分场景硬门（§10.2）在这里有直接价值。

## 3. 必须说明的局限（不要把 14 帧当成定论）

* 14 帧 / 6 组 / 每场景 1–4 帧：**不能**据此判"哪个模型更好"（方案要求逐 seed 配对、
  最小 seed 数、覆盖要求）；这里只报量级与方向。
* 选帧偏向漆线像素多的帧 → recall 偏乐观；"真无线铺装路"类只有 2 帧。
* 只有一位复核人、一次通过：**没有**标注者一致性证据。
* `233859`/`233648` 各只有 1–2 帧，单帧差就能把该场景的数字拉走。

## 4. 顺带修掉的一个真缺陷（否则这批复核会被误判）

`DatasetManifest.build()` 里 `src = paint_sources.get(...) or "engine_annotation"`
**从不读目录自己的凭证**——14 帧 sidecar 写着 `human_revision`，清单却全判成
`rank=unreliable` / `valid=False`（人工复核白做）。现在改为**凭证优先**
（`effective_source(声明, 凭证)`，调用方不能用字符串抬质量），并保留"无凭证时
按引擎默认 unreliable"的旧语义；有 sidecar 但没声明来源时写明确备注，不静默。
修后同一批帧：`rank=verified` 14/14、可训练 14/14、独立组 6。
