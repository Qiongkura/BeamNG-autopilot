### 1.2 对新草案七条规则的逐条改写

1. **“横向后验只能由传感器量测更新”应更精确。** 状态可以由运动模型预测，地图也可以形成假设/先验；但两者都不是新传感器量测。观测更新必须有真实源身份、采集时间与支持范围。最终横向权限另由证据和安全门决定，不由“后验”这个名称自动取得。
2. **不采用 `rho_paint + alpha*rho_curb + beta*rho_edge - gamma*gradD` 作为通用边界融合公式。** 漆线、路缘和护墙未必是同一物理对象；概率、可见性、距离梯度也不天然同量纲。先定语义与关联，再在同一对象上融合几何；物理障碍始终独立约束。
3. **保留铺装/土路区分，但不能简化为“只看一个路线属性”。** 当前 AGENTS 要求区分实际有铺装与真正土路，提到掩码中的铺装占比。地图或 `route_is_dirt` 不能把铺装旁土肩自动授权为道路；属性与观测冲突必须记录、降级。
4. **strict 的不压线规则保持。** 实线硬禁；“虚线 + 意图”只是一项将来研究能力的必要条件，不是充分条件。必须另有目标道观测、障碍/相向交通检查、可执行扫掠轨迹、取消策略与专门验收。
5. **strict 不倒车保持。** 倒车恢复涉及后向感知、控制与可停车空间，单独立项；不能用退出 strict 的方式默认放开。
6. **证据与预测分离保留，但撤回“一帧断档就清空一切历史”。** 断档应撤销“当前观测”资格、禁止权限升级，并进入有界预测/降级；不必抹除所有仍有诊断或预测价值的历史。身份、坐标系、时间发生断裂时才按契约重置对应状态。
7. **UNKNOWN 不等于 PASS 保留，而且必须落实到最终评分器。** 只新增一个 `lateral_digest` 或文档声明，不代表整个验收链已经做到。

### 1.3 本阶段真正的成功定义

先证明：候选被撤销后不会以另一个字段复活；历史/重复帧不会升级为新证据；规划、安全、控制看到的是同一参考；最终发出的每条命令都遵守当前权限；缺测不能获得安全 PASS。之后才比较能否更稳定、更远、更少误停。

## 2. 当前实现：已经有什么，仍错在哪里

证据等级：**源码确认**＝当前调用链可确认；**组件反例**＝合成输入执行得到，不代表完整 tick 或闭环；**历史记录**＝引用既有报告，本轮未重跑；**待验证**＝不能下效果结论。

### 2.1 不能再列为“从零实现”的能力

- 历史标线证据已经回喂组件提取和虚线恢复：`beamng_autopilot/vision/heads/semantic.py:210–257`，`beamng_autopilot/vision/segmentation.py:563–635`。
- 累积器已经有逐格 6 秒裁剪、同时间戳去重、同帧同格一票：`beamng_autopilot/vision/line_evidence.py:55–115`。
- 已有来源滞回、hold/coast、几何/宽度检查和新的 `ReferenceStabilityTracker`。`LaneTracker` 本身也已有平滑与拒跳，但当前 FSDStack 未调用该类；“库里存在”不等于该实现在线生效。
- 已有当前/规划车身越界检查、候选轨迹滞回、PathHold、最终停车与速度帽。不能继续写“只能事后发现越界”或“完全没有降级保持”。
- 前鱼眼输入、近场覆盖、车身路面覆盖三态测量、阶段评估脚本、停车统计、拒因遥测均已存在。问题转为接线正确性、覆盖、权限和可复现实验。

### 2.2 参考发布与权限：优先于换算法

**A. `fresh` 和 `paired` 语义错误。**

`fsd_stack.py:1710–1717` 用 `src == sensor` 代表新鲜，用原始 `lane_frame.paired` 代表真实双侧。中心漆线构造本来就会给 `paired=True, right=None`（`lane/pairing.py:970–973`）；fusion hold 也保留来源标签。

组件反例：中心漆线首帧是 `limited/1`；下一帧两路观测均空，按栈同样参数调用稳定器，仅靠 hold 就变成 `full/2`。**证明的是权限分类错误，不是已经证明实车满舵执行**；控制应用开关目前默认关闭。

**B. 被路面门撤销的单侧候选仍可发布 `sensor`。**

`lane/reference.py:830–835` 先算 `_single_vision`，`:865–875` 撤销中心，`:887–891` 又用旧布尔恢复来源/边界。完整单侧元数据、置信度 0.8、中心落在已观测不可行驶格的组件反例，返回：

```text
src=sensor, center=None, left 非空, width=3.6, rejected=False
```

这是发布契约错误；不能据此直接声称越过最终碰撞或 strict 安全门。

**C. slew 限幅后的参考与 Scene 的参考不是同一个。**

`fsd_stack.py:1693–1701` 只更新局部 `lane_ref`；`:1861,1885–1889` 构造 Scene 时仍读 `lane_ref_out.scene_ref`。该属性返回原 `center`（`lane/reference.py:486–495`）。按相同赋值顺序的组件示例可出现对外中心 −1.75 m、Scene 中心 −3.0 m。未执行完整 tick，静态链已确认分叉。

**D. 没有原始 lane_frame 时，合法 divider 参考可能到不了 Scene。**

组件反例：仅有长实线 divider、可行驶网格充分，选择器返回 `sensor` 且 `center` 非空，但 `frame_used=False` 使 `scene_ref=None`。落点同上及 `lane/reference.py:1023`。修复必须以**最终已接受参考**为发布依据，同时保留禁止地图横向兜底的规则。

### 2.3 末端转向限制：有 helper 不等于最终命令受限

`fsd_drive.py:3402–3426` 先做 away/ref-stability 限幅，再交给有状态 `SteeringShaper`。该 shaper 会保持速率/加加速度连续性，而不是保证立即落进新幅值区间。

本轮纯组件反例：上一输出 `0.55`，新请求已夹到 `0.15`，`dt=0.1`，shaper 输出仍为 **0.49**。因此需要在实际发送端复核限制，并同步内部状态；不能只修输入夹紧。

终点对准分支 `fsd_drive.py:4076–4087` 还会在 shaper 之后直接改写最高约 ±0.4 的转向；非硬停发送前没有统一复核当前局部权限。子步 `fsd_drive.py:4854–4877` 重新计算转向，也没有复用主循环完整的 mode/ref-stability/away 限制。硬停车和最终速度帽已有，不应推翻重做；应补齐**主循环、终点分支、子步和保护命令的一致终端契约**。

### 2.4 时间、姿态和地面模型

- 同步头完成后写 `age=0`（`fsd_stack.py:1143–1144`），不代表图像曝光到控制消费的年龄为零。当前 source_t 来自取帧返回时刻，未证明是曝光时刻。
- `fsd_drive.py:941–975` 的 snapshot age 读取语义/BEV/envelope 年龄，不等价于整个采集到执行时延；新 source age 遥测也未自动成为安全判据。
- `vision/lanes.py:404–432` 的射线相交对象是世界水平面 `z=ground_z`。`vision/projection.py:72–124` 支持姿态参数，不等于主链已经使用；主 FrameContext 没传 rotation，主标线回投主要走 pos/heading。
- 主语义/主道路默认用 `pos.z`，鱼眼/铺装候选/`line_lat` 用 `pos.z - 0.17`：`fsd_stack.py:896,1248–1252,1625–1628`，`occupancy.py:382–389`，`fsd_drive.py:431–435`。
- 合成射线仅改变水平面高度 0.17 m，横向落点可变化 0.34 m。**这是敏感度反例，不是实车坡道误差。** 车型高度常量、车身 pitch 和真实路面坡度是三个不同问题。

### 2.5 统计与评估器：已有实现不能盲信

1. `telemetry_contract.py:128–145` 和 `docs/LATERAL_FIELD_CONTRACT.md` 把 `lat_left/right` 描述成车角；实际 `fsd_drive.py:4186–4201` 用的是车辆中心点。四角最差值另在 `:4241–4261` 的 `body_lat_left/right`。
2. `lane_dev_m` 是规划路径到已接受参考的近 25 m 中位绝对距离，单位是**米**（`safety_monitor.py:838–861`）。不是 CCP，更不是“无量纲幅值”。
3. `eval.py:432–465` 仍有按路线航向和中心点推算车身的旧消费方式；`:713–749` 对部分横向缺列仍按 0 计。`lateral_digest` 的 UNKNOWN 尚不能保证 `score_run` 的横向验收不虚假通过。
4. `stop_digest` 已统一低速、蠕行、settle 等基础口径；但 `eval.py:301–319` 的 `by_reason.s` 是该原因出现的总时长，**不是只在停车时的时长**。不能拿它直接当“某规则停车秒数”。
5. `scripts/m5_seg_stage_eval.py` 有具体对照错误，详见 T01；Round6 的“旧像素约束几乎删光”不是旧线上算法的等价复现结论。

### 2.6 数据划分存在可复现的名实不符

`vision/dataset_split.py:90–130` 默认把每组时间尾部划到验证，并非整组隔离；`:157–163` 在 `groups_val` 非空时跳过共享组报告。

本轮 10 帧纯内存示例：训练与验证都含 `town/r`，实际共享组非空，`leak_check` 却返回 `leak=False, leaked_groups=[]`。`tests/test_dataset_split.py:43–58` 名称声称组不跨边，实际主要检查帧 ID 不重复。

训练入口 `scripts/m5_train_seg.py:416–443` 的 `by-map-scene` 沿用这一路径，并未填真实 `map_name`。**时间尾部可以作为开发验证，但不能据此宣称独立 episode/map 泛化。** 本轮没有训练，不能推断某个既有模型具体泄漏了多少。

### 2.7 近场和历史数字应如何解释

- `ROUND6_P0_PROGRESS.md` 的历史记录：0–4 m 带观测由 10/540 提升到约 70/540，增加约 16 ms/tick；每模式 n=2，不足以证明停车或安全效果。
- `fsd_stack.py:124–193` 中 `fisheye/fuse` 目前走相同添加路径，均叠加在主视已投影网格上，不能自然理解为两个独立融合算法。
- `band` 直接注入 observed/drivable，是上界实验，不是真实观测，不能进入正式通过统计。
- 车身当前 footprint 在历史探针中大多 UNKNOWN；前移 +2/+3/+4/+6 m 的矩形是前方区域，不是当前车身。不能把平移后的可见性冒充脚下覆盖。
- `line_conf_current` 是全缓存支持格的当前刷新比例；不是本车道正确率、所选边界当前占比或控制对历史的依赖比例。`history_confidence` 也不是 `1-current`。
- Round5 的事故、短路线和 Round6 的阶段试验都是历史基线，不代表本次工作树已经取得的闭环成绩。

## 3. 统一架构：估计可以丰富，授权必须明确

### 3.1 数据流

```text
真实传感器源 + 采集时刻/位姿
  → 单帧观测与几何投影
  → 带来源的历史证据与边界跟踪
  → 候选身份关联、语义/几何一致性检查
  → 最终已接受参考（唯一发布对象）
  → 状态后验与参考权限
  → 候选轨迹生成、当前/未来车身扫掠
  → SafetyMonitor + 当前模式权限
  → 末端命令约束（主循环/子步共用）
  → 实际发送回执与验收

导航/地图 → 路线意图、拓扑/身份假设 → 候选关联与影子比较
地图不能绕过观测与授权链，直接连到横向控制。
训练/评价真值不能连到在线控制输入。
```

不是另建一套总线。优先扩展现有 `LaneReference`、候选元数据、FrameContext、快照和控制回执，迁移时保留明确的兼容适配，最后去掉重复语义。

### 3.2 统一证据契约

| 字段组 | 必须能回答的问题 |
| --- | --- |
| `source_id / source_seq` | 来自哪个传感器、哪次真实采集？是不是重复消费？ |
| `capture_t / receive_t / consume_t / clock_id` | 时钟是什么？曝光时间是否已知？采集到执行隔了多久？ |
| `boundary_id / lane_id / role` | 是同一条边界吗？左/右/中心分隔/路缘的身份是什么？ |
| `frame / units / pose_id / ground_model_id` | 几何在哪个坐标系、用哪次位姿和哪种地面模型？ |
| `provenance` | 当前观测、历史重投影、预测、地图假设、人工注入各贡献多少？ |
| `support / visibility / local_age` | 当前实际支持哪些近场/远场区间？哪些区间已失鲜？ |
| `existence / covariance / semantic_confidence` | 存在性、几何误差、属性分类分别有多可靠？ |
| `authority / rejection / decision_id` | 为什么允许/限权/拒绝？各消费者是否使用同一次决定？ |

约束：

- 源时间不知道就写 UNKNOWN，不能用处理结束时间伪装曝光时间。可保存接收时间及已知延迟边界，但不得把不确定性抹去。
- 不因重复推理、历史重投影、预测或 `src=sensor` 标签而获得新票；历史量测仍属于原始采集 ID。
- 相邻相机、同一帧的两个头、同一掩码派生的多个候选不自动视作独立观测，避免重复增加置信度。
- 局部新鲜度按**已选候选的支持区间**统计；远处新线不能掩盖近场失鲜。
- `inferred` 边界允许用于假设和受限参考，但不能伪装成双侧真测，更不能据此宣称压线已完整测量。
- `line_evidence.added_pixels` 与包含黄色先验等贡献的 `line_pixels_added` 分开发布。像素数不代替组件、身份或几何恢复质量。
- `observed` 表示测到了；`drivable` 表示可行驶证据；`obstacle` 表示占用。未知、漏分割和已确认非铺装不是同一种状态。

### 3.3 最终参考的发布不变量

1. 已接受 `sensor` 横向参考必须具有非空、有限、有效的中心几何；否则明确 unavailable/rejected，不发布自相矛盾字段。
2. 任一否决触发后，center、边界、来源、权限、拒因同步更新；禁止使用否决前缓存的布尔重新恢复。
3. slew/平滑后的最终参考应统一交给 planner、stability、safety、controller。**真实观测边界仍保持原几何**，不能为了与平滑中心一致而移动实线或障碍。
4. 每个消费者带同一 `decision_id` 或几何版本；不能遥测报告 A、规划执行 B。
5. 没有原始 frame 的合法 divider/pavement 候选也要走同一接受流程，不以 `frame_used` 暗中决定有没有 Scene 参考。
6. `paired` 拆清“模型构造配对”和“两侧独立真测”；稳定器不得仅凭旧字段升级 full。
7. `limited` 不是无条件可行驶；仍须有可执行轨迹与硬安全条件。`full` 也不免除碰撞、越界和新鲜度检查。

### 3.4 边界仲裁与地图关联

先区分三类对象：车道漆线、铺装/可行驶表面边沿、碰撞实体边界。漆线优先用于车道参考，不意味着可穿过墙；两者可以同时约束车。

候选处理顺序：

1. 检查来源、时间、坐标、角色和关联是否可信。
2. 排除物理不可能、边界交叉、错误侧别、不可执行扫掠、实线/障碍冲突等硬不合法候选。
3. 在剩余候选间用局部观测、宽度似然、连续性及拓扑先验排序。
4. 存在多个相近解释时保留歧义、限权或弃权，不静默平均到两条车道之间。

地图与传感器冲突时，不简化成“永远信传感器”或“地图总更稳”。分别检查传感器质量、地图版本、坐标/姿态、数据关联；不能可靠解释时不授予新的横向权限。

当前地图能力并非完整高精车道地图：`roadnet.py` 主要提供道路中心、外沿、高度和路径连接；`connector.py:914–922` 另有 lanes/oneWay/radii 等道路规则字段。`beamng_autopilot/traffic.py:573–649` 按道路宽度均分的 legacy offset 不是实测车道级中心。缺少车道级实/虚、连接关系时应写 unavailable，不能自行合成法律权限。

## 4. 默认 strict 与研究能力的边界

本文“默认 strict”指**推荐的正式验收/演示基线**，不表示当前 CLI 无参数运行就是 strict。`scripts/m5_fsd_drive.py:30–129` 的入口必须显式选择 `--runtime tech --lane-mode sensor --strict` 并提供 `--goal X Y`；本文没有修改默认参数。下表研究入口是方案分类，**不是声称已有这些 profile 开关**。

| 能力 | 默认 strict | 研究入口 |
| --- | --- | --- |
| 感知车道保持、现有合法恢复 | 保留硬约束，修复接线 | 同样保留硬安全 |
| 地图路线意图与候选身份辅助 | 不变；不得地图设横向落点 | 新地图关联先 shadow |
| 历史证据、状态预测 | 不冒充新观测 | 可对比模型与误差 |
| PathHold | 审计现有 0.30/0.80 s 窗与重验 | 新边界经专项验证，不自动延长 |
| 无边界过路口 | 不因“没检测到线”自动授权 | 独立路口、冲突与停止空间证据 |
| 虚线变道/借道 | 不开放 | 显式能力开关 + 独立策略/验收 |
| 倒车恢复 | 禁止 | 后向感知、轨迹和控制独立验收 |
| 注入 band / annotation 真值 | 不得作真实驾驶证据 | 只在清晰标记的实验/评价通道 |

研究 profile 不是把 `strict=False` 当成总开关。若未来确需更改规则，应单独提交能力定义、适用运行域（ODD）、配置、风险边界与测试，再按项目纪律更新 AGENTS；**本终版不替用户批准这些更改**。

现行允许“保持航向”的文字不能解释为“任意失线处继续直行”。必须同时满足传感器剩余能力、可停车空间和碰撞约束；否则停车仍是合法结果。

### T01｜修正测量契约、分阶段评估与最终评分〔P0〕

- 最终评分按必测项目分别计算覆盖与 UNKNOWN；不能以缺列的 0 获得 no-crossing。双侧缺一侧时，分别报告可测侧，不能把整帧写作“没有越界”。

- 同一原始 logits 驱动各臂；各臂运行各自完整后处理，不把同一 production 输出重复贴在四列。明确 temporal 开关、跨 run/相机状态重置；生产一致性失败必须非零退出。

**反例与验收**：旧版函数 oracle；无路/有洞/細长低重叠组件；255 上预测不影响已知区分数；两帧 mean 与 global 不同；臂输出确实不同；阶段漂移非零退出；缺全部/部分横向列不能安全 PASS；中间行驶段不计停车。

**产物/回退**：版本化 metric spec、确定性小数据 fixture、可重现四臂报告。先使旧结果可解释，不直接据此调整安全阈值；旧数保留标签，不能覆盖成新数。

### T04｜统一末端控制约束及安全消费〔P0〕

**落点与复用**：`fsd_drive.py` 主命令/子步发送、`control/steering.py`、`control/drive_mode.py`、现有 ControlSubstep/命令发送封装、`safety_monitor.py`、`vehicle_body.py`；`tests/test_fsd_drive_pipeline.py`、`test_final_target.py`、`test_control_watchdog.py`、`test_path_hold.py`、`test_safety_monitor.py`。

**改什么**：把当前授权形成可复用的最终命令约束。主循环与子步共享幅值、方向、模式、过期和硬停止限制；shaper 后必须复核，截断后同步 value/rate 等状态。安全优先于舒适性；若突降权限无法兼顾安全轨迹和转向变化率，应减速/停止，不能偷偷越权。

保留 `final_target_speed` 和 `_final_stop_controls`，验证 DQN、E2E、横向 RL、纵向规划及后续整形不能抬高硬帽。已有 current/planned 车身扫掠继续独立存在，不能改成单一 lane_dev 或模糊分数。

**反例**：上一转向 0.55、本帧限额 0.15；上一输出朝错误方向；终点对准不得覆盖局部权限；主循环到子步权限收缩/参考过期；drive-mode 禁止油门时子步不得加油；停车后内部 rate 残留；有空隙但车身不可通过；当前已越界只能收敛；实线/障碍 veto 不被学习模块覆盖。

**通过条件**：断言实际 `send` 参数与回执，不只断言 helper 输出或 `steer_authority_clamped`。区分“命令被约束”与“真实车辆已经回到安全状态”，后者仍需闭环验证。

### T05｜统一几何基准，验证姿态与近场可观测性〔P0/P1〕

**落点与复用**：`vision/projection.py`、`vision/lanes.py`、`occupancy.py`、`fsd_stack.py`、`beamng_autopilot_tech/providers.py`、`lane/pavement.py`；`tests/test_camera_ring.py`、`test_nearfield_input.py`、`test_body_coverage.py`。

**改什么**：明确车辆原点/相机光心/地面高度、坐标轴与单位；主视、鱼眼、标线、铺装和遥测使用同一几何定义。将真实采集姿态接到实际调用链，而不只测试 CameraModel 支持 rotation。先修平地共同基准，再评估斜平面/分片地面；不能把车身 pitch 当道路法向。

对历史证据评估从过去地面到当前地面的重投影：仅保存 XY、再放到当前 ground_z 会丢失高度信息。决定是否扩充 3D 支持或限制坡道 ODD，依据独立真值，不凭“使用世界坐标”宣布已解决。

**近场工作**：明确 `fisheye/fuse` 的真实模式差别或合并命名；按传感器实际投影模型与畸变核查，不因名字叫 fisheye 就假定模型正确。统计车身及前方分带的分母、有效观测和 drivable；未知不能填成道路。

**反例**：非零 yaw/pitch/roll；不同相机高度；平面倾斜与坡顶；镜头边缘；同一世界标点跨视角；相机盲区；注入 band 不得列入真实观测；不同车型 footprint。oracle 应独立于被测投影公式，防两条实现共享同一错误。

**通过条件**：在声明 ODD 内给出米制误差分布和未覆盖区域；误差预算须小于所用安全余量。鱼眼训练不能突破物理视野盲区。平地影子算法可并行，不因坡道尚未解决而禁止全部离线开发；坡道控制上线必须等待相应几何证据。

### T06｜先简单状态后验，再按证据决定是否 IMM〔P1〕

**落点与复用**：`lane/tracking.py`、`lane/fusion.py`、`lane/stability.py`、`lane/reference.py`。若新增估计类，放在 lane 子包并保持与已有 tracker 分工明确，避免每层各自续命。

**首版**：同一 lane/boundary 身份下，输出 `e/e_dot/theta/theta_dot`、协方差、量测/预测状态及失效原因；先 shadow，不改变转向。`e` 为自车对感知车道参考的有符号米制横向偏移；`theta` 为相对该参考切线的航向差。单侧推断的宽度不确定性必须传播。

在低侧滑运动模型下可用 `e_dot ≈ v*sin(theta)` 检查一致性，`theta_dot` 要考虑车辆横摆率与参考曲率项。转向命令、实测轮角、横摆率和横向速度不是同一个量。身份更换时不跨两条车道求导；保留跳变事件，不用滤波隐藏它。

**比较次序**：当前基线 → 身份约束 + 鲁棒中值/单模型滤波 → 必要时 EKF → 有稳定多模态残差证据才试 IMM。Kang 的两个模型是假/真路缘量测假设，不是给所有来源套“大/小噪声”就能自动判真。IMM 必须有明确状态、测量模型、转移、初始化、滞回与校准数据。

**验收**：真实偏移/速率误差、响应延迟、错误接受、身份翻转、重新捕获时间、协方差校准和耗时共同比较。不能只要求曲线更平滑；一个永远不动的错误参考也很平滑。无收益则保留简单方案。

### T07｜补真实道路边界与局部拓扑，不把粗分割当通行证〔P1/P2〕

**落点与复用**：现有 LiDAR/`perception.py` 链、`lane/pavement.py`、`vision/heads/topology.py`、`occupancy.py`、`planning/corridor_feasibility.py`、`planning/constraints.py`；`tests/test_lane_pavement.py`、`test_topology.py`、`test_corridor_feasibility.py`、`test_selector_safety.py`。

**做法**：先确认点云是否有逐束 ID/垂直角/扫描时间与标定，满足条件才复现滑束、局部曲率/高差、分段地面与样条。几何自适应阈值用于替代不合适的常数，而不是宣布不再需要经验阈值或高度特征。

把路缘候选、铺装边沿、障碍实体分别发布；同一对象关联成功后再融合。程国柱的拓扑正则可借作软一致性检查或训练先验，但不削弱真实观测边界；分合流/路口局部失效时衰减的是先验。

Zhang 的粗 on-road 包含 sidewalk/curb，只用于后续路缘检测；不得据此将 `_drivable_fraction` 的安全含义改成任意连续分数。若分割未知，寻找其他真实证据或降级，不能把未知直接改成可行驶。

**验收**：有/无路缘、铺装+土肩、纯土路、坡道、护栏、草边、分合流、不同尺寸路口的正反例；报告定位误差、漏边界、假边界和错授权。几何 corridor feasibility 只是必要条件，仍须整条轨迹/车身/动态障碍检查。

### T08｜地图辅助候选关联，先做可证伪的影子对照〔P1，可与 T06 并行〕

**落点与复用**：`roadnet.py`、`connector.py` 可用道路字段、`lane/pairing.py`、`lane/reference.py`、`vision/heads/topology.py`。不要引入 legacy `beamng_autopilot/traffic.py` 的固定偏移横向目标。

**输入/输出**：输入真实存在的路线分支/方向/道路宽度先验，以及带身份的感知候选；输出候选关联分数、假设 ID、地图可用字段、冲突与弃权原因。**不输出独立可执行的地图横向中心。**

**对照**：同一组传感器候选，A 不用地图先验，B 仅辅助关联；无量测、地图偏移、过期地图、错误 lane count、分岔/宽路/急弯/单侧线分别测试。错误地图必须能被拒绝，不得提高 full 授权。

**验收**：在人工/真值确认的候选身份上，减少错误关联，同时不增加 false acceptance；无量测时不能新建 sensor 参考、不能恢复巡航。不能以“配对率更高”单独验收，也不沿用无来源的“87%配不成对”。

**上线边界**：shadow 可以先做；任何改变现行参考选择权限的接线必须作为明确行为变更验证。T08 不依赖先完成 IMM，也不应成为跳过 T02/T03 的捷径。

### T09｜收敛现有保持机制，增加有界风险预测〔P1/P2〕

**落点与复用**：`safety_monitor.py::PathHold/SafetyMonitor`、`lane/fusion.py` 的 hold/coast、`planning/hysteresis.py`、`planning/lateral_ref.py`、`control/drive_mode.py`；`tests/test_path_hold.py`、`test_road_loss_timer.py`、`test_drive_mode.py`。

现有 PathHold 默认 grace=0.30 s、max=0.80 s，缓存已验证路径，SafetyMonitor 负责当前场景重验。2.5 m 是到最近路径点的距离界，不是累计行驶距离；4 m 是剩余弧长要求，不是航位推算误差界。不能把这些说成已具备完整 dead reckoning 约束。

**补齐联合条件**：距最后有效观测的时间、实际累计行驶距离、航向/横向不确定性、剩余路径及可停车空间；统一各层 hold/coast 的期限与身份。预测/重投影/反复 offer 不得重置“最后真实观测”寿命。过期、坐标跳变、身份不一致按契约清理，瞬时失败与永久失效分开。

保守停车距离可从 `v*总延迟 + v²/(2*有效最低减速度) + 余量` 开始，但坡度、附着、制动建立时间及曲线扫掠必须纳入适用域。减速度或前方空间未知时，公式不是安全证明。

**风险输出**：车身到真实边界的有符号间隙、规划扫掠的首次越界距离/时间、停止余量、可用证据区间。TLC 在不趋近时可无有限交点；缺边界/模型不适用时应 UNKNOWN，不强行除以接近零的速度。

**验收**：快慢 tick、长停顿、远处刷新、零速、大横摆、路口缺界、前方障碍新出现、expired 后重复请求、先已越界后收敛。风险分数可提前减速，不能把实线/碰撞硬否决改成“总分尚可”。本轮不批准延长保持窗口。

### T10｜数据与标注：先划分与来源，再采集和训练〔从 P0 并行〕

**落点与复用**：`vision/dataset_split.py`、`labeling/tech_annotation.py`、`scripts/m5_train_seg.py`、`m5_eval_seg.py`、`m5_collect_seg.py`、`m5_collect_seg_ring.py`、`m5_annotate_manual.py`；`tests/test_dataset_split.py`。时间切片工具如需新增，可命名 `scripts/m5_timeslice_annotate.py`，**当前不存在，属于提议**。

**先修划分**：明确 `temporal-tail` 开发验证、episode/group 隔离、map/domain 留出是不同协议；分别报 frame overlap、group overlap、时间邻近和复制样本。使用真实 map/episode/time/source ID，不只 run basename；跨视角同一曝光、金帧复制与相邻片段必须一起归组。按时段切分时设置足够隔离区间，不能跨切口使用历史上下文。

训练入口必须真正落实选择的协议，泄漏条件不可只打印警告。核对 `train_only_runs`、分组排序、均衡采样与弱线过采样在最终训练索引上的一致性。40 帧已用于阈值扫描，就属于开发验证，另建锁定测试集；不能继续叫独立最终留出。

**数据补齐**：真实连续片段，包含时间戳、位姿、相机标定、曝光/接收时间、道路条件；覆盖淡线/虚线/急弯/阴影/夜间/无标线负样本/护栏假线/鱼眼域。自动 Tech annotation 保留 palette 与原图，人工检查材质漏标；annotation 仅用于训练评价，不作驾驶输入。

**标注 schema**：像素类别维持明确的 `0=background, 1=road, 2=line, 255=ignore`；标注工具按钮 ID 不可混用。另增加曲线 ID、左右/分隔角色、可见段、遮挡、起止、属性及 unknown。中心线、像素漆面和推断延伸分开保存。

**time slicing**：按固定图像行堆时间切片，人工控制点 + 时间方向插值，再映射回帧做空间插值。只适合连续、身份可跟踪片段；换道、遮挡、起止/身份变化处断段。生成的是辅助曲线标签，不是自动可靠的稠密分割真值。用逐帧人工抽验衡量误差和分钟/有效标签，不能预先承诺十倍提效。

**ONCE 借鉴**：2D 人工校正线 + 地面点云 + 标定投影形成稀疏 3D 真值，保留采集真值与训练插值的区别。没有真实点云支持的区段不能伪造测量。几何真值必须与被测模型独立。

### T11｜经典 CV 与学习感知：按失败类型做单变量消融〔P2〕

**落点与复用**：`vision/segmentation.py`、`vision/lanes.py`、`vision/heads/semantic.py`、训练与阶段评价脚本。只面向 Tech 感知主线验证，Steam 兼容回退不新增功能/优化。

**优先序**：

1. 先修 T01/T05/T10，再比较后处理与鱼眼域内数据增益；把误删真线和保留假线分别计量。
2. 对明确光照失败，试局部对比/TopHat/Otsu、ROI、方向可控滤波与颜色候选；ROI 必须能失效重检，不能盯着错误旧线。
3. 验证单帧样条/关键点拟合与可见性；曲线缺段不能自动补成可见实线。
4. 有对应数据和损失定义后，单独比较弱特征增强、多尺度/小波、轻量骨干、存在/可见性/属性分支。SegUNet 已有 mid 和 skip，不把“增加深层语义”当已确诊缺陷。
5. 若网络主耗时且量化/轻量化有机会，再选一个替代模型。结构名字、参数量或论文 FPS 不证明本项目快慢。
6. 多帧神经网络、运动信息特征融合和大型 Transformer/GNN 延后。运动输入需是真实测量且同步，控制命令不能作为独立道路证据；同时防止未来帧/未来转向泄漏。

**验收**：固定数据/初始化方案/训练预算/硬件，报告 raw 到最终组件全链路；IoU、precision/recall、可见曲线几何、身份、错误接受和延迟共同评估。空间平滑损失不是时间一致性损失；曲线头损失不能直接复制到 mask 而不定义对应表示。

**学习控制**：DQN、BC、E2E、横向 RL 保持现有默认权限。先证明参考和安全链可信，再逐个开/关严格对照；参与次数不等于收益，单次去掉 DQN 后撞车也不能证明 DQN 因果保护。

### T12｜性能与实验工具可信化〔从 P0 并行〕

**落点与复用**：`scripts/m5_perf_profile.py`、`m5_perf_decompose.py`、`m5_phase1_ab.py`、`m5_body_cov_probe.py`、`m5_scenario_set.py`，`run_manifest.py` 与现有独占/命令回执机制；`tests/test_perf_profile.py`、`test_scenario_set.py`，为新增脚本补入口级测试。

**已查实要修的工具问题**：

- `m5_phase1_ab.py` 默认每臂 5 次，固定 ABCD 轮转；`PIN={}`、仅少量环境变量清理，`BASE_ARGS` 只强制 sensor/strict，未显式提供 goal/map/model。其 `_span` 把过滤后的帧互相连接，可能跨行驶段累加停车；需调用 T01 的统一区间统计。不要把它称为已经冻结条件的随机配对实验。
- `m5_body_cov_probe.py` 会连接/可能启动、摆位和 step，不是离线只读脚本。半长/半宽为 2.3/0.95，与正式 2.2/0.9 不同；`:215` 的 `args.role` 未定义，`--cam front_main` 也不等于文义上的主视单臂。先修 CLI 和生产几何复用，再采信正反例。
- `m5_perf_decompose.py` 的 `stale_owner` 只是最大 age 项，不等于 SafetyMonitor 的触发来源；只看顶层 cmd_gap 会漏子步和保护命令，缺 tick_ms 子项还可能 KeyError。优先复用 `m5_perf_profile.py` 对命令回执/覆盖的处理；但该 profile 工具即使显示 `NOT MET` 也可能返回 0，不能仅凭退出码通过性能门禁。
- `m5_body_cov_probe.py` 当前主要把 blind 非 UNKNOWN 判为失败；in/off 分类不符、部分无 ring 情况还不能可靠导致失败退出。须补真正正反例断言，不能把退出码 0 当作车身保护验收通过。
- `m5_scenario_set.py` 已能生成场景协议、配对顺序并验收输入结果，但不驾驶，也不自动生成全部安全指标。复用其协议与门禁，不把协议打印或结果录入当成已经完成试验。
- manifest 中未设开关的原始 None 不等于解析后的有效配置；须记录实际默认值和关键开关。进程枚举失败不能返回“无冲突已证实”；独占不可测必须 UNKNOWN。实验入口也须接入清单与控制权检查。

**性能分段**：取帧等待、预处理、模型推理、CPU 回读、概率/后处理、组件投影、历史证据、近场、LiDAR/对象、规划、安全、发送分别记录。当前 `tick_ms.ring` 内含 semantic；近场位于 ring 之后并计入 range 大阶段。不能相加 ring 与 semantic，也不能相减来自不同样本的 P50 推算相机成本。

**优化顺序**：先找实际临界路径、重复推理/同步/复制/投影循环，再考虑批处理、调度、缓存、量化或模型替换。异步化必须带源时钟和迟到结果处理，不能用“处理完 age=0”掩盖旧帧。缓存得更快不等于观测更新得更快。当前子步只在主 tick 后的周期余量内运行，不是重感知期间持续独立工作的 15 Hz 控制线程；不能用目标频率代替实际命令间隔。

**验收**：相同负载下 P50/P95/P99/max、deadline 违反率、有效新源 Hz、range/object 饥饿、全部实际控制命令间隔；缺列 UNKNOWN。主流程变快但安全模态失鲜增加，不算通过。

## 7. 验收口径：感知、几何、权限、控制四层同时看

### 7.1 共同底线

- 结果必须是 PASS / FAIL / UNKNOWN 三态，按项目必测项聚合；已知失败优先报告，必需项未测不得给总体 PASS。
- 统计全程安全事件，同时分开 settle 前后和终点区行为。终点停车不能混进非终点误停。
- 区分算法自报“看见”和独立真值“实际发生”。若同一感知既控制又评价，只能算自一致性，不足以证明没有压线。
- 评价真值可使用经审核的 Tech annotation、独立人工标注或离线几何资料；不得回灌驾驶作为传感器证据。地图 edge_over 是辅助度量，不自动等于真实铺装/漆线真值。
- 任何增加放行的变更必须测 false acceptance；仅减少停车不够。任何增加拒绝的变更也必须测误停，不能以永远停车证明系统有效。

### 7.2 最小指标集合

| 层 | 必报指标 |
| --- | --- |
| 数据 | episode/map/相机分布、复制与邻近泄漏、标签有效区、冻结测试清单 |
| 感知 | 各阶段 global/mean IoU、已知区 precision/recall、误删真线、假线、可见段 |
| 关联/估计 | 错配率、错误接受、身份切换、中心/航向/速率误差、延迟、不确定性校准 |
| 证据 | 局部当前/历史支持、源年龄、重复消费、强制刷新与实际新源消费、缺列 |
| 参考权限 | limited/full/unavailable 原因、非新观测升级次数、参考版本不一致次数 |
| 几何安全 | 当前/规划车身越界、首次越界距离、真实铺装外、障碍与停车余量 |
| 控制/性能 | 最终命令约束、主/子步回执、命令间隔、有效新源频率、deadline 违反 |
| 任务行为 | 到达率、有效推进、非终点停车秒数/最长段、按真实停段分类的原因 |

像素容差带、Chamfer、曲线匹配只能作为补充。ONCE 原方案是**俯视 IoU 初筛 + 真值到预测的单向 Chamfer + precision/recall/F-score**，不是“以 Chamfer 全面替代 IoU”。项目曲线评估还须固定重采样、方向、有效可见区间和唯一匹配，防短线/重复线/多余分支占便宜；采用双向 Chamfer 等扩展时明确是项目改造，不冒充原论文。

### 7.3 数值门槛如何确定

- 确定性契约要求零违例：同源加票、无观测晋升、sensor 空中心、消费者版本分叉、发送命令越权、缺测安全 PASS。
- 几何误差、覆盖比例、新鲜度与停车余量根据传感器标定、车身尺寸、制动能力和 ODD 先冻结预算，再测；不要搬论文的 0.2 m、40 km/h、5 帧、0.3 m 阈值当本车答案。
- 不以“所有像素 100% 可见”作为不可能达成的条件。按具体安全检查列出必须可观测区间，不能满足则缩小 ODD/速度/权限或输出 UNKNOWN；不能填真值补足。
- 试验前固定非劣化项目、主要收益指标、停止条件与失败样例。报告逐 run 分布和区间，不把相关帧当独立样本凑显著性。

### 7.4 最低场景矩阵

直道双边真线；中心 divider 单侧；另一侧推断；虚线碎片；平行假线/护栏；无标线铺装边缘；铺装+土肩；真实土路；不同尺度路口；分合流；急弯；上/下坡及坡顶；强光/阴影/夜间；鱼眼边缘畸变；前方障碍突现；当前已压线的合法收敛；完全无观测；源冻结/乱序/迟到；teleport；主循环慢 tick 与子步运行。

每一类同时放正例与反例。任何论文的局部成功都不免除该矩阵。

## 8. 可复现实验与交接产物

### 8.1 三类试验不能混称

1. **纯组件确定性测试**：验证数学、状态和契约；不说明完整栈与车辆行为。
2. **原始传感器/图像回放**：同一输入比较感知与规划；遥测 JSON 只能重算它保存的统计，不能凭空重跑完整感知。离线更好的规划不能证明闭环更好。
3. **Tech 闭环**：动作影响未来观测，必须真正运行并记录独立安全证据、配置、控制权和失败。

### 8.2 A/B 规则

- 每次只改变一个假设；先比较当前冻结基线与单项变更，再有需要才做交互四臂。
- 四臂若用于近场×稳定器，应明确 A=均关、B=仅近场、C=仅稳定器、D=均开；`fisheye/fuse` 名称相近但执行相同不算有效算法对照。注入 band 单独列上界，不属于真实传感器臂。
- 固定地图/版本、车辆与损伤初值、起点/姿态、goal、天气、交通/种子、运行时长、模型 hash、采集规格和全部有效开关；环境继承必须受控。
- 采用配对、交错或随机区组并记录种子，避免所有 A 后所有 B；默认 ABCD 固定轮转不自动满足随机化。
- 初步每臂至少 5 次；根据效应与方差再定样本量。重复播放完全相同输入不等于新增独立样本。
- 保留所有运行、提前终止和失败，不只选最长里程。任何规则/权重/标签调整后，原测试集转为开发资料，最终测试重新冻结。

## 10. 旧方案中明确作废或降级的结论

1. “缺时序融合，所以新建 IPM 历史融合”作废：已接线；世界证据累积与单帧碎片恢复也不是重复两遍同一算法。
2. “只有全局过期、远处刷新令近场永不过期”作废：已有逐格裁剪。仍需要局部来源和新鲜度，不是删除历史。
3. “current confidence=0.093，事故控制 91% 靠记忆”作废：分母、参考对象和时刻均不支持这个推论。重复假线仍可能累积，单次假线不确认不等于永无误检。
4. “IMM/概率化是最根本首刀，硬门统一改概率”作废：先修来源、发布和最终约束；概率只在明确定义的模型和候选集合中起作用。
5. “Bayes 类型先验不受标定错误影响”作废：先验与似然都会影响后验，必须校准。
6. “lane_dev 是 CCP，急弯失败说明 CCP 阈值错”作废：本项目字段是路径对参考的距离。现有车身当前/规划扫掠应保留。
7. “CCP 只能低速直道才有意义”改写：位置/间隙测量本身仍有用，不足的是仅用它预测未来；预测须考虑航向、曲率和完整车身。
8. “McCall 不用 TLC，因此 TLC 不能用于控制”作废：其选择的是评价指标，强调多种任务相关指标。
9. “B-Snake 用单线和相机即可确定任意另一侧；米制宽度应随图像行变化”作废：真实 D 是先验/待估量，像素与米不能混。
10. “胡鹏 smooth 是二阶差/时间抖动损失”作废：是空间相邻点的一阶差约束；网络表示与损失尺度需核对。
11. “程国柱权重可直接写 rho_curb*rho_lane，或作为边界坐标加权”作废：原文含 `1-rho_lane`，调的是拓扑训练先验；沿曲线参数的梯度也不等于车辆时间导数。
12. “粗 on-road 允许不精确，所以最终路面 gate 可软化”作废：粗候选范围不等于可驾驶授权；Zhang 的 sidewalk/curb 是明确反例。
13. “Kang 无边界模式支持本车任意路口直行”作废：缺界原因、运行域、车速与传感器都不同。
14. “6DOF 相机支持意味着坡道已解决”作废：主链接线、车身姿态、地表形状必须分别核查。
15. “所有绝对阈值应改百分位；二阶滤波真正光照不变”作废：需有效对比/颜色/ROI 与无标线拒绝，不能凭标题推广为定理。标准 Hessian 方向二阶导的混合项系数也不能照损坏 OCR 抄写。
16. “鱼兆伟是 Son 译文、增量零”撤回，文献关系证据不足。
17. “ONCE extrinsic-free 不值得借鉴”作废：数据构建和评价价值明确，模型目标也应准确表述。
18. “IoU 是 precision/recall 的调和平均”作废：那是 F1；`IoU=TP/(TP+FP+FN)`，`F1=2TP/(2TP+FP+FN)`。
19. “小波/注意力无参数所以无耗时；论文 5 ms 对比项目 semantic 200 ms 证明数十倍空间”作废：必须核对阶段、同步、分辨率、硬件和实测。
20. “SegUNet 没有深层特征进入解码”作废：已有 mid 和 skips；换骨干是待实验方案，不是已确认修复。
21. “所有事故都发生在标线不可用时”“边界增强一定解锁里程”“配对率更高即成功”降为待验证假设，不作因果结论。
22. “同名统计函数/文档测试通过即契约一致”作废：本轮查出字段生产、stop 时长、split 和四臂实现的具体偏差。
23. “Round6 标注完成就能沿用全部总结”作废：其中旧像素臂不等价、后半待办与前半进展有过时内容；历史 n=2/盲区结果也不能证明保护全面有效。
24. “饱和限幅等于状态复位”作废：有状态 shaper/滤波器必须考虑内部状态及下一次输出；T04 的 0.49 组件反例说明区别。

论文 OCR 中缺损的符号、索引、单位不写成可直接实现的定式；必须回原页/作者实现核对。本文保留可核实的机制和条件，撤回过强归因，不以更漂亮的公式掩盖证据不足。
