## 1. Order 0 冻结（已完成，详见冻结文档）

- 复现链：两轮可晋级实验均为**每臂每 seed 12 训练帧、72 步、无 `--init`**。
  机制：基线臂只有 1 个目录（16 帧 → 12 训练 / 4 验证），候选 48 帧被
  `--max-train-frames` 按 run 配额截到 12；`epochs=24 × ceil(12/4)=3` = 72 步。
- 结论（写入冻结文档）：两轮 rejected 只支持"该配方被拒"，**不支持**对新增
  数据/学习能力作一般结论——样本利用、训练预算、初始化三者同时受限。
- 用户 dirty（README、monitor 四件套、两份 T14 文档）保留未动；`Item`（0 字节
  误重定向产物）保留；看板新面板本轮只出建议（§6）。

## 3. 主 agent 接线（autoloop）

`scripts/m5_seg_autoloop.py`：

1. **两臂共享预算与 init**：`train_cmd` 增 `--total-steps`/`--init`；
   `--total-steps>0` 时不再截帧（`--max-train-frames` 不参与，训练器对
   "预算+截帧"本就硬拒绝），champion.json 增 `step_budget`/`sampling`/
   `init_from`。
2. **步数取权威计数**：基线 `steps_by_seed` 优先读 `train_args.steps_done`
   （optimizer.step() 数），旧 checkpoint 才退回 `epochs×steps_per_epoch`。
3. **判定新增字段**：`step_budget`、`sampling`（`sampling_label()` 三档）、
   `init_from`、`train_meta`（逐臂逐 seed：steps_done/total_steps/stopped_by/
   sampler_report/init 谱系）、`scene_not_applicable`、`line_free_scenes`。
4. **N/A 适用性消费**：`line_free_scenes_from(scene_counts, scene_rank)` →
   `scene_report(..., line_free_scenes=...)`。场景档位来自**评价目录自己的
   凭证**（`read_dir_credentials` + `resolve_paint_rank`）；同场景档位不一致
   → 不证明（保持 UNKNOWN）。
5. **来源反伪造生效**：`resolve_paint_sources` 改用 `resolve_paint_rank` 解析
   档位，并用**已解析档位**（不是来源名）做晋级检查——否则无凭证的
   `engine_verified` 会绕过检查。
6. **负例 v2 汇总**：`sum_negative_summaries` 改用 `merge_counts`
   （最大连通域取 max，不求和），并报 `counter_version`；旧 v1 记录照旧可读。
7. **冲突提前拒绝**：预算模式 + `run_weights` 因子在**训练前**以
   `sampler_conflict` 拒绝（否则训练器硬报错，信息埋进 train_error）。
8. replay 安全性：判定落盘的 `missing_metrics` 就是过滤后的那份，replay 读回
   重算，不需要重跑 `proven_line_free`。

新增测试 `tests/test_t16_autoloop_wiring.py`（11 用例）：两臂命令含预算/init、
三档采样标签、plan-only 逐字打印、N/A 判据、负例 max 语义、v1 兼容、
`run_weights` 冲突拒绝（真实 rounds 路径，拒绝发生在训练之前）。
