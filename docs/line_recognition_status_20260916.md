# 标线识别现状与问题清单（2026-09-16）

本文用于对外请教。所有数字都来自实测，来源在文末给出；被排除的推断也一并列出，
避免他人重复走弯路。

## 1. 系统在做什么

BeamNG.tech 上的自动驾驶研究栈，标线识别这一段目前是：

```
RGB 相机帧 (536x403)
  → SegUNet（3 类：背景 / 沥青 / 标线，约 1.3M 参数，训练分辨率 536x403）
  → 标线掩码
  → 与三路证据融合：HSV 黄线掩码、经典 CV 亮点掩码、多帧世界坐标证据累加
  → 形态学与形状过滤（细长判据 / 面积判据）
  → _mask_to_markings：连通域 → 地面平面反投影到世界坐标
                       → 类型分类（solid / dashed / thin / unknown）
  → 虚线碎片重连 recover_dashed_boundaries
  → pair_lane_markings：投影到车身坐标系 (s, lat) → 候选门 → 左右配对 / 单边镜像
  → 车道参考 → 规划器
```

全地图共用**一个**模型（`logs/m5_seg/seg_model/best.pt`），没有按地图分模型。

## 3. 明确的问题

### 问题 1：可用边界的数量在部分路段严重不足（主要瓶颈）

同一地图同一起点，只改运行时长：

| 运行 | 可用候选边界/帧 | 配对成功帧 | 主要退路 |
|---|---:|---:|---|
| 好路段 120 秒（209 帧） | 7.52 | **78%**（163/209） | 真正配对 pair：138 帧 |
| 差路段 300 秒（556 帧） | 2.92 | **12%**（66/556） | 单边镜像 mirror_right：407 帧 |

差路段 556 帧中有 **411 帧**规划器判定“无可行驶路径”，车辆只能停。

同一份代码、同一机位，两次 120 秒运行的 sensor 可用率分别是 60.9% 和 80.9%，
说明**运行间波动很大**，识别能力不稳定。

### 问题 2：配对失败不是“看不到另一侧”

差路段 556 帧里，**两侧都有候选边界的帧有 494 帧（89%）**，但其中 **87% 仍然配不成对**。
也就是说配对失败发生在几何构造环节，不是“缺一侧”。

### 问题 3：拒收的两个主因都“拒得对”，所以调阈值没有用

差路段的拒收统计：

| 拒收原因 | 次数 | 被拒对象的实测几何 | 门槛 |
|---|---:|---|---|
| `thin:span` | 1431 | 跨度中位 **0.86 米** | 跨度需 ≥ 1.5 米 |
| `solid:side` | 1420 | 横向中位 **10.3 米**（p10 已是 8.0 米） | 横向需 ≤ 5 米 |
| `dashed:side` | 385 | 横向中位 7.6 米 | 同上 |
| `thin:side` | 162 | 横向中位 7.7 米 | 同上 |

被拒的确实是“不到 1.5 米的碎片”和“8 米开外的别的车道线”，不是本车道边界。
**问题出在提取端：正确位置、足够长的边界根本没被提出来的次数不够。**

### 问题 4：掩码碎片化

差路段的掩码白色像素总量与好路段相当（0.7%–2.1% 画面占比），但连通块数量差异巨大：

| 帧 | 白色像素 | 连通块数 | 平均每块 |
|---|---:|---:|---:|
| 好路段某帧 | 1577 | 4 | 394 |
| 差路段某帧 | **4228** | **157** | **27** |

同样是“找到了漆”，差路段被切成一堆平均 27 像素的小块，做不出长边界。

### 问题 5：模型不输出标线类型与颜色

网络只有 3 类（背景/沥青/标线），**没有** solid/dashed/thin 与黄/白的输出：

- 颜色来自“哪一路经典掩码命中”；
- 类型来自跨度与长度的几何启发式（`_kind_for`）。

因此 `unknown`、`thin` 本质上是几何推断的产物。候选集里 dashed/thin 占绝大多数
（差路段：R-dashed 604、L-thin 544、L-dashed 226 条，而 solid 只有 135 条）。

### 问题 6：弱势域与远距离缺真值

- `hirochi_raceway` 存在性 AUC 仅 **0.828**（红白路缘，训练样本少）；
- 山区微调会**退化**：v21 held-out line IoU 0.1407，反而低于 v8 的 0.2118，
  说明少量人工校正帧不足以替代基线；
- 人工帧容差召回最高只到 **71.6%**（v8 43.4% → v11 67.1% → v12 71.6%），始终未过 80% 门禁；
- **远距离没有任何有效真值**，所以“远处淡线识别得怎么样”这个问题目前无法用数字回答。
  已知最难的极致淡线帧（f00158 类）模型有零星 logits，但整图占比低于存在性阈值。

### 问题 7：下游代价是“停在路上”

严格模式拒绝用地图线做横向兜底（这是刻意的安全设计），所以识别不稳定表现为
`no drivable path` + 停车，而不是走错车道。差路段 300 秒内 411 帧如此。

## 4. 已被实测排除的方向（请不要重复走）

| 曾经的推断 | 实测结果 |
|---|---|
| 候选门阈值太严 | 否。被拒的是 0.86 米碎片与 10 米外线；放宽容差几乎无收益（文档实测：far-start 8→15 米只多 5 帧） |
| 掩码空心（路面约束把标线芯挖掉） | 是真 bug，已修（空心度 0.73→1.00，像素 +51%），但**同帧 A/B 配对完全不变**（2/40 → 2/40） |
| 共线碎片合并 | 无效。可用边界 1.20 → **0.87** 条/帧，0/60 帧获益 |
| 多帧证据累加没生效 | 否。它每帧补 2690 像素、标线条数 4.44→6.38，但**不拉长**边界（跨度中位 7.87→7.91 米） |
| 相机基向量不正交（导致画图偏移） | 是真 bug，已修（像素往返回归 11 px → 0 px），但世界坐标只移动 0.041 米，**识别漏斗不变** |
| 按地图分模型即可解决 | 未采用。目前单模型；`by_map/` 为空 |

## 5. 想请教的具体问题

1. **差路段两侧都有候选却 87% 配不成对**：这更像几何（重叠/宽度/跨度）不足，
   还是配对组合规则本身有问题？如果是前者，差在哪一条几何量？
2. **单边镜像为什么会不可用**：差路段 407 帧都在走单边镜像，却大多过不了可用性检查。
   单边界能否构成合法的本车道参考？如果不能，缺的是什么信息？
3. **拉长边界的正路**：模型已能提出 7.9 米级边界（离线实测中位跨度），但差路段
   候选跨度中位只有 3.2 米。要拿到“长且连续”的边界，应该优先做
   标签策略（虚线→连续）、专用边界输出头、还是在当前掩码上做更强的时序累积？
4. **类型/颜色是否必须学**：目前 kind 是几何启发式。加一个类型头值得吗，
   还是先把 span/几何做稳更划算？
5. **远距离与弱势域**：如果只能投入一件事，是补远区真值、补弱势域样本，
   还是改架构（分辨率/感受野）？当前对远区的判断完全没有数据支撑。

## 6. 复现方式

模型与流水线：

- 分割模型：`logs/m5_seg/seg_model/best.pt`
- 推理与后处理：`beamng_autopilot/vision/segmentation.py`（`predict` / `detect_lines`）
- 掩码 → 标线：`beamng_autopilot/vision/lanes.py`（`_mask_to_markings`）
- 候选门与配对：`beamng_autopilot/lane/pairing.py`、`beamng_autopilot/lane/constants.py`
- 融合与保持：`beamng_autopilot/lane/fusion.py`
- 多帧证据：`beamng_autopilot/vision/line_evidence.py`
- 相机模型：`beamng_autopilot/vision/projection.py`、`beamng_autopilot/vision/ring.py`

命令（需要 BeamNG.tech）：

```text
.venv\Scripts\python.exe scripts\m5_fsd_drive.py --runtime tech --map east_coast_usa ^
    --teleport 246.44 877.87 -107.62 --strict --lane-mode sensor --seconds 300 --speed 6 ^
    --no-e2e --no-bc --no-dqn --out logs/paper_notes/ab_gate_20260915/demo_hist.json

# 逐帧漏斗与拒收原因
.venv\Scripts\python.exe scripts\m5_vis_line_debug.py --episode <npz> --frames 6
```
