## 第 2 项：查清训练波动 → **完成**

- **原假设**：同配方 `road_iou` 跨 seed 0.43–0.69，波动来自 seed。
- **是否激活**：激活。36 个已有 checkpoint（roads3d + roads3f，2 臂 × 3 seed × 3 epoch）
  逐个评估，不新训练。
- **可复现输入**：`scripts/m5_seg_variance_report.py`；
  `logs/experiments/t14_variance/variance_roads3f_3d.json`；
  报告 `docs/T14_VARIANCE_ATTRIBUTION_20260924.md`。
- **实测结果**：总平方和 1.0475 = 臂间 0.0024 + seed 间 0.0354 + **seed 内(epoch) 1.0097
  （96.4%）**；`0.0` 的 checkpoint 是**55/55 帧全 0 的塌陷输出**；**`road_iou` 的平凡
  基线（全预测成路面）= 0.40245**，此前当作"稳定基线"的 0.4239 只高 0.0215。
- **结论**：**推翻**"seed 方差主导"。根因是**训练太短（15–30 步）导致同一 seed 在不同
  epoch 间摆动**，加上评估固定取 `checkpoint_last.pt` 把这个摆动记成 seed 差异；
  另有一个独立缺陷：像素指标被类别不平衡饱和（平凡解白送 0.40）。
- **未知与下一步**：训练到平台期后的稳定性未测（需要在第 3 项的循环里用固定步数重跑）。

## 第 3 项：接通后台执行入口 → **完成（验收逐条实测）**

- **原假设**：`run --no-dry-run` 能复用 `rounds` 完成"审计→提议→训练→评估→判定→重放"。
- **是否激活**：此前不激活（只打印计划）。现在真跑，且与手工 `rounds` **共用同一条流程**。
- **可复现输入**：`scripts/m5_seg_autoloop.py`（`rounds_args_from` / `gpu_minutes.json` /
  `gpu_minutes.pending.json` / `rounds --resume`）；
  配置 `logs/experiments/t14_3h_20260924_1906/entry_config.json`；
  运行 `logs/experiments/t14_entry_accept2/`（含 `loop_config.json`、`gpu_minutes.json`、
  逐候选事件流、两份判定）。
- **实测结果**（一条命令、无人干预）：

  | 验收项 | 结果 | 证据 |
  | --- | --- | --- |
  | ≥2 轮离线实验 | **2 轮**（r0 `addstraight`、r1 `addcurve`，各 3 seed × 4 epoch） | `decision_*` 两份 |
  | 一轮候选被实测淘汰 | **两轮都 rejected** | 判定 `rejected`；r0 均值 +0.015、r1 +0.005 |
  | 中断后能恢复 | **是**：在 r1 训练中途杀掉进程树 → 重启后"补记上次未结算的 GPU 时间 3.5 min"+"第 1 轮 已有判定：resume 跳过"→ 跑完 r1 | 两次运行的 stdout |
  | 连续无收益自行停止 | **是**：`自动停止：['2 consecutive rounds without a credible gain (limit 2)']`（阈值来自配置，不是默认） | 同上 |
  | 资源超限自行停止 | **是**：账本写 999 min 时入口拒绝执行、记 `resource_blocked`、退出 5 | `tests/test_autoloop_entry.py` |
  | 标签不足自行停止 | **是**：不带 `--allow-road-only` 时审计门判 `needs_review` 不训练 | `logs/experiments/t14_3h_realgate/` |
  | 默认不启动游戏采集 | **是**：`collect=off` | 配置与入口提示 |
  | GPU 预算跨进程且抗崩溃 | **是**：`gpu_minutes.json` 记 4.76 min（3.5 补记 + 1.3 实测） | 同目录账本 |

- **结论**：**支持**。修掉两处会让"后台循环"名存实亡的缺陷：① `--config` 指到不存在的
  文件会让 `rounds` 退回默认停止阈值（实测：配置 2 却按 3 跑）；② `--no-dry-run` 被配置里的
  `dry_run=true` 盖过。
- **未知与下一步**：常驻/定时（任务计划程序）与空闲窗口的真实调度未测——需要用户先定
  两个参数（见文末）。
