### 1. 计数契约的正文与图示写错了核心集合

**位置**：`paper_zh.md` 第 III-C 节、术语表；英文对应段落；计数契约图 `fig30_counting_contract.png`。实现依据是 `beamng_autopilot/experiments/candidate_metrics.py` 的冻结定义。

| 符号 | 现稿表述 | 实际实现的含义 |
|---|---|---|
| P | 至少携带一个候选的帧 | 真值明确存在漆线的合格帧，与模型是否预测出候选无关 |
| C | 抽取出的候选实例 | P 帧内纳入评价的预测候选 |
| R | 标注中的参考实例，且 R ⊆ C | C 中自身所在侧有可用真值参考的预测候选 |
| M | 匹配实例 | R 中满足冻结匹配条件的候选 |
| L | 横向位置一致的实例 | M 中预测与参考均有可判左右角色的候选 |
| A | 左右角色一致的实例 | L 中角色一致的候选 |

若 P 被定义为“有候选的帧”，那么“P 之外的候选”在逻辑上就无法存在。R 也不能同时是独立的真值实例集合和预测候选 C 的子集。

**修改要求**：

- 正文、术语表、英文稿和图示共同使用实际计数定义，不能只修中文段落。
- 将 R/C 解释为“候选参考可判率”或明确限定的 reference availability，不能让读者把它理解为所有真实标线被检出的比例。
- 单独说明：真实有线但零预测的帧、无真实线但出现预测的帧分别进入哪些计数。不能仅靠 R/C、M/R 证明漏检受到完整计罚。
- 若要声称实例召回，另给 GT 实例总数、匹配规则和一对一分配规则；现有三个条件比率不能代替它。

**证据链**：原假设：论文准确描述冻结契约 → 是否激活：该实现确为实例计数公共模块 → 可复现输入：模块头部定义、主稿 III-C、图生成器的契约文字 → 实测结果：P、R、L 三处定义不一致 → 结论：推翻“稿件已准确描述实现” → 未知与下一步：本轮未重跑实例探针；先统一定义，再用上述两个确定性例子验证文字、图和计数的一致性。

### 4. “约 30% 标注不可见／不可学”缺乏证据

**位置**：摘要、第 V-B 节、第 VI 节、未完成工作相关段落。实现依据：`beamng_autopilot/vision/paint_appearance.py`。

当前外观谓词使用 RGB 亮度、通道差与色度阈值，没有计算像素与周围路面的空间对比度。未通过这个谓词，不能推出“没有局部对比度”，更不能推出“任何局部对比度模型都无法学习”。上下文、时序和其它传感器能否恢复这些标线，当前实验没有检验。

该模块自己的说明也明确写着：外观条件是掩码门，不能单独作为真值判据。相同条件同时用于删预测和缩小评价范围，需要额外报告范围缩小所排除的错误，避免把条件化后的高分解释成整体能力提升。

**建议表述**：约 30% 的标注线像素不满足本研究的外观谓词；在该谓词限定范围内计算召回，会得到不同的读数。其视觉可辨识性和可学习性尚未独立验证。

**修改要求**：保留完整标签范围指标；并列报告外观范围保留的 GT 比例、被排除部分的漏检和误检。可以用已有标签的亮度／阴影分层及光照扰动检验敏感性，不需要新增人工标注。合成扰动的结论应限定为受控鲁棒性结果。

**证据链**：原假设：外观谓词识别了不可见、不可学的标线 → 是否激活：谓词确实参与外观筛选 → 可复现输入：RGB 阈值实现与正文论断 → 实测结果：实现没有空间局部对比度计算，也没有不可学习性实验 → 结论：只支持谓词筛选比例，不支持不可见／不可学的强结论 → 未知与下一步：先收缩主张，再做已有标签上的分层分析。

## 三、P1：提高研究结论的可信度

### 6. 6× 剂量“最优峰值”尚未成立

现稿剂量图的基础臂和 6× 臂各只有 1 个种子，4× 与 8.5× 各有 6 个种子。0.7625 的单次结果不能与其它剂量的六种子均值共同证明峰值位置；即使不声称精确提升幅度，峰值结论本身仍受随机性影响。补充材料写“五个种子”的地方也需与实际六个种子统一。

优先检查已保留的基础臂和 6× 多种子检查点，在同一冻结开发集、同一协议下评价；不足时再补缺失种子。所有剂量使用配对种子、相同初始化策略和训练预算，并明确“剂量”究竟是独立样本数量、重复次数还是采样权重。

报告逐种子差值和区间。帧与像素高度相关，场景／采集运行应作为数据不确定性分析的聚类单位；训练种子变异与场景抽样变异分开报告。小样本区间应标为探索性，不能把大量像素当作大量独立试验。

**证据链**：原假设：6× 是剂量响应峰值 → 是否激活：各剂量有已记录结果，但重复数不平衡 → 可复现输入：`dev_full_arms_20261005.json` 与 `dev_full_dose_arms_s43.json` 至 `s47.json` → 实测结果：基础／6× 各 1 次，4×／8.5× 各 6 次 → 结论：支持“已观察到的最高单次读数在 6×”，不支持稳定最优 → 未知与下一步：复用已有检查点完成配对评价。

### 7. 闭环安全和死锁的措辞需要收缩

现有闭环数据很有价值，但仅一个固定城镇路段、每臂四次运行，且采纳方案停滞比例 0.93–1.00，120 秒只行进 0.9–14.5 米。零次观测穿越与极低运动量同时出现，不能直接外推为普遍安全性改善。

“车辆当前在车道内，所生成路径被车体扫掠门拒绝”有日志支持；“任何前向路径都无法通过”是更强的可行性命题，512 个被拒绝帧不足以证明。应区分规划器已生成候选集与车辆动力学允许的全部前向路径。

建议：

- 将“消除全部穿越”改为“本组四次运行未观察到相应穿越，并伴随严重停滞”。
- 同时报原始事件数、独立事件定义、运动时间、距离、任务成功率；近零里程时不只给每公里率。
- 若保留死锁因果结论，冻结一组可复现初始位姿，扫描横向偏差／航向角，保存感知边界、候选路径、扫掠几何与最终控制命令；给可执行和不可执行正反例。
- 全程维持 strict 约束，感知提供横向参考，不能通过倒车或地图固定偏移来做“成功”对照。

**证据链**：原假设：采纳方案普遍提升安全，且不存在可行前向路径 → 是否激活：闭环中确有停止仲裁与路径拒绝 → 可复现输入：V-E 的运行统计、死锁图与诊断汇总 → 实测结果：低暴露下零观测穿越，已生成路径被拒绝 → 结论：支持当前场景的可用性失败与局部阻塞机制，不支持普遍安全或全部路径不可行 → 未知与下一步：本轮未重跑车辆；必要时进行冻结位姿的受控验证。

### 8. 冻结记录、公开复现和方法细节需要补齐

当前代码引用本地 `logs/` 并不等于审稿人能获取这些材料。本地 Git 清单没有跟踪 `logs/`、`weights/` 的实验内容，且点名的报告被忽略规则排除；本轮未验证是否另有公开归档。因此应给实际可访问的归档地址或准确声明可得性，不能仅写“仓库保留全部产物”。

还有两个具体复现风险：

- 部分图按文件修改时间取“最近 32 次运行”，新运行加入后，同一论文构建就可能改变。
- 一些协议示意图使用当前配置／实时哈希，可能不能代表历史实验配置。

建议增加一个冻结的论文输入清单：每张图、每张表和关键数值对应数据路径、摘要、提交、协议、种子、采样窗口；生成器只读该清单。预注册声明需给出实验前冻结的版本与时间，区分探索、方案选定与独立确认，不能以事后汇总文件代替事前证据。

方法表至少写清：网络结构／参数量、输入分辨率、初始化、优化器、学习率、批量、训练步数、损失、剂量采样方式、硬件、数据切分、匹配距离、角色判定、微／宏平均与空分母处理。真值来源与质量认证最好分成两个维度，避免把“人工／agent／引擎”天然理解为精度等级。

**证据链**：原假设：第三方可以从仓库按原输入再生成结果 → 是否激活：存在图生成脚本，但依赖本地忽略产物和动态选择 → 可复现输入：Git 跟踪／忽略查询、论文 README、图生成器 → 实测结果：本地能定位结果，外部可得性未证实，部分选取随运行变化 → 结论：复现链尚未在稿件中闭合 → 未知与下一步：补冻结清单和最小归档；本轮不执行上传或发布。

## 四、建议收束成什么论文

### 推荐主线

建议围绕“**评价范围敏感性与离线到闭环的差距**”组织材料。自动真值认证、冻结契约与可追溯产物是支撑这个研究的手段。

可考虑更短的工作标题：**《车道感知的评价范围敏感性与闭环可用性：基于可追溯仿真真值的研究》**。

研究问题控制在三个：

1. **RQ1：** 固定权重时，预测后处理与评价范围分别如何影响指标、验收和模型排序？
2. **RQ2：** 无需新增人工标注的认证训练增量，是否在共同评价条件下带来可重复收益？
3. **RQ3：** 离线较高的条件化指标，在闭环中对应怎样的感知可用率、运动能力和失败模式？
