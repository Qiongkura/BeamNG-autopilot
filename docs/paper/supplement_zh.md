# 摘要

本补充材料收录十六张图，它们的读数在正文中被引用，但不是正文论证的承重图。每张图都与正文一样，由三个脚本（`m5_paper_figures.py`、`m5_paper_figures_ext.py`、`m5_paper_figures_extra.py`）从同一批已记录产物（逐运行记分卡、逐帧遥测、运行清单、门判定文件与封存集记录）重新生成；本补充材料中的数字没有一个是手工抄录的。S-A 节汇集正文第 V-E 节背后的驾驶层证据（单因子阶梯、逐运行轨迹、各臂分布、车道放置偏差、安全裕度与配对对比）；S-B 节汇集第 V-C 节背后的组成与后处理扫描（五指标剂量响应、并行合并与阈值扫描、SWA、β=0.8 损失臂、实例覆盖与负例一侧全家）；S-C 节给出训练历史；S-D 节给出成本台账与空间隔离审计。适用于全部图的读数约定列在最后一节，其中包括三个「未测量而非为零」的量。

**关键词**—补充图，负结果，单因子消融，驾驶验收，审计链。

# S-A. 驾驶层证据

正文报告了五个预注册驾驶因子，其中四个被实现并否决、一个在实现前被既有测量否定，并把阻塞点定位为一处静止的车体扫掠死锁。以下各图是这些结论背后的逐臂与逐帧证据。

![驾驶单因子阶梯：各臂行进距离 (a) 与停滞比例 (b)，并给出最坏车体中心穿越帧。](fig6_factor_ladder.png){#fig:s6}

图 S1 中每一臂都仍未通过 `no_stall` 硬目标（0 帧），硬门保持 0/4；正是这张阶梯图支持了把已实现的因子报告为「被否决」而不是「部分进展」。

![逐运行时间序列（上：速度；下：路径到车道偏差），基线验收运行与 F-E 铺装门运行各一。](fig24_time_series.png){#fig:s24}

图 S2 说明停滞属于可用率失败而非控制失败：速度长时间停在零平台，而偏差序列显示车辆停在车道中心之外；F-E 臂之所以走得更远，只是因为它带着更大的偏差行驶。

![F-A／F-C／F-E 三次 A/B 的各臂分布（行进距离、停滞比例）。](fig25_arm_boxplots.png){#fig:s25}

图 S3 中的各臂分布是预注册最大值规则的原始材料：裁决按每臂最差一次运行读取；也正是区间的重叠，使得交付感知臂在路径可用率上没有产生分离（0.179 → 0.200）。

![闭环轮次中的逐帧车道放置偏差（v7 与 v8；黑条 = 中位数）。](fig26_lane_dev.png){#fig:s26}

图 S4 是定义性结果的闭环对应物：在基线定义下，车道偏差中位数为 0.86 m，车体在 8/8/8/13 帧中压过中心线；在采纳定义下穿越消失，代价是可用率。

![四次验收运行的安全裕度分布（最近障碍、最小碰撞时间、路径占用）。](fig27_safety_margins.png){#fig:s27}

图 S5 中的裕度是「验收失败属于可用率失败而非安全失败」这一结论的依据：四次运行都没有发生碰撞、没有路外帧、没有倒车帧，实测裕度落在各自分布的支持区间之内，而不是贴在极限上。

![配对对比：各臂的配对帧与候选数（开发池与有限类别池）。](fig37_pairing_compare.png){#fig:s37}

图 S6 在配对阶段本身量化了采纳定义的可用率代价：每 117 帧运行损失 3–4 个配对帧——这正是正文所述闭环可用率下降的机制。

# S-E. 读数约定与已声明缺口

1. **判定单位。** 验收结果是六种子臂（均值对照门读取，逐种子全部上报）；一次性确认是按索引选定、而非按分数挑选的单个检查点。
2. **封存集已被消费。** 确认图与正文确认来自那一次消费；实例级探针（身份率、角色、参考覆盖）**未**在其上运行，记录为 UNKNOWN，而不是通过。
3. **「线」的两套定义。** 采纳判定使用漆范围，标签范围保持与基线的可比性；膨胀是两套集合之间的取舍（0 px 行是 `mean` 读法，1/2 px 行是 `strict` 读法）。
4. **帧计数被运动量污染。** `body_cross_centre_frames` 随车辆行进距离缩放；F-C 与 F-E 的裁决按预注册的「跨运行最大值」规则作出，按距离的读法已为后续轮次另行预注册。
5. **剂量各档种子数不等。** 基础 1、4× 6、6× 1、8.5× 6 个种子；6× 点是交付候选的组成、仅依赖单一种子，因此剂量结果定位的是「已观察到的最高读数」，而不是稳定最优。
6. **有限类别池没有合格负例帧**，因此该池的假阳性率不可测（图 S9），且从不被报告为零。
7. **示意图不是测量结果。** 正文中五张示意图按代码与文档定义绘制，不来自运行数据。
8. **产物保留。** 逐轮次快照与被取代的运行目录已在一次存储清理中删除（审计文件 `logs/_cleanup_20261006.txt`）；每份判定文件、记分卡、清单、封存帧与交付检查点都被保留，因此正文与本补充材料的每一张图都可由保留的产物复现。
