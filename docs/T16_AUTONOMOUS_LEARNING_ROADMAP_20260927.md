### 需要纠正的结论

1. “只有人能生成合格标签”不成立。经验证的模拟器真值可以成为另一来源；不得仅改
   sidecar 字符串把旧不完整标签提升为 `engine_verified`。
2. “代码侧全部穷举、只有继续标注一条路”不成立。已有消融只排除了特定数据、模型和
   配置下的若干变体；训练初始化、样本调度、表示方式等还存在可检验方向。
3. “身份率是唯一硬阻塞”不准确。最新判定还列出精度、召回、角色、路外假线等失败。
4. 旧文档的身份率上界约 0.55 是固定候选集合/宽松匹配假设下的诊断，不能当作架构上界。
5. 最新线通道判定仍有两个无线场景 `line_recall=UNKNOWN`。需核对适用性接线：
   已证明无线时线召回应为 N/A，转由负例指标约束；标签不明时仍为 UNKNOWN。
   这项修复不能取消有线场景召回门，也不能令“永远不画线”过门。

## 2. 目标与自主闭环

目标：**用户新增人工标注量为 0；自动产出有出处的数据和可解释的训练结果；只在证据
达标时生成下一阶段候选**。不保证每轮改善，允许结果为无收益、证据不足或来源不合格。

闭环顺序：场景缺口 → 自动构造/采集 → 逐通道标签资格 → 去重与分组隔离 →
训练预算和初始化冻结 → 训练 → 固定开发集评估 → 错误归因 → 保留/拒绝 → 下一轮。

原本等待用户画线的状态改为自动分流：能重采就重采，能修生成器就进入生成器修复任务，
证据不足的像素写 ignore，仍不合格的样本隔离；同时继续其他合格场景任务。
达到重试/资源预算后给出诊断报告，不把“请用户标注”作为默认出口。

## 3. 第一优先级：让训练预算真正覆盖数据（P0）

复用 `scripts/m5_train_seg.py`、`m5_seg_autoloop.py` 和 `experiments/checkpoint.py`。

1. 增加明确的优化步预算与可恢复采样器，停止条件依据实际 optimizer step。
   新参数及 checkpoint 字段属于待开发接口，不能在实现前照抄为可运行命令。
2. 两臂共享 batch、总步数、初始权重、优化器和学习率计划；数据因子臂允许接触更多
   唯一样本。每轮从完整合格池按场景/视角配额轮换，记录 frame hash、累计 unique_seen、
   unique_available、正负例比例、曝光次数；旧固定截帧模式只保留为历史协议。
3. 接通训练器已有 `--init` 到循环配置，记录 parent checkpoint SHA、架构和训练历史。
   `--init` 是权重初始化，`--resume` 是恢复同一训练任务，二者不能混用。
4. 先独立检验“相同数据/步数下随机初始化与已有模型初始化”；选定新基线后，再做
   自动数据增量实验，不把初始化与数据组成同时变化解释成单一因子收益。
5. 旧生产模型的部分训练位置来源未知。可用于探索微调；进入最终确认前，须有完整
   谱系的新基座或能证明未被它见过的新场景，不能仅凭与当前训练目录无重复判独立。
6. 研发冒烟可以先用 1 seed 验证梯度、输入和预算；效果结论使用预先冻结的配对
   seeds 42/43/44。固定预算结果与充分收敛结论分开，未达平台期明确标注。

验收：等步数成立；增加的数据确实进入损失；两臂起始身份可追溯；恢复后的 sampler/
optimizer/scheduler 状态可复现；目录生成或 loss 下降均不能单独证明模型改善。

## 4. 第二优先级：自动真值生产（P1，核心工作）

### 4.1 先做能力探针，再决定扩量

本机 Python 环境的 BeamNGpy 是 1.35.1。官方 Camera 支持 RGB、语义、实例和深度；
材质格式有 `annotation` 字段，BeamNGpy 有程序化几何/道路接口。
这些是可用构件，不能据此断言现有地图中每一种漆线贴花都能被完整标注。
参考：[Camera](https://documentation.beamng.com/beamng_tech/sensors/camera/)、
[Materials](https://documentation.beamng.com/modding/file_formats/materials/)、
[BeamNGpy 1.35.1](https://beamngpy.readthedocs.io/en/v1.35.1/beamngpy.html)。

先用隔离的 Tech 测试场景构造已知有线、已知无线、遮挡、坡面/曲线、材质混合五类
测试。记录实际游戏版本、renderer、相机标定、材质/几何哈希、RGB/annotation/depth
帧身份。检测异步旧帧、黑图、分辨率错位、透明贴花边缘和 palette 变化。

### 4.2 两条自动来源路线

**路线 A：修复可控场景中的渲染语义。** 漆线使用独立材质或对象，语义类别与实际
可见纹理一致；铺装、碎石、土肩分别定义。若整张沥青纹理内嵌了漆线，不能把整个
材质标成 LINE；这类素材应拆分或留作弱标签，不承诺改一个类别字段就能解决。
场景/材质变体写入独立测试资产，不覆盖发行版地图；RGB 与标签必须描述同一场景。

**路线 B：程序化生成带真值的训练道路。** 若原图贴花链无法修复，在受控场景中自动
生成铺装、真实可见漆线、护栏、路肩与干扰纹理；自动记录每段漆线实例、左右角色和
铺装边界。先覆盖直道/虚实线/白黄线，再加曲线、断续、遮挡、阴影和磨损。
几何必须表现为真实可见表面，不能用突出路面的粗立方体代替漆线后直接宣称贴近目标域。
实例输出不能区分贴花时，使用自建实例 ID 渲染或经深度遮挡校验的投影，并单独验收。

自动标签来自创建这些可见对象的定义及渲染结果。场景定义可以用于离线训练和评估，
实际驾驶的横向参考仍只能由感知产生，不能把导航线/地图线加偏移送入控制。

### 4.3 自动资格不是模型给自己打分

复用 `beamng_autopilot_tech/annotations.py`、`experiments/labels.py`、
`credentials.py`、`manifest.py`、`spatial.py`；新增真值验证逻辑放库，探针入口保持薄。

每批生成的凭证至少包含：生成器/资产/运行版本、scene seed、地图/路段、相机和帧 ID、
来源图和标签 hash、通道有效区域、未知原因、测试报告 hash、校验器版本。
新增字段先做版本和兼容读取，不能通过手填 reviewer 伪装人工复核。

自动校验同时满足：

- 已知线段的可见投影与标签一致；用独立实现检查相机投影与坐标约定。
- 相机翻转、尺寸变化、时间错帧、遮挡物插入、标签篡改等反例必须被拒绝。
- 无线负例来自确定未生成漆线且无内嵌漆线纹理的场景；“模型没预测线”不作证明。
- 遮挡后的不可见漆线不计漏检；不确定边界像素 ignore，分别统计有效面积与拒绝率。
- LINE、ROAD、铺装/土肩、左右角色逐通道赋资格；某通道合格不能替其他通道背书。
- 在既有人工开发样本上可以离线比对迁移表现，不新增标注任务；这些反复使用的样本
  只能是开发证据，不升级成独立最终集。

资格只覆盖通过验证的场景/资产/相机组合；任一关键版本变化使旧证明失效。
通过后使用现有 `engine_verified` 来源；失败时隔离并自动换场景，不盲目扩量。

### 4.4 数据规模和隔离

先验收一个可重复的小批次，再以数百到低千帧的有效样本池做首轮规模试验；帧数只是
预算规划，不是质量门。优先增加路段、材质、曲率和光照组合，再增加近邻帧。
先单前视打通，随后扩到已有四视角，最后才考虑完整八相机。

训练/开发/最终集按场景族、基础几何/材质资产、路段和采集会话划分；同一时刻的
不同相机留在同组，换随机种子、换光照或空间轻微平移不算独立场景。
最终集在实验前封存；同一候选决策批次只消费一次，不把失败反馈继续用于该最终集调参。
生成器同源造成的偏差须明示；合成集通过不能自动外推到所有原生地图。

## 5. 第三优先级：让系统主动找样本，而不是请求人工标注（P2）

复用 `experiments/collection.py`、`controller.py`、`proposer.py` 和现有 Tech 采集入口。

- 在可信开发集把错误分成漏线、路外假线、断线、左右角色错误、无可信边界等桶。
  按桶选择可生成的新训练场景，不能把评价帧及其相邻路段回流训练。
- 有真值生成器时，自动改变困难条件并同步生成新真值；原生地图上没有可靠漆线真值
  的帧可贡献通过审计的其他通道，线通道不当作全背景训练。
- 同一批数据/配方/预算指纹无变化时不重复提议；每轮只改一个主要因子。
  “缺证据”“因子未激活”“有效实验无收益”分别累计，采用现有 outcome 停止规则。
- 一次只运行一个重计算阶段。采集、训练、全回归、时延测量进同一资源队列；继承
  已有 GPU/磁盘/时长上限、恢复和进程归属检测，不另建控制协议。
- 采集车辆由明确的游戏 AI 或场景脚本控制，学习候选只参与离线/影子预测；
  “shadow”入口仍可能控车，执行前复用 S7 审计与唯一控制者检查。

自动循环可以产出数据或拒绝报告而没有新 champion；连续无收益时优先检查样本覆盖、
来源与实际训练量，不无限增加 epoch、seed 或降低门槛。

## 6. 半监督与自监督作为后续扩展（P3）

可靠自动真值先建立锚点，再考虑 EMA teacher/student 一致性训练：教师输出与学生在
不同增强下的输出比较，只有置信度、几何/时序一致性合格区域参与，其他区域 ignore。
可参考 [Mean Teacher 原论文](https://arxiv.org/abs/1703.01780)；它提供方法依据，
不构成本项目一定提升的证据。深度/位姿也可用于时序对应，但遮挡与动态对象需排除。

伪标签保留 `pseudo` 身份，教师 SHA/版本和筛选条件落盘；不得作为评价真值。
当前 autoloop 会因训练/评价中出现非 verified 来源把整轮标为 research_only。
因此本阶段先维持研究臂；若后续要让半监督训练候选具备晋级资格，必须在新协议中
分别定义训练来源与评价参考资格，补防泄漏/防自评测试，用独立可靠参考验收。
不能只删除 research_only 或把伪标签改名为 engine_verified。

现有网络和训练链先保留。模型结构更换、端到端模仿学习、图像 RL 在数据与评价链
有稳定收益之后逐项推进；当前同时更换感知、规划和控制会失去失败归因能力。

## 7. 评估与可视化要求

不放宽当前有线场景身份率 0.60、精度 0.40、召回 0.70、角色一致率 0.70 等任务门。
适用性修复、采样预算变化、来源新证明都要版本化，重新测同一批基线后再做比较。

评价包含四层：像素精度/召回及路外假线；候选 C/R/M/L/A 与覆盖/身份；可见边界几何
及角色；安静独占性能。负例同时报任何假线帧率、像素占比、最大连通域和进入控制
区域的假候选数。帧率已经饱和到 1.0 时其他指标用于解释，不隐去原始帧率。

已有人工开发集保持原用途，新自动真值开发集独立报数；跨域结果不能用更容易的
合成场景均值替代。未测环境写 UNKNOWN，合成驾驶测试不得冒充原生地图泛化。

复用现有 dashboard / training monitor，新增或接入以下实际字段：

| 面板 | 用户应能看见 |
|---|---|
| 自动数据 | 生成/合格/隔离数量、原因、场景覆盖、已知无线与未知分开 |
| 数据实际利用 | unique_available / unique_seen、重复曝光、各视角/正负例比例 |
| 学习发生 | 初始权重与候选身份、实际步数、loss/梯度、验证曲线、恢复点 |
| 模型收益 | 对应 seed/场景的前后指标、所有未过门、N/A/UNKNOWN 与分母 |
| 自主决策 | 本轮改了什么、为何收集/训练/拒绝、下一步、连续无收益次数 |
| 资源 | 当前唯一重任务、预算消耗、暂停/恢复和失败原因 |

监控相关文件当前有用户未提交修改，实施时先协调该模块的唯一写入者，不覆盖。
尤其避免将候选池中 60 个帧文件显示成“60 帧已学习”，实际 unique_seen 必须来自训练采样。

## 8. 执行顺序、工作量与子 agent 分工

首个约 3 小时开发窗口以两个可检查交付为目标：训练预算/初始化接线方案及自动真值
最小探针。时间是工作窗口，不是对渲染兼容问题或模型收益的完成保证。

| 次序 | 任务 | 完成条件 |
|---|---|---|
| 0，先冻结 | 读取本轮 dirty、运行归属、旧实验配置，冻结新数据/预算/凭证契约 | 能复现“12 帧、72 步、无 init”的输入与结果；新旧口径分清 |
| 1，可并行编码 | A 做自动真值探针与校验库；B 做完整池采样/步预算/init；C 做来源与 N/A/UNKNOWN 测试 | 各自文件归属明确；运行重任务排队；主 agent 接线公共脚本 |
| 2，串行验证 | 纯逻辑回归和离线验证，再独占 Tech 测试自动真值 | 自动发现错误反例；标签由生成证据支持；原生地图能力限制写明 |
| 3，受控扩量 | 扩到多个独立训练场景，freeze 开发/最终划分 | 无跨组泄漏，unique_seen 可查，全部未知/隔离样本计数 |
| 4，学习 | 固定初始化/预算，先小规模冒烟，再冻结 3 seed 效果实验 | 真实权重更新、可重放结果；不得把暂行结果当收敛结论 |
