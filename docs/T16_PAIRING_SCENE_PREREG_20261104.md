# T16 配对专用场景预注册（2026-11-04）

## 1. 背景（为什么需要新场景）

原基线（`T16_LANE_PAIRING_ROBUSTNESS_BASELINE_20261104.md`）有两个装置缺陷：

1. **贴花 Scenario 未加载**：认证场景的 DecalRoad 是采集时临时 Scenario 里的
   对象，基础地图并不包含；探针只做 teleport，看到的全是地图自带标线，
   所以"认证线召回 0.00"是必然结果，不是模型结论；
2. **对称贴花跨在道路中心线上**：即使加载 Scenario（east 实测），配对按
   右行语义选中心线右侧的真实车道（`centre_line_own_lane`，中心差 2.1m），
   与认证贴花参考系不一致。

旧基线证据保留，但在结果文档中标注"装置缺陷，GT 无效"；本预注册定义
**配对专用场景**，让 GT 与道路可行驶车道语义一致后再跑三臂。

## 2. 场景定义（探针运行时构建，不产生新认证导出）

- 来源规格：三份认证场景 JSON（east off45 `a0s0`、italy off30 `a1s0`、
  west off40 `a3s0`），只借用站点几何（mid/dir/half_width/坡度）。
- 构建约定 `right_lane`（新增，仅研究/探针路径）：
  - 右线：横向 = −(半宽 − 0.05 m)，贴右侧铺装边；
  - 左线：横向 = 右线 + 2 × 1.8 m（车道宽 3.6 m，0.15 m 细线材质不变）；
  - Scenario 自车放在该车道中心（横向 = 右线 + 1.8 m），朝站点方向；
  - 每站一个 Scenario（沿用"单 Scenario 多路对象会截断"的结论）。
- **GT**：用 `build_scenario` 返回的构建记录里的真实线节点（与引擎渲染
  同源），按每条记录的 ego 位姿插值出车道中心/宽度；不使用规格里的
  对称节点。
- 该场景**只用于配对实验**：不生成认证导出、不进训练池、不改变任何门限。

## 4. 三臂（沿用原预注册定义，阈值不变）

- F1 `far_thin_allow`：thin+thin 远场对在几何自洽（隐含宽 2.5–4.5m、
  横向间距标准差 ≤0.35m、重叠 ≥4m、两侧起点 ≤22m）时允许配对；
- F2 `thin_near_relax`：thin 线 0–8m 窗口 ≥1 站点即计"有近场"；
- M1 `mirror_road_center_ok`：单侧镜像在边缘横向 0.5–2.5m、镜像中心与路面
  掩码中心差 ≤0.9m、置信 ≥0.50 时允许进入配对确认；
- 每臂单独跑（一次只开一个开关），场景 × 3 重复 × 20 tick；单臂不过 S1
  不追加组合臂。

**S1（不变）**：主场景 `true_pair_rate` 相对基线 ≥ +10pp 且 `phantom_rate`
增幅 ≤ +2pp，并在 ≥1 个复现场景复现；否则证伪。

## 5. 纪束

- 研究开关默认 False（= 现行行为），单测钉住；生产路径零变化；
- 不训练、不晋级、不新增人工标注、不消费最终集；
- 旧基线标注装置缺陷并保留；新批次的 JSON/JSONL 与构建记录全部归档；
- 若 A2/A3 在新场景仍不通过，则说明问题在"薄线可检测性/场景生成"而非
  配对门，三臂继续延后并记录。
