# T16 薄线检测召回上游课题 · 预注册（2026-11-04）

## 1. 动机与现有证据

配对三臂在 right_lane 场景上因**基线饱和**（true_rate=1.000）无法检验；
基线之前的失败都指向更上游：0.15m 细线在 live 536×403 下没有进入候选集。

已有证据（均来自本会话，不重复采集）：
- 原始（未加载 Scenario）基线：认证线召回 0（装置缺陷，仅作历史）；
- 场景模式基线：east 候选召回 ~0.98/0.72、west 1.00/1.00；
- hw6.0 宽路：`thin:span` 丢弃 31 次/20 tick、候选 0；
- italy 窄路：左线在 +1.15m 时左线召回 0.40，`thin:side` 丢弃率最高 38%；
- 候选横向与近场 GT 有 0.8–1.0m 系统偏差（跨段中位数 vs 近场标定），
  说明"候选召回"指标必须按 kind/距离分层，不能只看中位数。

## 2. 要回答的问题

- **Q1（分层召回）**：0.15m 细线的候选召回随**距铺装边余量**（0.05/0.6/1.0m）
  如何变化？thin:span / thin:side 丢弃率各是多少？
- **Q2（难场景判定）**：哪些配置的基线 true_rate <0.8 且拒绝计数非空，
  可作为 F1/F2 复测的"难场景"？
- **Q3（机制）**：召回损失主要来自 `thin:span`（掩码碎段）还是 `thin:side`
  （横向位置被拒）？两者随余量如何变化？

## 4. 判据（先于跑批冻结）

- **D1 分层报告**：每个 (场景, 余量) 必须同时报告左/右/双侧召回与
  thin:span/thin:side 丢弃率，不允许只报混合均值。
- **D2 难场景定义**：基线 true_rate <0.8 **且** `rejects` 或 `collect_drops`
  非空；满足者进入 F1/F2 复测名单。
- **D3 机制判定**：若 `thin:span` 是主因（丢弃率 > side 的 2 倍），则 F1/F2
  （作用于配对门）不适用于该场景，拒绝做"空臂"；应转向掩码/候选层。
- **D4 无增益即证伪**：若所有配置的基线 true_rate ≥0.8，则本课题记录为
  "此数据规模下细线召回不是瓶颈"，F1/F2 不再复测。
