# T16 重采样域对照结果：east 的后处理在 536 分辨率下删除黄线（2026-11-04）

## 执行

预注册 `T16_RESAMPLE_DIAG_PREREG_20261104.md`。离线只读：同一批池帧按
native（144×192，训练域）/ cubic / lanczos（144→536×403 预上采样）/
roundtrip（锐化再降采样）四种输入跑 `m5_seg`，比较 raw/post 黄线召回。
模型 pin `seg_model_v28_sslA`；east 9 帧（3 站）、west 3 帧。

## 判定（预注册 D1–D3）

- **east 触发 D2**：cubic/lanczos 的 post 黄线召回相对 native 下降 **62.5pp**
  （≫20pp）——不是重采样本身（raw 反而 +3pp），而是**后处理在 536×403
  分辨率下把黄线删掉**。
- **west 满足 D1**：三个条件的 post 变化都在 ±5pp 内，重采样无实质影响。
- roundtrip 与 native 接近（−3.7/1.5pp）→ 信息损失本身不是主因。

## 机制

`Segmenter.predict()` 的后处理（形态学、路面约束、连通域/外观门）在**输入帧
分辨率**上运行，而核大小/膨胀/跨度阈值都是**像素固定值**：

- 池域 native：模型内部把 144 放大到 536 推理，但 argmax 掩码被缩回 144，
  后处理在 144 上跑 → 黄线存活（0.73）；
- 预上采样到 536：后处理改在 536 上跑，同样的像素核/约束对细黄线作用更强
  → 黄线被删到 0.10；
- live 相机正是 536×403 原生 → **这就是 live 右线候选召回≈0 的直接机制**。

west 不受影响说明这是**场景相关**（黄线位置/宽度/路面掩码覆盖率）而不是
普遍规律，但 east 的失败足以解释矩阵与探针里的右线缺失。

## 结论与下一步

1. **HA/重采样假设均排除**；根因是**后处理分辨率敏感**（in-recipe，可修）。
2. 下一步（需新预注册）：**后处理分辨率归一**研究臂——在 536 输入下把
   argmax 掩码先缩到规范分辨率（如 144 或 192 宽）跑后处理，再放大回 536；
   或把后处理核大小按分辨率比例缩放。先离线在池帧的 cubic 条件上验证
   post 黄线召回能否从 0.10 恢复到 ≥0.6，再决定是否接 live。
3. 不训练、不改默认门、不新增标注；west 作为不回归控制（要求 ≥0.84）。
