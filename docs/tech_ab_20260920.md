## 1. 关键发现：一个真实安全缺陷（已在实车暴露并修复）

**首次基线车完全不动**：151 帧里 144 帧 `minimal_risk / obstacle contact risk`，
`risk_kind=hard_collision`，油门全程 0、刹车全程 1；而同一帧 `fwd_clear` 中位数
16.4 m、`lane_paired=136`。世界是好的，是安全检查把车按死了。

根因（`obstacle_risk.assess_obstacles` 的分支顺序）：接触带判定排在**横向走廊过滤之前**，
于是任何 3 m 内被跟踪的物体——路缘、树、路边停放车辆，城镇街道上几步就有一个——都被升级为
"立即碰撞"。

修复（提交 `511beca`）：

1. 走廊门控提前到最前：走廊外且预测不会侵入走廊的物体，即使很近也只算 `roadside_clutter`；
2. 走廊侵入预测改为在 3 s 窗口内按 0.5 s 步长采样，横穿车辆不再因为"TTC 时刻恰好还没进
   走廊"而被当作路边杂物。

修复后同一场景、同一配置：`off_road` 143→23、`stall` 141→78、行驶 14.4 m→89.5 m
（下表 `seg_prob_gate` 列，即修复后默认配置 + E1）。

1. **`substeps` 全程为 0**：15 Hz 控制子步在这些 run 里**从未生效**（`_sub_driving`

   不是单个开关的阈值问题。

### 4.1 `collision_count` 的实测结果与实现

补测链路（提交 `abd5ca4` / `e0ffb40` / `b11fdba` / `d5a9ace` / `63d5384`）：

- `beamng_autopilot/damage.py`：把 `Damage` 传感器 payload 归一成一个数；**无法识别的形状返回
  `None`（未测量），绝不返回 0**——缺传感器时的 0 会被读成 PASS，比没有指标更糟。
- `beamng_autopilot_tech/providers.py`：挂载 `Damage`（beamngpy 1.35 唯一正确的
  `vehicle.sensors.attach(name, sensor)`；手写 `Sensor.attach` 签名不符会抛错并被吞掉）。
- `Connector.read_damage_total()` + `fsd_drive` 逐帧 `damage_total`。
- `eval.collision_events()`：损伤增量 ≥ 阈值算一次碰撞；无样本时 `collision_count=None`。

实测（`logs/fsd_benchmark/damage_town_check.json`，40 s，town，strict）：

```text
frames 52 | damage samples 52/52 | 0.0 -> 68.8383 (t=34.3s)
collision_events: collision_count=1, first_collision_t=34.338
path hold: 2/52 frames served (30 verified offers)   <- PATH_HOLD 首次实车生效
```

同一跑次 `path hold (creep)` 出现在控制台（`src=hold`），这是实施方案阶段 B 的
有界路径保持**第一次在真实运行中被触发**：感知掉线的那一帧没有直接全停，而是复用
了上一条已验证轨迹并降级到蠕行。

### 4.2 尚需决策：`collision_count` 是否作为硬门槛

`score_run` **故意还没有**把 `collision_count` 变成硬门槛：未测量（Steam 会话、未挂
传感器的 Tech 会话）应当算 FAIL 还是 UNKNOWN，是策略决定；悄悄改变 PASS 的含义正是
方案警告的做法。当前每个 scorecard 的 `assessed` 块都会带这个数字。

## 5. 结论与下一步（本环境可执行的）

1. **不能宣布 §12 达标**：10 组全部有未过门槛项，且 `collision_count` 根本未采集。
2. **最高优先级是感知可用性（stale sensor）与 tick 时间**：tick P95 700–1600 ms 直接
   决定了控制周期与 stale 判定；这与方案 §A（控制与感知解耦）方向一致，但本次实测显示
   异步头开关单独开启（`async_heads`）并未降低 stale（118 帧），需要先查清
   `stale` 的来源模态（遥测 `freshness` 字段已具备逐模态 age）再改。
3. **控制子步需要在停车/无路径帧外复测**：`substeps=0` 说明它没被触发，先修触发条件，
   再谈它对平顺性的贡献。
4. ~~碰撞计数需要补进 evaluator~~ **已完成**（第 4.1 节）：实测第一次跑就测到 1 次碰撞，
   说明"代理指标全 0"的跑次同样可能撞车。下一步是决定未测量会话在 `score_run` 里算
   FAIL 还是 UNKNOWN（第 4.2 节），然后才谈 §12 第一条门槛。
5. **PATH_HOLD 已在实车生效**（2/52 帧，30 次已验证 offer），但样本太小、且该跑次撞了车；
   它的收益（无意义停车降幅）要在**修掉碰撞与 stale 之后**用多轮同配置对照来量。
6. 所有开关保持默认关闭；本报告不改变任何默认值，也不据此重调阈值（单轮样本不足以标定）。
