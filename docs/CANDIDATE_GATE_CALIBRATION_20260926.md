# 候选口径门槛标定（2026-09-26，基于 136 帧权威人工真值集）

**依据**：方案 §10.2「改变候选匹配、参考覆盖或左右角色口径后，旧阈值不能未经校准直接
复用；在独立校准数据上定新值，冻结后再搜索。**不得为当前候选过门而调低阈值**」。

**校准数据**：`review_pack_20260926` 的 136 帧权威真值（8 个采集组；用户 2026-09-26
决定"按我标的作为权威"）。参考来自**数据集自己的 `label == 2`**（人工真值），
与训练标签无关。探针：`m5_marking_identity_probe`（投影候选匹配）。
可复现命令与原始 JSON 见文末。

## 2. 三条标定结论（写进协议 v4）

1. **覆盖率的分母必须限定在"有标线参考的场景/帧"**：无标线场景（人确认无线）
   没有参考，覆盖率**天然为 0**——那不是模型的问题，是评价集没有参考。若按全部场景
   算，任何模型都会永久失败。→ 定义：`candidate_reference_coverage` = 有参考帧上的
   有参考候选 / 该帧集产生的全部候选。
   **门槛 0.80**（要求驱动：至少 4/5 的候选必须"有参考可判"，否则身份指标只覆盖少数
   候选、结论不可用）。实测 0.890–0.916 → 通过但留有余量；**没有**按当前值下调。
2. **身份率门槛维持 0.60（协议原值，不改）**：实测两个模型都是 **0.31**（逐场景
   0.095–0.783）→ **按现口径两个模型都不该晋级**。这正是"不得为过门调低"的落点：
   校准不是为了放行，而是把"未标定"换成"实测不合格"。
3. **左右角色一致率：门槛 0.70**（要求驱动：角色混淆超过 30% 时左右身份不足以支撑
   横向参考）。实测 0.743–0.746 → 通过。
4. **逐场景判身份的样本量下限：≥30 条候选**（要求驱动：低于 30 条时 p=0.5 的 95%
   区间宽约 ±0.18，单场景结论不稳）。实测有参考场景的候选数 30–377，最小 30 →
   刚好落在门槛上，说明这个下限是"够用但不高"的选择；不足 30 条的场景记
   `needs_evidence`（不进硬门，也不当通过）。

## 3. 与旧口径的关系

* 旧 `candidate_identity_rate`（G09 之前的原始 `match_rate`）分母含"该侧无参考"的
  候选；新口径把参考覆盖拆出来单列。**旧判定不能与新口径混比**（协议哈希已变）。
* `COVERAGE_GATE_FROZEN` 由 `False` 翻为 `True`：覆盖率不再是"未标定阻止晋级"，
  而是有实测依据的**硬门**（≥0.80）。
* 影响：两个现役模型在新的覆盖率门上是**通过**的（0.89/0.92），但在身份率门
  （0.60）上**不通过**（0.31）→ 晋级仍被挡，理由从"未标定"变成"实测不合格"。

## 4. 局限

* 校准集 136 帧 / 8 组、单复核人（用户已决定按权威使用）、**未做一致性验证**；
* 参考是人工真值，所以这里的"匹配"以复核人的画线口径为准；
* 两个模型训练数据不同（生产含土路素材 1883 帧/60 epoch；候选 20 帧/24 epoch），
  本表**不是受控对照**，只用于标定门槛分布；
* 有参考场景的候选数最小 30（corner），该场景的身份率（0.33/0.35）区间较宽。
