# T14 后台自主迭代训练实施方案（2026-09-24）

## 目标与边界

在本机后台持续运行一个**标线与铺装路面感知模型实验循环**：发现错误场景、取得可靠标签、生成候选模型、用固定指标淘汰或晋级、保存可复现证据，并让人能看见每一步的学习与失败原因。首期只改感知候选模型，不让候选模型自动取得车辆控制权。端到端驾驶模型留到感知与闭环评价可信后再纳入。

“自主迭代”的含义是神经网络通过反向传播更新权重，外层控制器自动选择数据/配方、评估和淘汰。仅重复调用训练脚本不算完成。**自动运行不保证模型必然持续变好**：没有可用的独立标签或改善证据时，循环应停下并报告缺口，而不是自称成功。失败样本可以进入待标注队列，但不能把模型自己的预测直接当真值反复训练。

### 先纠正数据前提

`m5_collect_seg_ring.py` 的实测说明：Tech annotation 在当前地图提供密集路面类别，但可见漆画线常被渲染成 `ASPHALT`；一个有大量白线像素的画面曾只有 3 个 `SOLID_LINE` annotation 像素。因此“有 Tech annotation”**不能直接推断“标线标签可靠”**。采集器本身也把 line class 不可用写进 `label_source`。路面和标线分别做标签审计；标线有人工修订且记录来源，或经单独验证的模拟器真值时才进入有监督训练/最终评估。未覆盖的漆画线区域不能默认为背景负例，应标成 ignore/UNKNOWN 或排除该样本的标线损失与指标。`scripts/m5_inject_yellow_labels.py` 的 HSV 注入属于伪标签，只能进独立研究臂，不能当最终真值。铺装/土肩也要独立确认，不把“road 类”自动等同“可行驶铺装”。

## 已有基础与关键缺口

| 环节 | 现有能力 | T14 缺口 |
| --- | --- | --- |
| 数据 | `m5_collect_seg_ring.py` 可从 Tech 采集路面 annotation；`m5_annotate_manual.py` 可修订标线；`dataset_split.py` 可做泄漏审计与困难样本筛选 | 区分 road/paint 真值质量、主动标注队列、自动场景队列、数据版本不可变 |

| 评估 | `m5_eval_seg.py`、`m5_seg_stage_eval.py`、`m5_marking_identity_probe.py` | 固定开发集/最终集职责、成对比较、自动硬门槛、生产时延与闭环门槛 |
| 可视化 | 训练入口会保存 `curve.png` 和 `train_hist.json`；T13 有多 seed 结果 | 缺实时进度、数据/标签审计、固定图像预测与错误热图、晋级理由、资源与异常视图 |
| 循环 | `m5_pipeline.py` 能串采集/训练/回放 | 该脚本面向 E2E，不用于 T14 标线模型；缺少不可变候选和晋级门 |

T13 的 50 帧测试集已经被用于选择与分析，今后只能作为**开发诊断集**；重新采集并冻结不参与开发的新最终集。T13 的 A/B 三 seed 标线 IoU 差值均值约 +0.030，样本少且波动大，不能据此宣布“增加场景数据必定无效”。T13 候选层只比较了不同 seed 的两个模型，也不能当成数据因子的成对结论。

## 交付架构

```
Tech RGB/annotation + 人工漆线修订或经验证的漆线真值
        ↓  来源、内容哈希、逐类别标签审计、泄漏审计
不可变数据版本 ──→ 训练集 + 开发集；独立最终集只用一次
        ↓
错误挖掘与待标注队列（只从训练/开发集产生）
        ↓
实验提议器（一个因子、相同基线与成对 seed）
        ↓
SegUNet 反向传播训练（独立目录、检查点、可续训）
        ↓
逐 epoch 事件 → 只读学习看板 + 固定图像预测对照
        ↓
像素/候选身份/几何/延迟分层评估 → 自动淘汰或影子候选
        ↓
经独立 Tech 闭环门槛后人工确认部署
```

后台控制器放在 `beamng_autopilot/` 内，入口放在 `scripts/`。建议新增 `beamng_autopilot/experiments/` 保存数据版本、任务状态机、资源门控、晋级判定与事件协议；`scripts/m5_seg_autoloop.py` 只解析配置并调用库。只读看板也从 `scripts/` 启动，读取实验事件与固定探针产物，不给驾驶进程另起命令协议。复用现有训练、采集与评估脚本，不复制模型或指标实现。配置中必须有 `collect=off|tech`、每日 GPU 时长上限、时间窗口、显存余量、最大候选数、数据集路径、`dry_run`；默认 `collect=off`，因为是否允许后台启动游戏尚未确定。

## 神经网络学习流程（每轮的输入、输出与门槛）

### 1. 建立可靠监督信号

- **输入**：Tech 同次曝光 RGB/annotation、采集元数据，以及经人工修订或单独验证的漆线标签。基线模型仅用于排查/预填，不能成为自己的监督真值。
- **输出**：逐帧、逐类别质量标记（`road_valid`、`paint_valid`、`pavement_valid`、`unknown_reason`）、有效像素掩码、来源与内容哈希。标线真值缺失时，该帧可以贡献可信路面损失，但不得把未标出的可见漆线当作负例；必要时整个标线通道忽略。
- **准入门**：缺 RGB/annotation 对齐、0 帧视角、错误地图身份、低质量 palette、重复内容、不可判定的漆线真值或已被别的集合消费，均隔离并说明原因。抽样人工复核“有线、无线、道路边缘、土肩”正反例；记录每类有效帧/像素与 UNKNOWN。不能由 `line_pixels > 0` 单独证明标签完整。

### 2. 版本化与划分

- 不可变 `dataset_id` 由帧内容、逐类别标签、元数据和划分清单的哈希生成。训练/开发/最终集按完整地图路段或采集组隔离；同一路段的相邻帧、同次曝光多视角和字节复制不能跨集合。现有 `--split by-map-scene` 实际会在组内取时间尾部做验证，不能把“共享组 6”写成组隔离；T14 要增加真正的整组隔离方案与独立审计。
- T13 已查看的 50 帧转为开发诊断集。新的最终集在实验开始前封存，含路口、弯道、退化标线、无标线、土肩与不同铺装材质，并验证每类真值。每次配方搜索只看开发集；最终集仅给冻结配方做一次确认。若最终集失败，下轮研究使用新的独立集，不反复调到旧集通过。

### 3. 错误挖掘与主动标注

- 在**训练/开发集**运行当前 champion，输出路外假线、真实线漏检、错把边缘/阴影当线、候选左右角色错、铺装/土肩错的样本清单。`m5_eval_seg.py --hard-neg-out` 和 `m5_marking_identity_probe.py` 可提供部分排序信号；只在标签可验证的区域计算错误。
- 以场景覆盖和不确定性选样，限制同一地点连续帧占比，保留无线负例。缺标线真值的高价值帧进入 `needs_review`，由 `m5_annotate_manual.py` 或经验证的模拟器真值补齐后才入训练。看板显示“待复核/已通过/被拒绝”数量与具体原因；无人复核且无可验证新样本时，循环暂停数据迭代。

### 4. 实验提议与训练

- 首期固定 `SegUNet`、输入 536×403、三类输出和生产后处理；优先试**数据质量/场景配比**，再依次试困难样本采样、损失权重、训练轮次。一次实验只改一个因子；相同初值、划分、增强、评估入口和成对 seed（至少 3 个）。数据臂增加帧数时同时报告总优化步数，并做等步数对照，避免把训练更久误认为数据更好。
- 每个候选在独立目录反向传播训练：前向 logits → 与有效标签计算 CE/Tversky/clDice 损失 → 反向传播 → Adam 更新 → 开发验证。对缺真值类别用有效像素掩码；先用小数据验证这一掩码在**所有损失项和指标**上都生效，否则不允许混合部分标签数据。`checkpoint_last.pt` 负责恢复，`best.pt` 仅表示脚本按开发 mIoU 选的权重，**不是驾驶任务最优**；保存所有被任务评估的 epoch，按预先固定的下游指标和硬门槛重选候选。
- 一个 `candidate_id` 固定配置、git commit、数据/初值哈希、seed、Python/Torch/CUDA、命令、每 epoch 数据量、优化步数和随机状态。若现有 checkpoint 未保存恢复所需全部随机状态或数据版本，先补齐并验证“中断续训≈未中断”再宣称可复现。异常处理：NaN/标签污染立即失败；OOM 允许一次降 batch 后**生成新配方 ID**；无条件重复重启禁止。

### 5. 分层评估与自动决策

- **像素层**：按全局和每地图/场景计算 road/line IoU、precision/recall、近场漏线、路外假线与土肩误入铺装；只统计有对应真值的像素并报有效覆盖率。不要用 mIoU 或训练 loss 单独选模型。
- **候选与几何层**：固定同一生产后处理和候选提取路径，比较漆线身份确认率、左右角色、零假设对照、路外候选占比、成对率与本车道中心；有独立投影/几何标签才报米制误差，否则记 UNKNOWN。`raw→morph→road constraint→full_predict` 必须一致，且新候选真实到达最终横向参考链。
- **性能层**：同一硬件、同一输入尺寸比较预处理/推理/后处理 p50/p95、GPU 显存与完整驾驶 tick deadline。离线 p95 不等于 Tech 闭环 p95。
- 自动选择预先声明的主任务指标，并对路外假线、铺装误判、候选身份、延迟设**事前冻结**的非劣门槛。每个成对 seed 和场景给出差值、分布及不确定性；有 UNKNOWN、指标定义漂移、production mismatch 或硬门槛违反时为 `rejected`/`needs_evidence`。小预算预筛可淘汰，不能晋级；完整 seed 评估通过后只标记 `shadow_candidate`，不覆盖生产模型。

### 6. 最终验证与回流

- 配方冻结后对新的独立最终集只测一次，再用 Tech `--runtime tech`、带 `--goal X Y` 的影子和短程闭环验证新源被消费、控制权唯一、车身不压线、不出铺装、不碰撞、strict 不倒车、完整 tick deadline。右边界信任顺序仍为标线优先，其次真实感知的路面边界/护墙/围栏；无可信边界时停。导航只给路线，不能用路线加固定偏移做横向定位。
- 失败时保留失败样本和权重，分类原因后进入**下一轮训练/开发数据池**，绝不回流最终集或自动改生产默认权重。连续预设轮数无可信收益、标签不足、计算预算耗尽或数据分布异常时停止搜索并报告原因。实际生产模型切换需人工确认，并保留上一版本与回滚命令。

## 学习过程可视化：T14 必交付，不是可选截图

看板须在后台训练时刷新，训练结束后可离线重放同一 `candidate_id`；它**只读实验产物**，关闭看板不影响训练。先复用 `train_hist.json` 导入 T13 六个 run 作为历史验收样例，再让 T14 从结构化事件增量更新。画面必须区分“训练中”“开发集测得”“最终集一次确认”“Tech 闭环未测”，不得把开发曲线画成最终安全成绩。

| 视图 | 必须显示 | 更新时机与防误读要求 |
| --- | --- | --- |
| 运行总览 | 当前 `run_id/candidate_id`、状态、数据/配置/模型哈希、seed、epoch/总数、已训练步数、耗时、下一步、停止/失败原因 | 状态从事件流读取；中断重启后同一 run 续接，不伪造已完成 epoch |
| 学习曲线 | train/val loss **分图或同量纲**，开发集 line/road IoU 与 precision/recall，学习率、梯度/AMP 异常；逐 seed 曲线 | 原始值和缺失点都保留；不同指标不可共用一个无说明的纵轴；可指向对应 checkpoint |
| 固定探针图像 | 同一组版本锁定的 RGB、可信标签、预测掩码、FP/FN 错误图，标出当前候选与 champion；按路口、弯道、退化线、无线、土肩切换 | 每 N epoch 或 checkpoint 生成，图像和标签哈希固定；无真值区域灰显 UNKNOWN；预测颜色不覆盖原图细节 |
| 候选任务结果 | 漆线身份、左右角色、零假设、路外候选比例、成对率、本车道中心/米制误差（若有独立真值） | 展示分子/分母及每场景差异；不能只显示总体均值。错误候选可回查原始帧、候选像素、被采用的横向源 |
| 实验对比 | champion 与候选的成对 seed 差值、场景覆盖、置信区间或原始分布、非劣门槛、晋级/淘汰理由 | 基线与候选必须共用同一开发集/生产后处理；最终集结果只在冻结确认后显示，不参与搜索排序 |
| 数据与标签 | 每地图/场景/视角帧数、有效标线/路面/铺装像素、重复/泄漏/UNKNOWN、待复核队列与被拒原因 | 新数据进入训练前后显示版本 ID 和帧数差；“有 Tech annotation 但无可靠标线真值”单独计数 |
| 资源与闭环 | GPU 显存/占用、训练速度、每轮耗时、推理 p50/p95；Tech 验证时显示新源刷新/消费、最终命令、deadline、压线/出铺装/碰撞/停车原因 | 历史资源可重放；没有 Tech run 时闭环字段明确写“未测”，不能显示 0 事故 |

### 事件与图像协议

- 控制器、训练入口和评估器往 `logs/experiments/<run_id>/events.jsonl` 追加结构化事件；每条至少有 `schema_version`、`run_id`、`candidate_id`、`dataset_id`、`config_hash`、`seed`、`phase`、`status`、UTC 时间、`epoch`/`step`（适用时）、指标名/值/单位/分子/分母及缺失原因。状态枚举：`queued → auditing → needs_review|training → evaluating → rejected|shadow_candidate|needs_evidence → final_testing → approved_for_review|rejected`，异常还有 `paused`、`failed`。事件必须带单调序号；写入可恢复，半写行可识别，重启后不重复画点。
- 固定探针图像放在 `logs/experiments/<run_id>/probes/<checkpoint_id>/`，旁边清单记录帧内容哈希、标签来源、模型权重哈希、后处理配置和图像生成时间。每轮最多保存固定数量，避免 12 GB GPU 机器旁边无限增长磁盘；原始数据不复制到看板目录。可选显示中间特征图/显著性，但只能作为模型诊断，不能当正确性证明。
- 看板不向 autopilot 发控制命令。若以后从 GUI 控制驾驶，仍使用已有 `ControlBridge`；实验控制从 CLI/任务计划启动，不另造驾驶命令协议。看板有“导出本轮证据包”，包含版本、曲线、固定探针、指标、异常与八项报告所需字段；只有实际存在的测量才可导出为数值。

### 可视化验收案例

1. 导入 T13 六个 `train_hist.json`，能按 seed 显示 3 个 epoch 的 loss/开发 line IoU，并单独显示冻结集最终结果；同 seed 的 A/B 差异可见，不能把训练 loss 下降标成安全提升。
2. 模拟第 2 epoch 断电并恢复：界面只出现一次第 2 epoch，`run_id`、数据版本与 checkpoint 继续一致；断点前后曲线不跳成另一个模型。
3. 构造“标线标签缺失但 RGB 有白线”“路外假线”“土肩被预测成路”“预测全背景”四个确定性样例：显示真值有效区、FP/FN 或 UNKNOWN 与淘汰理由；缺标签不得显示漂亮的 IoU。
4. 构造推理 p95 超限和闭环尚未运行：资源视图显示超限，晋级视图给 `rejected`/`needs_evidence`，闭环事件显示“未测”。

## 后台运行规则

- Windows 任务计划程序只负责在配置的空闲时间启动/恢复控制器；控制器自身持有单实例锁，支持正常退出、断电恢复、磁盘空间门槛、每日 GPU 时间上限、最大连续运行时长和温度/显存监测。先以 `--once --dry-run` 验证将执行的命令与数据流，再允许常驻模式。学习看板不占训练 GPU，不阻塞训练。
- `collect=off` 时只使用已存在且有独立标签的数据。`collect=tech` 只有在明确允许后才启动 Tech；采集前检查当前是否有驾驶会话，采集时不得争抢控制权。优先用 annotation 与定点/步进采集，不让实验模型控制车。
- 运行产物均写入 `logs/`，权重留在 `weights/` 或 `logs/`；不提交运行产物。代码与测试按 AGENTS.md 模块边界分提交。异常、预算耗尽、数据不足或连续无收益时控制器停止并给出明确原因，不能静默重试无限循环。每次任务保存退出码和最后完整事件；意外退出不自动标记为训练完成。

| 0 冻结协议 | `docs/` 中的基线与指标配置；生产权重/配方哈希；T13 历史导入 | 先用固定样本核对生产、v13b、T13 候选的像素/候选/性能口径；预先写定主指标、非劣阈值、预算和最终集使用规则 |

| B 训练与恢复 | 训练事件接入、完整 checkpoint、唯一候选目录、锁与资源门 | 训练会真实更新权重；固定小样本可过拟合以证明梯度链；中断续训结果与未中断在预设容差内；OOM/NaN/预算耗尽状态可复现 |
| C 学习看板 | 只读脚本/视图、事件协议、固定图像探针、T13 导入器 | 上述 4 个可视化案例全通过；关掉看板训练继续；缺列与 UNKNOWN 不被画成 0；可导出证据包 |
| D 自动搜索 | 错误分桶、有限实验提议、成对 seed 评估、硬门槛判定 | 连续至少 3 轮可无人值守运行；至少包含一次净负收益自动淘汰；相同输入重放得到相同决策与淘汰理由 |
| E 新数据闭环 | 经授权的 Tech 场景队列、annotation 采集、漆线复核队列 | 新标注内容哈希真实进入下一版本训练；无可靠漆线标签时自动进入复核队列或停止；空采集不会被当成成功 |
| F 驾驶晋级 | 独立最终集、影子/短程 Tech 门槛、版本登记与回滚 | 八项评审证据齐全，最终控制链硬约束生效，才提出人工确认部署；失败不影响生产权重 |

初始模型仍用现有 `SegUNet`，初始训练配方以 T13 记录为**可复现对照**，不把 T13 的 `best.pt` 直接视为新 champion。阶段 0 应把优化目标按优先级冻结：① 可验证的本车道漆线身份/几何与右侧边界来源，② 漏线及路外假线，③ 铺装/土肩，④ 延迟和资源；像素 IoU 是训练诊断与辅助门槛。阈值先在基线与开发数据上定并写入版本化配置，搜索开始后不随候选成绩改动。若 3 seed/有限场景结论含糊，追加 seed/独立场景或标 `needs_evidence`，不能取单个最优 seed 晋级。

离线逻辑改动至少运行 `.venv\Scripts\python.exe -m pytest tests/ -q` 与 `.venv\Scripts\python.exe scripts\m5_offline_validate.py`。测试覆盖缺标签仍有可见漆线、部分标签损失屏蔽、内容重复、跨视角/近邻泄漏、训练与最终集串用、并发锁、中断恢复、负收益淘汰、缺列门槛、图像探针同帧对齐与事件重放。涉及游戏的 E/F 默认 Tech 实测；未跑的项目明确写“未测”。提交按 `beamng_autopilot/<子包>`、`scripts/`、`tests/`、`docs/` 分开，每个提交自身可通过 `pytest tests/`；推送前运行 `scripts/check_commit_scope.py`。

## 每轮报告模板

每条结论按“原假设 → 是否真正激活 → 可复现输入 → 实测结果 → 支持/推翻的结论 → 未知与下一步”填写。另附八项：① commit/config/run 与无控制权冲突；② 覆盖率、缺列和 UNKNOWN；③ 强制刷新与新源消费；④ 几何正反例和最终控制链；⑤ 路面门真阳性、漏检、误停；⑥ 性能分解和 deadline；⑦ 碰撞、压线、出铺装、分类停车时长；⑧ 通过、失败、未测。离线阶段对闭环项填“未测”，不能写“安全通过”。

## 尚待用户指定的运行参数

1. 是否允许无人值守时自动启动 BeamNG.tech 采集，还是仅使用现有数据。
2. 空闲时间窗口、每日 GPU 时间上限，以及用户使用电脑时是否立即暂停。

在这两项确定前，执行者可以完成阶段 A/B 和离线 `--dry-run`，但不要启动后台采集或常驻训练任务。
