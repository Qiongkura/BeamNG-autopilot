# 标线检测链路优化验证（2026-09-12）

## 范围与结论

本次是在当前未提交工作区（包含已有时序证据实现）上修复链路，不是相对 Git HEAD 重写感知。
模型权重、细线过滤、虚线恢复算法、车道配对安全门、规划与地图逻辑均未改变。
没有新增 Steam / 经典 CV 能力；保留已有兼容回退。没有使用导航或地图横向偏移。

固定城镇录像上的双边配对小幅增加，不能宣称已经解决全部丢线。

## 实际改动

- `vision/segmentation.py`：`detect_lines(..., line_mask=...)` 可直接消费已有掩码；
  显式空掩码也不重复推理，尺寸错误明确报错。旧调用仍自行推理一次。
  新增 `reset()` 清除图像滞回状态。
- `vision/heads/semantic.py`：同一前视帧只调用一次 `predict()`，融合后的掩码同时
  提供给 mask 消费者及几何/虚线提取。推理异常不重放历史证据，保留已有 CV 回退；
  记录原始像素数、历史新增像素数及阶段错误到 TaskOutput.meta。
- `vision/line_evidence.py`：每个世界网格单元每个观测时间戳至多一票，避免单帧密集
  像素直接达到多帧确认门槛。重复时间戳不加票，时间倒退重置历史，非法时间戳报错，
  忽略非有限投影点，空支持点集固定为 `(0, 2)`。
- `vision/hydra.py`：FrameContext 追加可选 `timestamp`（秒），旧实时调用仍默认
  使用 monotonic 时钟。
- `scripts/m5_seg_task_eval.py`、`scripts/m5_lane_continuity.py`：录像逐集重置，使用
  录制时间而不是离线处理速度计算证据衰减。
- `tests/test_semantic_line_pipeline.py`、`tests/test_line_evidence.py`：新增针对单次
  推理、融合输入、故障回退、时间/状态隔离及证据计数的回归覆盖。

## Tech annotation 实机复核（2026-09-12）

重启无响应的 BeamNG.tech 会话后，完成了一批实际采集：

- `logs/m5_seg/run_tech_ann_20260912_160000`：4 段 / 320 帧，标线像素总量
  8317，平均 26 px/帧，177 帧含标线。
- 复核发现静态兼容调色板会把当前 italy 会话的天空色 `(128,196,255)`
  误标成路面。现在采集器在会话开始时读取 `bng.get_annotations()`，按
  `ASPHALT` / `STREET` / 标线类别解析活动调色板，并将版本与完整类别映射写入
  `meta.json`；annotation 仍只用于训练和离线评测，不进入驾驶控制链。
- 修复后的验证批次 `logs/m5_seg/run_tech_ann_20260912_161500`：20 帧，平均
  路面标签 54257 px/帧、标线标签 26 px/帧；元数据记录
  `palette_version=beamng_get_annotations_v1`、`palette_source=beamng_get_annotations`。
