# W3 持续运行验收：4 小时窗口签收报告（2026-09-26）

**范围**：方案 §8.2 第三步「受监督观察通过后做 8 小时持续运行验收」。
**本次窗口**：用户指定的 **4 小时**（13:44–17:40:52）；**方案原条款的 8 小时未跑**，
见 §6 结论与偏差。本次不涉及驾驶/Tech（W7 前置 R2 未达成）。

## 1. 跑的是什么

监督器 `scripts/soak_runner.ps1`（方案 §8.2："常驻入口由调度器唤起**同一入口**；
互斥和恢复由库负责"）：

| 项 | 设置 |
| --- | --- |
| 每轮 | **一个新 run** + **一个不同的单因子提议**（19 个：数据组成 17 + 线损失 2） |
| 训练 | agent 档池子、road-only 研究档、3 seed、24 epoch、等步数、`collect=off` |
| 单轮上限 | `max_wall_minutes=45`（实测每轮远低于此）；轮间隔 60 s |
| 互斥 | 每轮独立获取/释放 run 锁 + 机器级租约；GPU 账本逐轮结算 |

## 3. 这次窗口证明了什么

* **无人值守链路能连续跑 4 小时**：56 次进程级唤起、47 轮真实训练+评价+判定，零崩溃、
  零卡死、零孤儿、零计时污染。
* **资源与互斥保护真的生效**：见 §4——磁盘不足时入口**拒绝训练**（rc=5）而不是带病跑。
* **判定链在真环境里被压了 47 次**：v3 协议快照、逐 seed/分场景硬门、覆盖率门槛拦截、
  `research_only` 强制、缺测不当违反——都在真数据上走通。

**不能证明**：任何模型质量（全 inconclusive、road-only、研究档）、完整驾驶 tick
deadline、8 小时稳定性。

## 4. 记录在案的偏差：磁盘被验收自身写满（9 轮被拦）

* **现象**：第 45–53 轮全部 `rc=5`、每轮 0.05 min；`resource_state.json` 写明
  `free disk 4.6 GB < 5.0 GB`。
* **原因**：验收自身产物累计 **24.96 GB**，其中 **6336 个 `epoch_*.pt`**
  （`--save-every-epoch` × 24 epoch × 3 seed × 2 臂 × 44 轮）。磁盘从 29.9 GB 掉到 4.59 GB。
* **门的行为是对的**：入口按配置的磁盘余量**拒绝启动训练**，没有带病继续写。
* **处置**：清理 `epoch_*.pt`（保留每轮 `checkpoint_last.pt`/`best.pt`/判定/日志）
  释放 **19.96 GB** → 第 54 轮起训练恢复（rc=0），窗口跑满 4.0 h。
* **代码修复（本次一并提交）**：监督器每轮结束自动清理该轮 `epoch_*.pt`
  （`-KeepEpochCheckpoints` 可关），并打印释放量——同一事故不会重演。
