# 项目长远开发计划（2026-11-04）

> 基于本会话全部证据：训练侧 15 个变量证伪、四图锚点耗尽、SSL 双种子集成
> 0.539246（部署路径可复现）、条件矩阵三场景无驾驶格、live 贴花参考被地图
> 标线污染。计划按"证据驱动 + 外部依赖"排序，不做无数据的空转。

## 总体判断

1. **当前瓶颈不是训练技巧，是数据多样性与场景可控性。**
   弱折 A（逐帧 IoU 0.16–0.21）的根因是线稀疏/短/断（与线像素密度单调相关），
   继续调参已被 15 个变量证伪。
2. **部署侧已有可交付物**：双模型集成 +0.0107~+4.7%（相对单种子）、
   1.55× 时延、3.4MB 显存、fail-closed 正确；缺的是 live 侧可信验证与
   默认化授权。
3. **整车主线的驾驶级验证在现有环境不可推进**：需要无标线路段/新地图
   或部署域感知数据。

## 阶段计划

### Phase 0（现在–2 周，无需外部资源）：固化与交付

- **P0.1 部署硬化**：集成默认化的 live 安全/性能审计预案（放置/驾驶链路、
  时延分布、fail-closed 注入、回退路径）；用户授权后再改默认。
- **P0.2 回归与文档**：把本会话的诊断链（渲染门、回放、错误归因）固化为
  可重复的回归套件；整理方法学文档（SSL、集成、评测协议、负结果）。
- **P0.3 监控**：live 运行记录（时延、感知可用率、fail-close 原因）纳入
  证据归档，作为默认化决策依据。
- 交付标准：全部可复现、测试通过、默认行为不变。

### Phase 1（需数据授权，3–6 周）：部署域数据与域适应

- **P1.1 数据来源**（用户提供其一）：真实相机域公开数据集（带标注）、
  或 town 类引擎标注数据。
- **P1.2 域混练**：与现有 71 族池混练/域适应；新增**留出族**（绝不与训练
  重叠）建立第二个固定评测集。
- **P1.3 目标**：弱折 A 类场景 +0.05 以上；town 类配对可用率从 ~0 提升到
  可放置（≥50%），并保持四折不回归。
- 失败条件：若域混练无增益，记录为负结果，不降门。

### Phase 2（需新地图/程序化路段，4–8 周）：规模与场景可控性

- **P2.1 新地图档案**：材质扫描 + 锚点自动扫描（沿用现有 `MAP_PROFILES`
  与采集器）。
- **P2.2 程序化无标线路段**：为 live 贴花参考提供"唯一漆源"（解决五锚点
  全部被地图标线污染的问题，恢复条件矩阵的驾驶级验证）。
- **P2.3 目标**：池 ≥200 族 / ≥6 图；条件矩阵可产出驾驶格；live 右线
  指标可归因。

### Phase 3（随 Phase 1/2 数据到位）：训练与架构前沿

- 线专用架构与损失（细线感知：clDice/Tversky、多尺度、条带卷积），
  更高分辨率裁片训练；SSL 在新地图无标签帧上扩量。
- **晋级门槛**：固定折 + 新留出族 + 配对种子，宏平均 +≥2pp 且无单折退步
  >0.5pp；随后走部署审计（时延/显存/fail-closed）。
- 任何不满足门槛的方案只作为研究资产，不晋级。

### Phase 4（Phase 2 之后）：整车条件与安全验证

- 条件矩阵：TOD×天气 12 格 × 重复，产出条件×表现表（车道可用率、
  fail-close 率、完成度、安全计数）。
- 250s 长跑、车道穿越计数可信化（UNKNOWN 清零）、交通场景。
- 安全验收：fail-closed 行为、最小风险状态、时延预算。

### Phase 5（长期）：实车迁移与产品化

- 相机标定/时延补偿/执行器适配；冗余与接管策略；
- 版本化发布流程（数据版本、模型版本、评测报告、证据归档）；
- 合规与软著/文档资产维护（已产出的申请材料可随版本更新）。

## 依赖与决策点

| 决策 | 需要谁 | 影响 |
| --- | --- | --- |
| 集成默认化 | 用户确认 + live 审计 | 默认驾驶行为变更（时延 1.55×） |
| 加权实验 W1/W2 | 用户授权 | 仅探索性；测试折调参，不晋级 |
| 部署域数据/新地图 | 用户/外部资源 | 解阻 Phase 1/2/3/4 |

## 纪束（贯穿全部阶段）

不降门、不消费最终集、不新增人工标注、不晋级未过门槛的模型；
每批实验预注册、失败证据保留、全部产物哈希归档。
