### 结论 3：『中断续训 = 未中断』**已逐位验证**；GPU 上的差异是内核非确定性，且我先前的实验设计是错的 → **支持（已修复）**

三个阶段、按时间顺序如实记录：

1. **GPU 上的两次比较都不同**（`logs/experiments/t14_phaseB2/`）：A vs A2（同配置两次未中断）n_diff 92/106、max 1.08e-01；A vs B（2+续训）n_diff 92/106、max 5.58e-01。
2. **定位到"内核不确定"这条路**：加 `--deterministic`（`cudnn.deterministic` + `use_deterministic_algorithms` + `CUBLAS_WORKSPACE_CONFIG`）后在 CUDA 上直接报错——**PyTorch 没有 `nll_loss2d` 的确定性实现**，而它正是本项目的交叉熵损失。于是加 `--device`，在 **CPU 的确定内核**上做决定性检验：同配置两次未中断 **n_diff = 0 / max = 0.0**（说明 pipeline 与 `--deterministic` 有效），但"未中断 vs 2+续训"仍 n_diff 92/106。
3. **差异的真正来源是我的实验设计，不是漏状态**：续训那一轮的 `lr` 实测是 **0**（未中断是 5e-4），因为调度器的 `T_max` 取自**本次调用的 `--epochs`**——我让前半段 `--epochs 1`、续训 `--epochs 2`，那是**换配方**而不是中断。加 `--stop-after N`（按同样的 `--epochs` 建调度器、只跑到第 N 轮退出）重做后：

   | 比较（CPU + `--deterministic`，`--epochs 3` 不变） | n_diff | max_abs_diff | 结论 |
   | --- | --- | --- | --- |
   | A vs A2（同配置两次未中断） | **0** | 0.0 | 逐位一致 |
   | A vs B（未中断 vs `--stop-after 2` + 续训） | **0** | 0.0 | **中断续训 = 未中断** |

   续训轮与未中断轮的 loss 也完全相同（2.5748 / 2.4127）。

- **结论**：checkpoint 的往返**无损**（A@ep0 与 B 载入态 n_diff=0），随机状态/数据版本/优化器/调度器/BN 缓冲都恢复正确；**"可复现"这一条现在可以声称**，但必须带上适用域：逐位可复现只在 `--device cpu --deterministic` 下成立；CUDA 上因为 `nll_loss2d` 无确定性实现，改用**实测容差**——见下面第 4 点（3 seed、AMP、比值 0.88、判据 1e-2 相对差）。
- **已固化为测试**：`tests/test_seg_resume.py`（3 例：续训=未中断逐位一致、同配置两次一致、`--stop-after` 不改 LR 计划），并把"改 `--epochs` 不是中断"这条坑写进测试文档串。
- **GPU 上的容差已量化**（`scripts/m5_seg_resume_tolerance.py`，AMP + CUDA、3 seed、2 轮中断→3 轮，`--epochs` 全程不变）：

  | seed | 控制组 max_abs / max_rel | 续训组 max_abs / max_rel | n_diff |
  | --- | --- | --- | --- |
  | 42 | 3.909e-02 / 3.257e-03 | 3.448e-02 / 2.873e-03 | 92/106 |
  | 43 | 1.441e-03 / 1.201e-04 | 1.627e-02 / 1.356e-03 | 92/106 |
  | 44 | 3.762e-03 / 3.135e-04 | 2.346e-04 / 1.955e-05 | 92/106 |

  **比值 resume/control = 0.88** —— 续训差异**完全落在"同配置跑两次"的噪声带内**，而且两边都作用在**同一批张量**（92/106，BatchNorm 缓冲与偏置）。
  据此把判据冻结为 **相对差 ≤ 1e-2**（= 实测噪声 3.3e-3 的 3 倍余量），写入
  `docs/t14_thresholds_v2.json`（v1 的数值一字未改，只新增容差与来源；`config_hash` 由 `29a6f387201db6a4` 变为 `f350b13313baa9db`）,
  并由 `Thresholds.resume_within_tolerance()` 提供判定（附实测来源）。
- **新增防护**：阈值加载现在会**校验文件里的 `config_hash`**——手改一个阈值会被当场拒绝并提示开新版本（实测：改 `line_recall_min` → 报 "被改过"）。
- **未知**：`--deterministic` 对 GPU 训练速度的影响未测；容差是**这一张卡 + 这一版 torch/CUDA + 这批数据**上量的，换硬件/驱动应重测。

### 结论 4b：§4 的失败纪律已补齐（NaN / 标签污染立即失败）→ **支持**

方案 §4 写着"异常处理：NaN/标签污染立即失败"，但训练器**此前没有这道守卫**（实测：只有我自己加的梯度范数 None 化，
非有限损失会一路写进 checkpoint，而且"跑完 N 轮"看起来像成功）。现在：

* **逐 step 检查损失**：非有限即抛错，错误串带 epoch/step/lr，并走 `record_training_failure`
  写一条 `failed` 任务记录（看板不会停在上一次 `running`）；
* **加载数据时校验标签取值**：只允许 `0/1/2/255`，出现未定义类别立即失败并报出类别与文件，
  不静默当背景。

两条都用**故障注入**测过：`--line-weight nan`（第一步损失就非有限）与一帧写入类别 `7`；
测试断言退出码非零、`failed` 记录里含"非有限"/"标签污染"。**未知**：CUDA 上的真实 OOM 未注入测试（只有预算耗尽与数据缺失路径有回归）。

### 结论 4：判定语义修正（提案与判定的两处真缺陷）→ **支持**

1. **提议器在最高错误率桶缺少对应因子时会一路掉到最后的 `epochs` 族**（实测：`candidate_off_road` 94% 却没触发场景配比）→ 现在 `candidate_off_road` 也触发 `scene_mix`。
2. **判定把次要指标的 0 差异当成"分不出来"从而挡住晋级**，而方案要的是"次要指标非劣"→ 现在**主指标**要求 ≥1 项可信改善且不得可信变差，**辅助指标**（IoU 等）只要不超非劣余量；`inconclusive` 只报告不拦截。
   并补了一条反向测试：**只涨 IoU（辅助）不改主指标 → rejected**（方案原话：像素 IoU 是训练诊断与辅助门槛）。

### 结论 5：阶段 D 的"连续 3 轮无人值守"验收——**机制通过，数字无科学价值（如实说明）**

`rounds --rounds 3 --seeds 42 43 44` 一次命令跑完三轮，全程无人工干预，最后**自己停下**：

```
第 1/3 轮 scene_mix-...-r0 -> rejected（IoU [0.0, 0.0, 0.0024]，identity 0.0389）
第 2/3 轮 epochs-...-r1    -> rejected（IoU [0.0, 0.0, 0.0]，identity 0.0339）
第 3/3 轮 scene_mix-...-r2 -> rejected（IoU [0.0, 0.0, 0.0025]，identity 0.0279）
自动停止：['3 consecutive rounds without a credible gain (limit 3)']
```

产物：三个候选**各自一份事件流**（`candidates/<id>/events.jsonl`，都走完
`queued→auditing→training→evaluating→rejected` 的合法路径）、三个 `roundN_decision.json`
（含硬门槛实测值：`offroad_false_ratio` 0.313–0.616 远超 0.1、`candidate_identity_rate`
0.028–0.039 远低于 0.6）、循环级 `paused/stopped` 带我冻结的停止判据。

**必须说清的适用域**：这批数字**不能当作候选好坏的证据**——为了把三轮跑完，训练集只用
了 20 帧单一摆位（`ident_probe`），评估却在另一条路（`holdout_wide2`）上，
所以三方（含 champion）的 IoU 都≈0、身份率都≈3%，判定是"**全都不可用**"而不是"谁比谁好"。
本轮证明的是：**循环能多轮无人值守、能按冻结门槛自动淘汰、能按停止条件自行收工**；
要得到有科学价值的结论，应把 `--runs` 换回 173 帧基线并把 `--eval-runs` 换回同一分布的开发集。

**真实配方上的复跑**（`--runs` = 173 帧基线、`--eval-runs` = `holdout_wide2` + `holdout_lines2`，3 seed）：

| 轮 | 因子 | 候选 IoU（3 seed） | 身份率 | 判定 |
| --- | --- | --- | --- | --- |
| r0 | 对照（数据集组成键被白名单跳过） | 0.0005 / 0.45 / 0.0 | 7.8% | rejected |
| r1 | `--epochs 6` | 0.0 / 0.0 / 0.0 | 6.1% | rejected |
| r2 | 对照 | 0.4235 / 0.3575 / 0.0695 | 19.2% | rejected |

四点读数：① **同配方跨 seed 的方差极大**（0.0–0.45，另一轮 0.0–0.68），说明这个 3 轮微调预算下
**按 seed 会出现整条路 IoU=0 的灾难性失败**——T13 冻结集上 0.37–0.49 的稳定区间不能外推到别的路；
② `epochs 3→6` **没有改善**（三条 seed 全 0）；③ 身份率 6–19% 远低于 60% 门槛，三轮都被硬门槛拦下，
说明**身份**仍是瓶颈（与 T08/T13 一致）；④ 三轮全 rejected → 冻结的"连续无收益"规则把循环停下。

**过程中暴露并修掉的三个缺陷**（都有实测触发；第三条是本轮复跑才暴露的）：
1. **"轮"与"候选"的身份混用**：所有轮共用一个事件流时，第一轮 `rejected` 是终态，
   第二轮无法再进 `evaluating`（被状态机拒绝）。现在**每个候选一份事件流**，循环级事件留在父流。
2. **候选 id 必须逐轮唯一**：proposals 只有 2 条时第 3 轮复用了第 1 轮的 `candidate_id`，
   从而撞上已终结的事件流；现在 id 带轮号后缀（同一因子在下一轮再跑是**新候选**）。
3. **冠军没有跨轮持久化**：只在第 0 轮就地取自己的值，于是 `round1_decision.json` 的
   `champ` 是**空的**——第 1 轮起"净收益"这条判据根本没被比较过（只有硬门槛在拦）。
   现在冠军写进 `champion.json` 并逐轮读取；复验（2 轮×2 seed）后第 1 轮理由里出现了真正的
   配对比较：`champ [0.1425, 0.2138]` vs `cand [0.0, 0.6754]` → `line_iou: inconclusive
   (mean 0.15955)`。冠军与候选择 seed 数不一致时**取较小者比较并在日志里警告**，不静默对齐。

### 结论 6：单因子 A/B——把学习率从 3e-4 提到 1e-3 **没有净收益**（实测淘汰）

做法：两条臂**只差 `--lr`**（3e-4 vs 1e-3），其余全同（同一批 173 帧基线、同 `--epochs 3`、
同 `--batch 4`、同 seed 42/43/44、同 `--split tail`），在**同一批开发输入**上评（`holdout_wide2`
+ `holdout_lines2`，最终集不参与），走冻结门槛判定。

| 臂 | seed | IoU | precision | recall | 路外假线比 | 身份率 |
| --- | --- | --- | --- | --- | --- | --- |
| lr 3e-4（现行） | 42 / 43 / 44 | 0.0818 / 0.0298 / **0.2803** | 0.543 / 0.031 / 0.311 | 0.088 / 0.377 / 0.740 | 0.002 / 0.056 / 0.297 | 0.256 / 0.071 / 0.198 |

- 硬门槛违反 3 项：`candidate_identity_rate` 0.136 < 0.6、`line_recall` 0.276 < 0.7、`line_precision` 0.235 < 0.4；
- 成对比较**全部 inconclusive**：IoU 均值 +0.073、recall −0.125、precision −0.059、路外假线 −0.021（差值全在 seed 波动内）；
- `replay` 复算：**相同 1 / 不同 0**（判定可复现）。

两条读法：
1. **同一条臂内 seed 方差压倒一切**：候选臂 IoU 0.0 / **0.6107** / 0.001，现行臂 0.03–0.28。
   若只挑一个 seed，可以"证明"任何一边更好——这正是冻结协议要求"成对 seed + 门槛"的原因，
   也是**不能拿单次最好 seed 晋级**的实测证据。
2. **瓶颈仍不在步长**：身份率 6.5–27% 依旧远低于 60%，recall 均值反而比现行低 0.125。
   提高学习率没有带来数量级改善，与"数据/身份是瓶颈"的判断一致。

### 结论 7：身份率低的主因是"候选不在真线上"，不是匹配规则或参考稀疏

> **限定（见结论 12）**：本结论的分母含"候选所在侧**没有引擎参考**"的样本
> （三条路实测 102/268 未匹配候选属于这一类）。因此正确表述是"候选与引擎参考的几何
> 不符"；把它读成"候选是假线"需要一个**独立于引擎 line 类的漆线真值**，目前没有。

用已有探针产物（8 份 `ident_*.json`，2 条开发路 × 4 个模型，共 1055 个候选、870 个未匹配）
做归因。**先修了自己脚本的一个符号 bug**：横向距离若按绝对值算，"候选在左、引擎线在右"
的镜像位置会被算成 0 距（实测导致 88 个候选被误判成"贴近却没配上"）；真实匹配规则
`match_candidate` 用的是**带符号**的 `lat_m`，改回带符号后：

| 未匹配候选的归因 | 数量 | 占比 |
| --- | --- | --- |
| 离引擎漆线 ≥2 m（且帧内有漆线） | **766** | **88.0%** |
| 其中"**反侧/镜像**"（带符号距 ≥1 m、绝对距 <1 m） | 139 | （占未匹配 16.0%） |
| 贴近（<1 m）却没配上 → 规则/容差边界 | 21 | 2.4% |
| 帧内完全没有引擎线可参照 → 参考不可用 | 19 | 2.2% |

另外按帧内引擎漆线像素分层看匹配率：`1–200 px → 0.080`、`200–1000 → 0.149`、`>1000 → 0.194`
——**参考越密匹配越好，但最密的一层也只有 19%**，说明参考稀疏只是次要因素。

**口径修正（本轮第二次自查抓到的）**：我临时的分析脚本第一版把"铺装外"定义成
`on_road_frac < 0.5`，于是**落在漆线上的候选必然被判成"铺装外"**（漆线与路面是两个互斥类），
数字被系统性抬高。仓库工具的 `candidates_off_road` 用的是并集口径（漆线<0.5 **且** 路面<0.5），
本来就是对的——文档里原有的 70–94% 是工具的并集口径，没有被污染；被污染的是我的中间稿。
按并集重算：候选**铺装外 719/1055 = 68.2%**（旧口径 77.9% 里含 103 个其实在漆线上），
远距（≥2 m）候选 634 个中**铺装内错位 117、铺装外假线 517**。

**三条读法**：
1. **主因是候选错位**（88% 离任何真漆线 ≥2 m），这与"70–94% 的候选在铺装外"一致 →
   瓶颈在**候选提取 / 线通道的假线**，不在地图先验、不在匹配规则、也不在参考质量；
2. **镜像已被判定：不是几何/投影问题**（139 个逐个体检）：判据是候选**自己的像素**是否落在
   引擎漆线上——`on_line_frac ≥ 0.5` 且被投影到镜像位置才是"像素在漆线、投影错侧"这类几何缺陷；
   实测 **0 个**属于这一类，**139 个全是本就不在漆线上的假笔画**（镜像位置只是巧合）。
   所以投影符号目前**没有**被抓到缺陷，不需要去动几何；这 139 个应归入下面的假线问题。
3. **调参不会解决它**：结论 6 的 lr A/B 与本条一起说明——把学习率提高、把轮数加倍，
   都不会让候选跑到真线上去；要动的是**线通道的数据/候选门**。

### 结论 8：候选门"连 learned 候选也要求在自己路面区域内"——实现后**实测被否**

上一轮拆解指向"候选门对 learned-backed 候选无条件放行"，因此把它做成**默认关闭**的开关
（`BEAMNG_LINE_CAND_SURFACE_GATE`）并实测。两个发现，一个是逻辑陷阱、一个是实测否证：

1. **最直觉的写法是同义反复**：`learned_frac` 的定义就是"候选像素在 **line 掩码**里的占比"，
   所以"路面 ∪ 线掩码"这个并集判据对 learned 候选**恒真**、写出来等于没写——
   单测在提交前当场抓住（`test_optional_surface_gate`）。有区分度、且运行期可得的判据是
   "**是否落在模型自己的路面掩码里**"。
2. **改成路面掩码后，实测把真标线一起切掉了**（同一批 25 帧、`holdout_wide2`、`armA_seed42`）：

   | 开关 | 候选 | **落漆线** | 仅路面 | 路外 | **匹配率** | 角色一致 |
   | --- | --- | --- | --- | --- | --- | --- |
   | 0（默认） | 120 | **21** | 24 | 75 | **0.217** | 1.00 |
   | 1（收紧） | 60 | **0** | 10 | 50 | **0.017** | 1.00 |

   候选砍半、但**落漆线候选从 21 变成 0**、匹配率掉 13 倍，而路外假线只从 75 降到 50；
   像素层几乎不动（precision 0.4383→0.4371、recall 0.977→0.977、IoU 0.4345→0.4308）。

**结论：缺陷是"空间不一致"，不是"缺一道门"**——在**引擎标签空间**里"铺装外"的那些候选，
在**模型空间**里并不在路面掩码之外（这些路上漆线就落在模型路面掩码更窄/缺失的位置）。
自指的候选门看不见问题所在的那个空间，所以**开关保持默认关闭并登记为被否**；
要修这条，需要**独立的铺装面来源**，或回到**线通道的数据/标签**侧。

### 结论 9：3 小时计划的停止门——"人工修订的 48 帧"全部因**没有地图身份**被拒；身份不只有"缺"，还有"错" → **支持（停止门正确触发）**

- **原假设**：`manual_gold_lines`(8)/`manual_mountain_labeled`(20)/
  `manual_review_batch_labeled`(20) 有人工修订证据，可作训练臂的漆线真值。
- **是否真正激活**：激活。`m5_seg_dataset_audit.py` 真的读入这三个目录 + 两条 dev
  路段，`--paint-source` 显式声明人工修订。
- **可复现输入**：`logs/experiments/t14_3h_20260924_1906/02_dataset_audit.json`、
  `03_needs_review.json`（48 帧逐帧 path/group/reason/needed）、
  `04_identity_provenance_check.json`、`05_legacy_identity_inventory.json`。
- **实测结果**：
  - `n_records=98, n_rejected=48`，48 条**全部**是
    `no map identity in the recording`；训练集 0 帧；dev 50 帧
    `road_valid=50/50` 但 **`paint_valid=0/50`**（引擎标注的漆线类不可用）。
  - 身份来源清点：28 个带 `map_name` 的采集目录里**只有 8 个**（`t13_*`）记录了
    `map_name_source`；**20 个目录 / 2508 帧**的值无来源；其中
    `ecrev_a_20260924`、`ecrev_b_20260924`、`gm_holdout_20260924`、
    `gm_walk_20260924`、`holdout_eastcoast_20260924` 的**目录名与值 `italy`
    直接矛盾**——旧的 `m5_collect_seg_ring.py` 把构造参数当地图名写入过。
  - 来源本身也没有身份可搬：`manual_*` 目录无 `meta.json`；
    `manual_gold_lines/meta.json` 只有 `source` 路径 + 内容哈希 + 像素统计。
- **结论**：**支持**停止门。三条硬事实：(a) 这 48 帧的身份**不可恢复**（UNKNOWN，
  不是 0，也不是"默认 italy"）；(b) 身份的"值"在拿到独立证据前**不可用于决策**；
  (c) 漆线指标在本轮数据上只能是 UNKNOWN。
- **未知与下一步**：`italy` 之外的地图身份需人工/独立证据核对；新采集必须先带身份
  （见结论 10 的改法）。

### 结论 10：`rounds` 的三处接线缺陷已修，并用计划点名的四条证明钉住 → **支持**

- **原假设**：`rounds` 已能"提议 → 真的改变训练输入 → 与**独立基线**成对比较 →
  自动判定 → 可重放"。
- **是否真正激活**：**此前没有**。三处缺陷都实测存在：
  1. 数据因子（`add_runs`/`group_weights`）只打印 `skipped_factors` 后**照训不误**，
     候选臂与基线臂输入完全相同；
  2. 第 0 轮用**本轮候选自己的 IoU** 当 champion（自我比较）；
  3. 成对比较**按位置**配对，seed 顺序/数量不一致时截断；
  另有一处：`rounds` 的判定文件叫 `round0_decision.json`，`replay` 只 glob
  `decision_*.json`，**根本重放不到**。
- **可复现输入**：`scripts/m5_seg_autoloop.py`、
  `tests/test_seg_rounds_wiring.py`（6 条）；计划点名的四条证明：
  ① 数据因子真改输入（`--plan-only` 两臂命令逐项 diff，只允许数据列表/输出路径；
  `arm_runs` 单测；`drop_runs` 与空 `add_runs` 反例）；
  ② 缺列硬门不过（缺 `candidate_identity_rate` → 判定不得为 `shadow_candidate`，
  理由含 "UNKNOWN (hard gate needs a measurement)"）；
  ③ 基线非自我比较（第 0 轮先训练基线臂并落 `champion.json{source: baseline_arm}`
  + 两臂命令落 `round{r}_commands.json`；第 1 轮起从落盘读，缺则 `no_baseline` 拒绝）；
  ④ seed 不错配（按 seed 键控配对；集合不一致 → `seed_mismatch` 拒绝）。
- **实测结果**：`pytest tests/test_seg_rounds_wiring.py` 6 passed；
  因子未生效时退出码 3 且**不产生** `round0/` 产物与判定文件；
  判定文件改名 `decision_{cand_id}-r{r}.json` 从而被 `replay` 读到，
  并带上 `pairings`/`hard_gate_violations`/`thresholds` 四项 replay 需要的字段。
- **结论**：**支持**（接线层面）。但**没有**在真实数据上跑过：数据门不通过，
  按停止门不能开训练。这条只证明"提案会真的改变输入、对照是独立的、配对不会错配"。
- **未知与下一步**：等第一份"带身份 + 可信漆线真值"的数据到位，再跑步骤 5
  的两臂各 3 seed；届时 `rounds` 的退出码 0/1/3 与 `replay` 一致性一起进报告。

### 结论 11：审计门内建进 `rounds`；`--allow-road-only` 的训练侧被证明**不成立** → **支持（含新发现的能力缺口）**

- **原假设**：`rounds` 一条命令完成"审计 → 训练 → 评估 → 判定"；
  `--allow-road-only` 能开"只做路面通道"的实验（方案 §1 的"必要时光标线通道忽略"）。
- **是否真正激活**：审计那一步此前不在 `rounds` 里；现已内建。road-only 的
  **训练**侧：**不成立**。
- **可复现输入**：真实数据两次运行
  `logs/experiments/t14_3h_realgate/`（不带开关）、`…_ro/`（带开关）的
  `rounds_dataset.json` + `events.jsonl`；
  `logs/experiments/t14_3h_20260924_1906/proposals_manual_data_factor.json`；
  `tests/test_seg_rounds_wiring.py`（9 条，含审计门 3 条）。
- **实测结果**：
  - 不带开关：train 2 组 / dev 2 组、`trainable=50 paint_ok=0 rejected=0`
    → "标线真值不可用 → needs_review"，未训练，退出码 3；4 个目录各得一条
    "identity has no provenance" 提示。
  - 带开关：审计通过、训练被 `road_only_not_implemented` 拒绝，退出码 3，
    产物只有 `events.jsonl` + `rounds_dataset.json`。
  - 代码证据：`labels.mask_line_for_loss` 只把**已标注**的 line 像素改 ignore；
    训练器是带类别权重的 CE（`ignore_index=255`），**没有类屏蔽**。置零
    `line_weight` 不是屏蔽——CE 分母仍含 line 类 = 教"未标注漆线=背景"，
    正是方案 §1 禁止的错误监督。
- **结论**：**支持**审计门；**推翻**"road-only 可训练"。这条比"没跑"更有价值：
  它挡住了"改个字符串让审计通过、然后照训"的路。
- **未知与下一步**：实现整通道忽略（类屏蔽 CE + 指标屏蔽 + 小数据验证
  "掩码在所有损失项和指标上都生效"），之后才谈路面通道臂。

### 结论 12：候选反例人工复核——**引擎 line 类在这批地图≈"中央线 + 右边缘"，左边缘漆线常无标注** → **限定结论 7**

- **原假设**（结论 7 的读法）：候选离引擎漆线 ≥2 m ⇒ 候选是假线，主因是候选错位。
- **是否真正激活**：复核激活（新工具 `--overlay-out`/`--crop-limit` 出整帧复核图 +
  未匹配候选 2× 放大；人工看了 4 帧/4 候选 + 1 处左边缘放大）。
- **可复现输入**：`logs/experiments/t14_3h_20260924_1906/11_candidate_review.md`、
  `review_overlays/review_*.png`、`crop_*.png`、`review_queue_candidates.json`
  （268 个未匹配候选，其中 **102 个所在侧无参考＝未测**）。
- **实测结果**：
  - 三条开发路的引擎线像素**左/右 = 0.021 / 0.234 / 0.193**；
    `diverse_wide` 有 **19/30 帧左侧一个引擎像素都没有**；模型对左侧引擎像素的召回
    p50 只有 **0.022**（右侧 0.903）——不是模型不看左边，是**左边没有参考**。
  - 放大图里：**沥青上连续亮白左边缘线清晰可见，却没有引擎标注**；引擎蓝只在
    中央线与右边缘。→ 这就是计划点名的"引擎漏标真实漆线"。
  - 复核的 4 个候选像素肉眼**都不在漆线上**（草地/挡墙根部/路缘结构），
    但"离引擎线远"不能作为它们为假的独立证据。
- **结论**：**限定结论 7**。正确表述是"候选与引擎参考的几何不符，原因（候选假 / 参考缺）
  未分离"；相关身份率、假线比在**参考不可用侧一律 UNKNOWN**，不得当 hard negative。
- **度量修正（工具已改，不是事后口算）**：探针新增
  `match_rate_with_reference`（分母只含"候选所在侧有 ≥50 引擎像素"的候选）与
  逐候选 `side` / `side_ref_px` / `reference_available`。三条路实测：
  旧 0.103/0.209/0.352 → **新 0.190/0.252/0.494**（合计 0.221→**0.314**），
  29.7% 的候选"该侧无参考"＝未测。既有"身份率 6–19%"的引用必须写清分母。
- **未知与下一步**：① 漆线真值必须独立于引擎 line 类且**两侧都标**；② 探针改成**按侧判定**
  （只在有参考的侧算匹配率并给分母）；③ 计划的 ≥10/≥5 抽样量本次未达标（实际 4/1，已入队列）。

### 结论 13：提议器与训练器的"能力对齐"（提议只发可执行的键）→ **支持**

- **原假设**：`propose` 的输出可以直接交给 `rounds` 跑。
- **是否真正激活**：此前不成立：`scene_mix` 族发 `group_weights`、困难采样族发
  `hard_neg_manifest`，训练器都没有实现；`rounds` 的"因子未生效即拒绝训练"会让
  循环停在原地。另修一处结构问题：`loss_weights` 族的 `continue` 会连带跳过后面的
  `epochs` 族（top 桶非 `missed_true_line` 时 epochs 永不触发）。
- **可复现输入**：`beamng_autopilot/experiments/proposer.py` 的 `APPLICABLE_KEYS`、
  `available_runs`/`blocked`；`scripts/m5_seg_autoloop.py --available-runs`；
  真实产物：`logs/experiments/t14_3h_propose_real/proposals.json`、
  `logs/experiments/t14_3h_20260924_1906/plan_arms.txt`。
- **实测结果**：给可用数据组时产出 `{'add_runs': [...]}`（可执行）；
  不给（空列表）时记 blocked 并**不退到"多训几轮"**；
  旧调用方式（None）保留回退发 `epochs` 并把"想要数据"记进 blocked。
  `rounds --plan-only` 的两臂命令只差 `--runs`/`--out`。
- **结论**：**支持**（接线）。真实两臂训练仍待可信数据。

### 结论 14：整通道屏蔽（class-masked CE）落地，并用它跑完第一场真实两臂 3 seed → **支持（机制）**

- **原假设**：缺可信漆线真值时，把 line 通道"忽略"即可（此前只有 `mask_line_for_loss`
  ＋类别权重）。
- **是否真正激活**：此前**不成立**：权重置零只取消正样本的拉力，未标注像素仍在
  softmax 分母里当负样本——引擎标注把可见漆线标成沥青，等于教"未标注的可见漆线=背景"。
  现在 `LineSegLoss(..., class_mask=)`：被屏蔽类的 logit 置 -inf，移出分母，
  该通道**梯度恒为 0**（有测试）。
- **可复现输入**：`beamng_autopilot/vision/seg_losses.py`（`masked_cross_entropy`）、
  `scripts/m5_train_seg.py --ignore-line-class`（判据来自 `audit_label`，不是命令行声明）、
  `scripts/m5_seg_eval_matrix.py` 的 `road_pixel_metrics`、
  `scripts/m5_seg_autoloop.py` 的 road-only 配方与 `road_iou` 主指标；
  真实运行 `logs/experiments/t14_3h_roads3/`（与硬门修正版 `…_roads3b/`）。
- **实测结果**（详见 `logs/experiments/t14_3h_20260924_1906/12_roads3_two_arm.md`）：
  三次运行：不等步/缩 epochs/精确等步（详见 `12_roads3_two_arm.md` §7）；
  两臂命令除 `--runs`/`--out` 外逐字相同；`train_hist.line_ignored_frames` 基线
  `[25,50,75]`、候选 `[50,100,150]`（每帧都真被屏蔽）；road IoU 基线
  `[0.424,0.424,0.423]`、候选 `[0.596,0.431,0.687]`，配对差均值 +0.148
  （sd 0.130，ci95 半宽 0.150 → inconclusive）→ 判定 **rejected**（四项标线/身份硬门
  UNKNOWN + 主指标 inconclusive）；`replay` 相同 1/不同 0。
- **两条限制**：(a) **不是等步数对照**（n_train 20→40，步数 15→30），所以
  "+0.148" 混着"训练更久"，因果结论记 needs_evidence；(b) 标线指标全 UNKNOWN。
- **等步数对照（已接线并实测，两个版本）**：`rounds --equal-steps` 先按基线实测步数
  缩候选 epochs（15 vs 20 步，残余 +33%），再升级为**精确等步数**
  （训练器 `--max-train-frames` 按 run 配额截帧：候选 40→20 训练帧，两臂 epochs 相同
  → **15 vs 15 步逐位相等**）。三次运行（同因子/同开发集/同 seed）：
  不等步 **+0.1476**（ci95 ±0.1505）→ 缩 epochs **+0.0401**（±0.0784）→
  精确等步 **+0.0389**（±0.0766），均 `rejected`。
  即 +0.145 里约 3/4 来自"训练更久"；等步后只剩 +0.039（3 个 seed 里 1 个 +0.116、
  另两个 ≈0），ci95 覆盖 0 → 不晋级。真正的缺口是 **seed 数太少**。
- **看板接线（补做）**：`--run-dir` 一次喂全（按 `Event.key` 合并 run 级与
  `candidates/*/events.jsonl`、递归发现本 run 的 `train_hist.json`、新增
  "判定与成对比较"节读 `decision_*.json`）；实测 `t14_3h_roads3d` 渲染出
  30 条曲线序列 / 8 条事件 / 终态 rejected/decided。更正：先前"24 条曲线"
  来自 T13 默认目录，不是本 run。
- **样本量估算（补做）**：`PairedResult.summary()` 新增 `seeds_needed_for_effect`
  （半宽=2·sd/√n 的口径解 n；不可分辨时 None）。本组数据（+0.039 / sd 0.066）
  需要 **约 12 个 seed** 才能判出——比"再多跑两三个"大一个量级，说明这条因子
  在当前尺度上不值得继续投 GPU——**且这个结论已被更强的归因取代**：
  真正要修的是训练长度（到平台期）与评估 checkpoint 的冻结口径，见
  `docs/T14_VARIANCE_ATTRIBUTION_20260924.md`（`rounds` 判定前会打印提示）。
- **第二个数据因子（采样权重）已可应用并实测**：训练器 `--run-weights`（超额有放回、
  每轮样本数不变 ⇒ 步数不变）+ `rounds` 的字典型因子接线。真实运行
  `t14_3h_roads3f`（同数据、只差权重、步数 30 vs 30）：配对差 **+0.0068**、sd 0.174
  → `seeds_needed_for_effect=null`（~2600 个 seed，不可分辨）→ rejected。
- **两条更重要的观察**：① ~~seed 方差主导~~ **已推翻（见 `docs/T14_VARIANCE_ATTRIBUTION_20260924.md`）**：
  36 个 checkpoint 逐个实测，波动 **96.4% 来自同一 seed 内不同 epoch**（臂间 0.2%、
  seed 间 3.4%）；根因是训练只有 15–30 步、模型在"平凡解(+0.02)/塌陷(0.0)/学到一点(+0.1)"
  之间摆动，而评估固定取最后一轮。**另：`road_iou` 的平凡基线（全预测成路面）= 0.4025**，

  不把"机器在忙"当模型缺陷。
- **顺带查出的缺陷（已修）**：第一版判定把**命令行阈值** `--hard-p95=45.0` 当测量
  送进硬门——正是 3h 计划点名的第 2 条；已改为四项硬门输入全部取自本轮实测，
  缺测即 UNKNOWN，`--help` 标明三个开关已废弃。
