## 二、本轮最重要的事：一个数字用错了 checkpoint

**城镇场景（`m5_fsd_benchmark.py` 的 town）用 `logs/m5_seg/seg_model_v13b/best.pt`。**
此前多轮离线审计用了 `Segmenter()` 的默认（`seg_model/best.pt`），同一批 217 帧结论完全相反：

| 指标 | v13b（城镇实际） | 默认 `seg_model/best.pt` |
| --- | --- | --- |
| 近场召回 左/右 | **80.2% / 80.8%** | 19.6% / 2.2% |
| 配成双侧本车道 | 14.8% | 33.6% |
| `lane_sel=sensor` | 23.5% | 45.1% |

由此**作废**两条结论："右侧边界检不出、修法在分割侧"，以及基于默认模型的那版漏斗
百分比与提取守卫实验。**跑 `scripts/m5_lane_continuity.py` 必须显式带
`--seg-model logs/m5_seg/seg_model_v13b/best.pt`。**

仍然成立（与 checkpoint 无关）：右侧检出缺口**不存在**，训练标注也**不缺右侧**
（采集 run `R:near` 195.8 px/帧 vs `L:near` 165.3 px/帧）。

## 三、本轮实现的改动：虚线边界恢复

`beamng_autopilot/vision/lanes.py`：

- `group_world_fragments`（纯逻辑，可单测）：方向一致 `|cos| ≥ 0.94`、横向共线
  `≤ 0.45 m`、纵向间隙 `≤ 8 m`、链跨度 `≤ 60 m` 的片段并成链。
- `recover_dashed_boundaries`：每条链合成**一条长边界**。
- `_mask_fragment_polylines`：把掩码连通域回投影成世界片段。
- 接线在 `Segmenter.detect_lines`，8 项单测在 `tests/test_dashed_recovery.py`。

**为什么需要它**：城镇 `line` 类不是几条连续长线——每帧 **p50 17 个连通域**、高度
中位数 **7 px**，只有 **23.8%** 能过提取器的形状门（`h≥18`、宽度、填充率）。被丢的
是**真漆画**（被丢像素 65% 落在 GT 上），但都是**亚米级碎屑**（被丢 `unknown` 标线
世界跨度 p50 0.60 m），不携带边界几何，于是本车道只剩一侧边界、永远配不成对。

**实测（3 集 654 帧，v13b）**：

| | 配成双侧本车道 | `lane_sel=sensor` |
| --- | --- | --- |
| 归并前 | 20.8% | 45.1% |
| **归并后** | **43.0%** | **55.5%** |

关键：归并出的边界**本身足够长**，是**凭自身几何合法**跨过
`LANE_PAIRED_VISION_MIN_SPAN_M = 6.0`——**跨度门槛没有被降低**。

**接线时的坑（已量）**：归并必须只吃**学习掩码**，不能吃
`white_mask = 学习 ∪ 经典CV亮线`。喂并集只有 23.9% 配对率，喂学习掩码才是 43.0%
——CV 并集里的纹理亮边不是漆画，会污染分组。经典 CV 通路保持"只保底不新增功能"。

## 四、不要重走的坑

1. **降 `LANE_PAIRED_VISION_MIN_SPAN_M`**：3.2 m 的短配对可以在"每个点都离车很近"
   的同时让中心偏离导航路线好几米（runs 42/47/52）。实测降它能把配对率"提"到 41.9%，
   但放行帧里有 18% 不在车道内——**聚合指标不能否证一条为尾部风险存在的守卫**。
   该门现已补单测（`tests/test_lane_fusion.py`）。
2. **放开标线提取守卫**：守卫是承重的（放开 `min_height` 会让"标线"从 3.0/帧涨到
   57.9/帧而配对率不动）。
3. **放开候选门控**：`*:side` 那些被丢标线的 GT 占比是 **0%**，门控正确。
4. **时序延续（last-good hold）**：掉线是**长时缺失**——16 段、185 帧、101.6 秒，
   **最长一段 35.6 秒**，1 秒以内缺口总计只有 0.3 秒。
