# 铺装路面边界横向参考（2026-09-18）

用户要求（AGENTS.md「驾驶约束」）：**在铺装路面上没有标线时以铺装路面边界
为准，禁止将车辆驾驶到土和草上**；右侧信任顺序 **标线 >> 路面边界 = 护墙
= 围栏**。本文记录实现方式、每一条门限的实测依据，以及还没解决的问题。

## 1. 现状：为什么必须补这一层

严格模式（`--strict --lane-mode sensor`）此前只有两个横向来源：

1. 配对/可信的**漆画标线**（`lane_src_sel="sensor"`）；
2. 没有就 `perception-unavailable` → 刹停。

结果：**没有标线的铺装路根本开不了**。实测（east_coast 两个行驶段，
414 帧，`scripts/m5_paved_edge_probe.py`）：

| 情形 | 帧数 | 当时结果 |
|---|---|---|
| 全部帧 | 414 | `sensor` 290 / `perception-unavailable` 124 |
| **无漆画线**的帧 | 74 | 之前只能停 |
| 当时 source != sensor 的帧 | 124 | 之前只能停 |

## 2. 实现

新增 `beamng_autopilot/lane/pavement.py`：把语义头的**铺装路面掩码**
（`strip_soil_from_road` 已在上游扣掉土色）反投影到路面平面，按纵向分带
（3 m/带，3–24 m）取：

* `right`：观测到的铺装右边沿（= 硬边界）
* `left`：观测到的铺装左边沿（= 硬边界）
* `center`：**保持右侧**目标 = `right + lane_half_m(1.75) + 0.15`，
  再夹在本带铺装范围之内（窄路自动收到中间）

信任顺序在 `lane/reference.py` 里由**位置**保证，不靠注释：
`配对标线 > 单边标线 > 铺装边界 > （仅非严格）地图先验`。
铺装边界只进严格模式；非严格模式仍是地图先验 own-lane，行为不变。

铺装边沿作为**本 tick 硬边界**发布（`boundaries=True`），因此「车体越界」
走的是与压线同一条 no-cross 判定；同时规划器的可行驶面门限
（`planning/constraints.py:_path_off_drivable`）用的是同一张掩码，
这是「不上土不上草」的第二层。

## 3. 门限的实测依据（每条都对应一次失败）

| 门限 | 值 | 依据 |
|---|---|---|
| 右边沿必须在**画面内**观测 | 6 px 边距 | 铺装跑出画面时「边沿」= 画面边框。修掉之前，18 m 宽铺装被读成 9.6 m、「边沿」在车右 3.4 m——而且相机会跟着动，目标会一直追下去 |
| 外扩钳位 | 0.45 m/带、整段 1.0 m | 掩码溢到土肩时，读数会逐带向外走（0.45 m/带 × 8 带 = 3 m） |
| 车必须在铺装上 | \|lat\| ≤ 0.25 m | 曾试过「两侧都有铺装就桥接中间空洞」，被实测否决：east_coast 帧 70/100 车**在植被里**，分类器在它两侧各给了一块「路」，与「引擎盖挡住近场」在几何上无法区分 |
| 目标内偏 | 0.15 m | 见下：掩码边沿整体偏外 |
| 边沿采样内缩 | 0.05 m | 同上 |

### 关键实测：掩码右边沿准不准（人工标注帧）

用用户手标的 35 帧（`logs/m5_seg/paved_shoulder_labeled`，土肩/砂石=背景）
在**图像空间**对比「模型右边沿 vs 人工路面右边沿」（共 6801 行）：

| 模型 | 每帧中位误差 | p90 | 溢出土肩的行 | 缺路面(内缩)的行 |
|---|---|---|---|---|
| 现网 base | **+15.0 px** | +55.6 px | **53.6%** | 14.5% |
| 微调 paved_shoulder | **0.0 px** | +24.0 px | **39.9%** | 21.6% |

（+ = 模型边沿在人工边界**外侧**，即把土肩算成了路。）

结论两条：

1. **现网 base 模型的右边沿不能单独作为横向依据**（中位偏外 15 px ≈
   0.25 m，p90 约 0.7 m，尾部可达 1.5–3 m）。0.15 m 的内偏与 0.05 m 的
   采样内缩只够吃掉误差的中位部分，**连续的整片溢出只能靠模型解决**
   （内偏加大反而会在双向路上把目标推到中线对面）。
2. **微调模型把中位误差压到 0 px**，尾部也明显变好——所以实车验证应当
   同时 A/B「铺装边界」和「微调模型」两个因子。

植被掩码（`vision/veg_mask.py`）对这批土肩无效：扣掉绿色后溢出率
53.6% → 53.4%（土肩是灰色砂石/枯草，颜色不可分，与 2026-09-16 的结论一致）。

## 5. 尚未解决的问题

1. **模型仍是第一瓶颈**：铺装右边沿的中位误差已经由微调模型解决，
   但 39.9% 的行仍是「模型说路、人工说土肩」。这一项不解决，
   「不上土」只能靠实车 A/B 兜底，不能靠常数。
2. **微调模型尚未上线**：`logs/m5_seg/seg_model_paved_shoulder/best.pt`
   在标注集与全域指标都优于 base（line IoU 0.371→0.432，mIoU 0.750→
   0.775），但上一次带它的实车 A/B 因**放置失败**而中止（当时严格模式
   还没有铺装放置路径）。现在放置路径已补齐，A/B 需要重做。
3. **宽路口/大铺装面**（跨度 > 10 m、右边沿出画面）仍然弃权 → 严格模式
   在那里依旧刹停。这是诚实行为，不是缺陷，但会让某些路口无法通过。
4. **左边界**用的是掩码原始外沿（不做内缩），因此在铺装左缘溢出的帧上，
   左侧硬边界可能偏外——对「保持右侧」无影响，但左侧越界告警会偏松。

## 6. 实车失败与回滚（2026-09-18 晚，必读）

**结论：铺装边界候选默认关闭（`--paved-lane` 才启用），在掩码边沿可信之前不得默认开。**

实况（east_coast 无标线路段，现网 base 模型，`--strict --lane-mode sensor`）：
车压着车道线走，最后顶在护栏上起不来。该次运行的日志尾部：

```
t= 33.1 v= 2.5 lane=sensor/1 dev=0.00  reason=scattered obstacle
t= 35.3 v= 2.4 lane=paved/1  dev=0.71  reason=scattered obstacle
t= 46.1 v= 0.0 lane=paved/1  level=minimal_risk reason=no drivable path
t= 54-61     lane=paved/1   reason=scattered obstacle（贴着护栏蹭）
```

两个原因，都是实现问题，不是数据问题：

1. **我用「离线可用率」当成了「正确性」**：为了让该路段可用率从 29% 涨到
   98%，我把跨度上限 10→14 m、走廊延续 2→4 m。多出来的每一帧，都是掩码
   把砂石土肩算成路面的帧——车就是用这些帧开出去的。两个门限已回到实测
   紧值，跨越上限进一步收到 **7.5 m**（该路段人工标注的铺装只有约 6 m，
   掩码读 8–11 m）。
2. **把掩码边沿当成硬边界发布**：掩码偏外 15 px（中位）时，这些「边界」
   落在土肩上——于是 no-cross 规则保护的是一条土肩线，**真正的车道线反而
   不再受保护**。这解释了「一直压线都报警不了」。所以该候选默认关闭，
   与非严格路径一样不再参与默认行为。

重新启用的前置条件（缺一不可）：

- 铺装边沿可信：微调模型（同样 35 帧人工标注下中位误差 0.0 px，base 为
  +15 px）；且微调模型自身的车道配对问题（放置后车体压线冻结）先解决；
- 边沿不得越过**已检出的右侧标线**（需要一个「标线 >> 路面边界」的结构性
  约束，而不是只看掩码）；
- 实车 A/B 各项安全计数为 0（off-pavement / 压线 / 倒车），且至少 3 个
  不同路段。

## 7. 模型部署 A/B 判决（2026-09-19，同一 iterated 配置）

| 配置 | crossC | crossR | off | rev | stall | 距离 |
|---|---|---|---|---|---|---|
| **base 双任务（现网默认）+ 全部修复** | 0 | 0 | 0 | 0 | **6** | **70.4 m** |
| 微调路面 + base 漆线（拆分） | 0 | 0 | 0 | 2 | 38 | 32.6 m |

结论：**微调模型的路面掩码在动态驾驶中劣于 base**——它把可行驶走廊收得太窄，
规划器停车翻倍并触发倒车恢复。`--line-seg-model` 拆分接口保留为工具，但
**部署决定 = 继续使用现网 base**，除非微调模型在更多路段证明走廊稳定性。

同轮修复（全部有帧证据，`--vis` 输出）：
1. 漆色还给配对（黄先验拆分 + 虚线链着色）——压线直行的机制根除；
2. 镜像中线矛盾拒收——错误侧镜像不再"居中"；
3. no-path 急刹旁路——撞树根因（刹车斜坡稀释）根除；
4. 严格模式语义头豁免预算推迟——stale sensor 停车 9→~0，stall 21→6。

剩余差距：stall=6（两段轻碰护栏后起步），对应下一杠杆 = 护栏/树簇障碍盒
在弯道里的横向余量处理。
